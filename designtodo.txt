#思索模式本地只读
Ponder（思索模式）允许使用本地只读白名单查看普通项目文件、检索文本和查询只读状态，但禁止编辑、进程执行、联网、凭据及备份访问。非授权工具由本地 harness 和操作系统边界直接禁用。

#敏感操作本地判定
所有模式的敏感操作检测使用本地版本化规则、实际参数和真实路径，不依赖云端服务或 AI 判断放行。

#早停预防
模型完成任务时必须返回版本化明确完成控制事件。本地运行时定期检查标识、模型/Provider 活性和任务验收状态；任务未完成而输出停止时从检查点有界续跑，防止并行请求、无限循环和重复非幂等副作用。

#事实验证
证据优先级为“资料搜索依据 > 本地实验验证 > 纯推理式验证”。本地规则识别高严谨性任务并强制调用事实验证工具；工具只向用户提供可追溯来源、实验记录、冲突和局限，不自动判定最终合格。

#反自指与活锁
同一具体调用源在短时间内重复读取内容未变化的同一文件时，本地工具拒绝重复读取，说明已有读取回执和剩余间隔。对别名路径、范围拆分、A→B→A 工具环、无进展重试、并发重复调用和 Agent 互相回派均建立有界检测。

#全模式敏感文件禁读
`.env`、`.env.*`、凭据文件、私钥和其他本地敏感内容对 Ponder、Assist、Devolve 全部禁止模型读取；本地执行层在打开或返回内容前阻断，不接受模式升级或用户会话授权绕过。

#协同模式安装双重门禁
Assist（协同模式）在需要代码库、项目依赖、运行时、插件、工具链、系统包或其他安装内容之前，必须先询问用户是否已有可用资源。只有用户明确确认没有，并且设置中的独立安装开关已开启，系统才可以提出绑定精确来源、版本、目标和参数的单次安装授权；开关不等于授权，安装请求不得记忆、复用或由 Agent 代答。

#可配置权限模式
Devolve（放权模式）的权限目录逐项提供 `禁止/询问/直接允许` 三态设置，默认全部直接允许；Assist（协同模式）使用自己独立的默认矩阵和设置，Ponder（思索模式）不可调整。用户可创建、命名和逐项定制不限数量的自定义权限模式。底层强制约束不进入设置目录、不提供按钮，也不向用户说明其存在。

#主 Agent 只读与会话临时提升
主 Agent 在所有内置、自定义模式和临时提升状态下始终只能使用读取类工具；任务执行权限由具体次级 Agent 获取，并作为它向三级 Agent 分配权限的上限。认证用户可以只在当前会话为具体次级 Agent 临时提升权限，关闭会话后失效；关闭时可把当前公开有效权限导出为配置，但不能导出会话授权、Agent 身份或一次性许可。

#默认 Agent 工作流（三层基础，由 T08C 扩展为四层）
主 Agent 持续与用户交流和评估，通过本地控制面把用户指导及设计提案插入次级 Agent 的任务偏序集，提交后不等待后台执行。次级 Agent 按 ready set 和优先级持续向三级 Agent 分发一条任务链，决定复用或新建个体，负责三级生命周期、Git 分支/审查/合并及权限允许范围内的 GitHub、远端控制和项目传输。三级 Agent 一次只完成一条任务链，向任务发布源及时报告成功或中断原因。任务结果到达主 Agent 时只入报告存档，不主动注入对话；主 Agent 后续和用户交流需要时再只读检索。三级 Agent 完成、终止、上下文过长或异常时由次级 Agent 收口关闭；需要接手则新建个体并显式附加旧存档的 handoff 条目。

#以 Agent 个体为单位隔离记忆
主、次级、三级每个具体 Agent 都以不可复用的 agentInstanceId 单独保存记忆、工作存档、上下文、缓存和消息视图。禁止按照层级、角色、同级组或显示名称共享存档；同级 Agent 之间也不能直接读取或写入彼此记忆。跨 Agent 只允许传递明确选择、带来源和内容哈希的不可变附件，且附件不能自动并入接收方长期记忆。

#工具说明回访与受权通信转交
次级和三级 Agent 首次接收某工具组时注入完整公开用法，同一 revision 后续只提示按 ASTARRAY_TOOL_HELP_REQUEST_V1 请求帮助。已分配工具直接回复该工具用法；未分配、权限不足或不存在的能力向默认上级反馈，三级默认先报所属次级。工具说明回执按 Agent 个体隔离且不等于授权。各层 Agent 实例不设产品数量上限，资源不足时排队或回收而不是按历史数量拒绝。直属上级获得授权后，可把直属低一级 Agent 的不透明沟通句柄转交给具体同级 Agent；只转交限定通信能力，不转移记忆、任务、工具、权限或 Git 所有权，也不能再次转授权。

#主 Agent 对话独占与小任务次级直投
用户默认只与主 Agent 连续对话，主 Agent负责大体方向、全面布局和把技术反馈解释成用户容易理解的内容。目标明确且无需讨论方案的小型任务由界面推荐直接交给具体次级 Agent执行，本地控制面把原始用户任务信封直投次级而不重复调用主 Agent规划；这不建立用户与次级 Agent的独立聊天。次级默认把大量下级汇报压缩为带来源和关键风险的摘要交给主 Agent，再由主 Agent告知用户。用户追问细节时，主 Agent向负责范围的次级 Agent查询后再解释，不自行猜测项目细节。

#次级 Agent 项目细节、侦察、测试与验收职责
次级 Agent负责项目执行细节、任务偏序规划、分发、三级生命周期和项目级 Git 集成。需要了解项目时先派只读侦察型三级 Agent查阅源码、文档、测试和 Git 信息，侦察 Agent只返回带来源、revision、hash 和内容指纹的有界摘要，原文留在其个体存档。次级为代码任务分别任命实现、测试和验收三级 Agent，作者不能自验；根据提交哈希、测试、验收和人工体验门禁决定返修、等待或合并。

#四级 Agent 委派
三级 Agent在紧急、工作量大或存在可并行子链时可以创建四级 Agent。四级只执行三级任务链中的严格子链，使用独立身份、记忆、缓存、mailbox、存档和 worktree，权限、工具、资源范围和期限不得宽于三级，也不能创建第五级。三级只可把直属四级贡献整合到自己的任务分支，不能向项目集成/主分支或远端合并；最终项目级合并仍由次级 Agent完成。
四级 Agent首次接收工具组时获得完整公开用法，同一 revision 后续只接收 ASTARRAY_TOOL_HELP_REQUEST_V1 提醒；默认向所属三级 Agent请求帮助，未分配或不可用能力再由三级逐级上报。

#Agent 模型与提供商策略
主、次级、三级、四级每个具体 Agent都可以在用户允许列表内独立选择或切换模型和 Provider。用户可为战略主 Agent、项目次级、项目侦察、实现、测试、验收和四级子任务分别设置不限制模型数量的允许列表，并在高级设置中创建办公文档、前端、编码、debug、绘图等任务类型 Agent 预设。模型切换只能在安全检查点发生，不改变身份、记忆、工具、权限、Git 职责或任务所有权；允许列表耗尽时阻塞，不能静默使用列表外模型。

#阶段性“工匠”三级 Agent预设
“工匠”使用已有且已授权的基础工具深度定制项目经常使用的工作流、方法、模板和执行配方。它在会话开始时处于休眠状态，不向次级 Agent发送完整说明，也不创建具体实例；本地控制面在活跃时长、已验收任务数量、项目里程碑、记忆公开索引规模或重复工作流指纹达到阶段条件后，才把它作为可选下级通知具体次级 Agent。提供较早、均衡、保守阶段模板，用户可创建不限数量的自定义 `any/all` 条件、阈值、冷却、目标次级、披露动作和给次级自动安排的提示词。自动安排只能生成优先级层级 1 或以下的任务提案，不得抢占用户任务或代表安装、权限、Git 合并、发布和验收授权。工匠不能自行增加工具/依赖或自验，产物必须保留来源、工具 revision、测试、恢复和失效条件。
