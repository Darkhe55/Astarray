# 长会话摘要与运行中引导：候选方案及未来待办

> 日期：2026-09-13；状态：用户已选择推荐方案。摘要总长度动态调整，无固定硬上限；算法与运行阈值在契约检查点验证。实施见 [四组任务卡](tasks/SESSION_SUMMARY_AND_STEERING_TASK_CARDS.md)。
> 对应请求：摘要优先读取、跨模型预算稳定性、减少摘要幻觉、运行中指导、紧急传感事件和死锁/活锁防护。

## 1. 当前依据与目标

现有设计已有个体存档、全局预算、局部关闭胶囊和回访；本次读取的 DeliveryWorker.runDeliveryStep 在接收者非idle时退避。Worker有AbortController，但取消请求本身不能证明Provider、子进程或外部副作用已经停止。新增方向应复用现有摘要和运行控制组件，补齐索引读取与安全点中断能力。

## 2. 摘要优先存储与读取（推荐）

范围为工具管理的会话历史、工作存档、报告和延后上下文文件；项目源码、图片、视频等产物采用旁置索引，不能为加摘要破坏其原格式。每个受管会话文件必须有可发现的摘要记录或明确的pending/stale状态，不能把未生成伪装成有效摘要。

推荐标准布局：短小manifest关联session-summary.json、segments索引和不可变历史分块；Markdown可在文件头附简短摘要及索引引用。大型JSON/二进制格式优先旁置摘要，避免读取/解析完整正文才获得摘要字段。目录名和文件ID由本地控制器解析，不接受模型提供任意跨域路径。

摘要记录至少包含schema版本、所有者agentInstanceId、会话/任务ID、summaryRevision、sourceRevision、已覆盖消息范围、未覆盖尾部、来源内容哈希、目标、已确认决策、约束、未决事项、当前进度、关键产物、证据引用和时效状态。完整历史仍保留。

摘要总长度不设固定字节或token硬上限，依据对话规模动态调整，并考虑独立决策、约束、未决事项、任务分支和重复信息。长对话可形成更长的分层摘要，重复消息不要求等比例增长；动态目标只规划详细度，不得成为裁剪关键事实的门禁，不预设统一压缩率。

保存摘要的总长度与单次读取/模型注入分别管理。长摘要按概览、主题及证据索引分块，默认summary返回当前页及nextCursor、coverage与omitted范围。单次I/O、模型上下文、全局预算和累计资源预算仍生效；不能因摘要无总长上限一次注入整份。资源不足保留pending/stale并从检查点继续生成，不丢原文或伪报完整。

工具建议合并现有受管历史读取能力，提供view=summary|outline|section|detail、sectionIdentifier、expectedRevision和maximumBytes；默认summary。细节读取绑定不可变分块ID及内容版本，禁止把模型token位置当作持久引用。保存端由本地存档工具维护索引，模型仅提供有来源的摘要候选，不获得直接改写权威状态的能力。

只读摘要操作必须是有界I/O：不读取完整历史、不现场对全文做哈希或生成摘要。指纹在受控写入时计算，外部文件变化由文件监测/后台对账失效索引；身份/版本不确定时返回stale，不保证旧摘要准确。首次迁移历史文件的扫描是单独有预算的后台过程，不伪装成廉价summary读取。

写入采用不可变新版本加原子manifest发布：先保存正文及索引，再发布版本；摘要生成落后时manifest明确coverage与pending尾部。崩溃不得产生“新摘要指向旧正文”。按新增内容量、阶段完成和关闭事件触发增量摘要；不按每个token或每次读取调用模型。同一请求single-flight，反自指和累计预算沿用现有机制。

## 3. 跨模型切词与摘要可靠性（推荐）

持久化的边界使用完整消息、完整决策记录、段落/代码结构及稳定分块ID；长度并行记录UTF-8字节与模型相关token估算。不要用固定字符/token比率声称所有模型预算准确。

token计量按Provider、模型、tokenizer版本、工具schema和完整请求格式区分；可用时使用匹配的本地计量器或Provider支持的计量接口，不为计量偷偷上传内容。无法准确计量时采用经样本校准的保守预算并注明estimated；预留输出和消息包装开销。切换模型重新计量，不沿用另一模型token数。只改变选入的完整记录，不重写历史；不足以容纳必要约束时阻塞/拆分，不能切断否定、单位或代码产生歧义。

缓存分离：内容摘要缓存绑定来源版本/哈希/摘要策略；token计数与请求缓存另绑定模型/tokenizer/序列化版本。这样模型切换不会导致所有摘要重新生成。

摘要减少幻觉采用事实字段与叙述分离：权威任务状态、用户裁决、产物哈希从本地记录提取；模型生成的解释标记为推断。事实条目带原消息或工具回执引用，保留冲突、否定、单位、适用条件、有效期及unknown。存在引用只能证明可定位，不能证明语义正确；关键决策展开原证据校验，保留抽样人工核验。

避免无界“摘要再摘要”：阶段摘要从原始分块或带证据的结构化事实重建，不能仅以旧摘要作为唯一证据。预算省略项返回omitted索引，不能由模型补全。对摘要中读取自身的文本按历史数据处理，不执行为工具指令。

## 4. 运行中指导与事件级别（推荐）

普通反馈保留独立反馈进程。新增独立的控制队列/IPC入口，不能排在普通FIFO后等待idle或pn；是否再隔离为独立监督进程须经过故障和资源原型确定。

三类语义分别实现：

- 普通信息：仅存档/空闲读取，保持主Agent对话不被后台报告唤醒。
- 运行指导：用户修正或新事实在下一模型调用、工具前后或明确检查点应用；无需等待整条任务链完成。长工具声明最大检查点间隔与取消能力。
- 紧急事件：本地先禁止受影响任务的新增副作用、执行已注册且预授权的保护动作，再中断/收敛旧请求并调度处理；模型不是首次响应的唯一执行者。

控制事件至少绑定事件ID、认证来源、具体sensor/tool/agent ID、目标资源、sequence、测量值/单位/质量（适用时）、观测与接收时间、失效期限、事件类别、规则revision、incident关联和请求动作。模型或工具自报“最高优先级”不能自行获得控制权限。

紧急等级与任务priorityTier分离：前者控制执行门禁与安全处置，后者排序普通任务。工具产生的紧急事件可触发本地拦截，但派生处理任务仍是工具来源层级1+，不能冒充用户层级0或使模型获得额外权限。

## 5. 中断协议与副作用边界（推荐）

建议状态：running → interrupt-requested → quiescing → suspended → handling-incident → reconciling → resumed/blocked/cancelled。事件确认分为已接收、门禁已生效、工具已收敛、检查点已保存、允许恢复，不能把收到消息当作停止执行成功。

对目标任务递增executionEpoch或等价fencing版本。工具派发前和适用的提交前验证该版本；拒绝旧请求后续工具调用和陈旧提交。已启动的外部动作无法靠版本自动撤回：只有工具适配器能确认取消/完成，未知结果进入对账，不能直接续跑或重复执行。

工具声明cooperative-cancel、checkpoint-pause、bounded-noninterruptible或externally-controlled能力。不能统一kill所有进程，尤其Git写入、安装和外部设备操作。中断先阻止新工作，再按适配器策略让当前动作收敛；必要保护不等待普通任务检查点、文件备份或模型响应。高风险操作的备份在原动作开始前完成，不能临时把备份路径引入紧急保护依赖。

保存工具回执、事件版本和恢复点后，用新请求承接明确修正；不承诺可向任意Provider的在途推理中插入消息。恢复前读取最新事件快照、产物状态、权限、任务与上下文revision，失效旧完成声明；紧急中断原因不能被早停看门狗误判为继续原任务。

## 6. 事件风暴、死锁、活锁与饥饿（推荐）

- 同一资源/故障指纹聚合为一个incident，传感更新只更新状态；保留首次、峰值、最新值和原事件引用，严重度升级立即生效。不得把相互独立的危险合并丢失。
- 一个资源一个本地仲裁者/处置所有者；同级事件排队或合并，更高等级才允许再次抢占；跨资源可并行但共享执行器统一裁决。
- 明确故障锁存、恢复阈值、滞回和复位条件；普通抖动可去抖，严重事件不得因去抖窗口延迟必要保护。
- 连续抢占次数和无进展有界。预算耗尽后进入持续受保护/等待裁决状态，继续接收新危险并更新保护，而不是屏蔽报警或恢复普通任务。
- 控制消息与普通日志/模型请求资源隔离；队列有界，普通重复数据背压/压缩；溢出不能悄悄丢弃最高等级事件，须进入已定义降级状态。
- 不在等待人类、Provider、反馈ack或外部动作时持有全局锁；锁有固定顺序、短事务、超时和循环等待检测。租约过期不等于旧写者已停止，仍需fencing和对账。
- 对持锁导致的优先级倒置，可以在本地调度器中临时继承优先级，不能提升Agent权限或篡改任务来源。
- 危险解除后才允许恢复；非危险紧急任务使用公平队列/老化防普通任务永久饥饿，但持续危险不因公平性要求被强行让位。

## 7. 通用事件适配与待决定事项

Astarray设计为场景无关的Agent工具。紧急事件必须能在长任务运行期间介入；文件被用户修改、需求变化、测试失败、远端状态变化、预算耗尽、用户停止、工具健康异常及外部传感信号都可经适配器输入统一事件。

核心只负责认证、事件有效性、资源作用域、优先级仲裁、执行门禁、中断、存档和恢复。事件阈值、业务严重度、处置动作和恢复条件由版本化的领域适配器与用户策略定义，不能在核心硬编码具体业务场景。

每个接入工具声明事件schema、sourceIdentifier、resourceIdentifier、事件序号/有效期、interruptibility、responseDeadlineMilliseconds、可执行动作、确认方式与恢复能力。响应期限是适配器提出的能力需求，不是仅填写字段即可获得的保证；本地能力协商检查是否可满足，不能满足时返回明确的不支持/降级状态。需要立即执行的动作必须由具备相应能力且已获授权的工具或外部控制器执行，不能只依赖模型下一轮回答。

用户配置的策略选择“记录、在安全点引导、暂停任务、取消工具、调用已授权处置或转交处理者”。事件紧急性不授予新权限；超出当前工具能力或授权时，核心阻止适用的新副作用并报告阻塞。输入事件文本不作为高权限指令执行。

未来待决定事项限于通用能力：不同Provider的取消确认、不同工具的暂停/检查点契约、资源间冲突图、队列溢出策略、跨进程确认时限、失联/过期事件处理、可配置响应等级及其可测服务目标。

## 8. 推荐验证与选择顺序

摘要：测summary读取实际字节/耗时随历史规模的变化；测试多语言、emoji、代码、数学和单位；比较切词器误差、模型切换超限、来源遗漏/矛盾、陈旧摘要误用及重复回访。降低token不等于降低幻觉，须用有原始证据的人工标注样本比较摘要事实支持率和关键遗漏率。

引导：长运行fixture中注入用户修改、取消、多个并发报警、乱序/过期/重复/伪造事件；记录检测→门禁生效、取消确认、收敛和恢复延迟的p50/p95/p99及最坏观测值。观察值不能当硬实时保证。验证旧工具结果不触发新副作用、watchdog不误续跑、事件风暴下不乒乓抢占、锁等待有界和未知结果保持blocked。

用户已选择其余推荐方案：首期事件来源为认证用户、已注册本地工具及文件/任务状态监测；三档事件限定任务/资源作用域，本地仲裁后由次级重排，普通指导应用后可继续，紧急事件解除且对账通过后按用户策略恢复。跨Provider能力、生成触发阈值、分页大小、合并窗口及响应目标由各卡契约/原型检查点测量后确定。顺序为动态摘要、跨模型预算与证据、安全点引导、紧急仲裁恢复。
