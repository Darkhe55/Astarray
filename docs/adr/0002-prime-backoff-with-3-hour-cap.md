# ADR-0002：质数退避与 3 小时单次封顶

- 状态：已接受（冻结）
- 日期：2026-08-12

## 背景

反馈进程向忙碌的接收者投递消息时需要退避，同时新消息必须尽快送达。

## 决策

每次检测到接收者忙碌后，等待第 n 个质数秒（n = 连续忙碌轮次，p₁=2, p₂=3, p₃=5, p₄=7, p₅=11, …），单次等待上限 **10,800 秒（3 小时）**；达到上限后保持 10,800 秒。新消息入池、接收者变为空闲、反馈进程重连成功时重置到 2 秒。

## 后果

- 新消息优先：池更新即回到 2 秒快节奏尝试投递。
- 繁忙退避防止轮询风暴；上限避免长时间忙等待空转。
- 3 小时是单次休眠上限，不是消息 TTL；消息不得因等待过久而丢弃。
- 测试必须使用虚拟时钟，禁止真实 sleep 数小时。
- 质数生成使用有界、可测试的策略，达到上限后直接保持上限，不无限保留数组。
