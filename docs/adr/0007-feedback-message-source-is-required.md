# ADR-0007：反馈消息必须携带不可变的原始来源

## 状态

Accepted — 2026-08-12

## 背景

反馈系统会传递用户裁决、主 Agent 指令、次级 Agent 调整、三级 Agent 汇报和系统恢复事件。如果消息只有内容与接收者，接收方、TUI 和审计系统无法判断信息究竟来自用户、哪个 Agent 或哪个系统组件；经过多层转发后还可能错误归因。

## 决策

每条进入独立反馈进程的消息必须携带结构化 `source`：

- `user`：包含会话内稳定且不敏感的来源标识。
- `agent`：包含该 Agent 生命周期内全局唯一、不可复用的 `agentInstanceId`，以及 `main / secondary / tertiary` 层级。只写角色或 Agent 类型不构成有效来源。
- `system`：包含系统来源标识和组件名称。

来源在消息首次进入反馈系统时确定，并在入池、持久化、投递、重放和转发全过程保持不变。转发 Agent 不能把原始来源改写为自己。反馈进程必须在入池前校验来源结构，并结合已注册的 IPC 客户端身份检查具体 `agentInstanceId` 的来源声明；不合法或疑似伪造的消息被拒绝并写入审计记录。

TUI、headless JSON、日志和审计事件必须保留来源，但不得用来源字段存储邮箱、API key 等不必要的敏感信息。

## 结果

- 用户可以区分用户裁决、特定 Agent 汇报和系统事件。
- 崩溃重放与跨 Agent 转发不会丢失原始归因。
- IPC 注册和身份校验实现更复杂，但能避免 Agent 冒充用户或其他 Agent。
- 任何缺少来源的旧消息都不再符合协议，必须在迁移或恢复时进入明确的兼容处理流程，不能猜测来源。
