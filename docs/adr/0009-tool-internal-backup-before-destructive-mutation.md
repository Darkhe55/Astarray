# ADR-0009：破坏性变更必须由工具内部先自动备份

## 状态

Accepted — 2026-08-12

## 背景

删除文件、删减文字、替换和覆盖会使既有内容消失。要求 Agent 先调用备份工具既不可靠，也会增加模型调用、把恢复材料暴露给模型，并允许模型遗漏或绕过备份步骤。滚动 `.bak` 文件还会因覆盖旧备份再次触发备份要求，形成递归问题。

## 决策

所有删除资源、删除部分内容、替换、截断和覆盖操作必须由执行工具内部完成 pre-image 备份。工具必须先把目标完整快照和必要元数据写入内容寻址、追加写的受保护备份库并持久化 manifest，随后重新校验目标指纹未变化，最后才能执行变更。

备份失败、目标发生并发变化、备份库不可用或无法产生一致快照时，原操作 fail closed，目标保持不变。纯新建操作只有在原子确认目标不存在时免备份；目标存在时必须拒绝或使用受保护的覆盖工具。

自动创建备份时，备份内容、物理路径、对象哈希、恢复凭据和被删除原文不进入模型输入、工具 `outputText`、反馈消息或 TUI 对话。后续可通过受控工具显式列出、读取或恢复；读取只返回被请求的业务内容，底层路径、对象哈希和恢复密钥仍不暴露。

备份库不向普通文件工具提供删除或覆盖入口。删除备份只能通过独立特权入口，并作为 pre-image 规则的唯一递归例外；其不可删除审计账本提供追踪。恢复本身属于覆盖操作，恢复前也先备份当前版本。

所有工具注册时声明 mutation kind 和是否提供工具内备份；注册表与运行时 guard 双重校验。无法证明受保护的通用 shell、脚本、插件或 MCP 写工具不得注册。

## 结果

- 破坏性变更不依赖模型遵守备份流程。
- 备份失败不会导致未受保护的数据丢失。
- 模型不能访问或泄漏备份材料与恢复能力。
- 需要额外实现内容寻址存储、manifest、指纹校验、恢复控制面、配额和跨平台故障测试。
