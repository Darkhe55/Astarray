# ADR-0012：次级 Agent 负责 Git 分流、审查与合并

## 状态

Accepted — 2026-08-13

## 背景

多个三级 Agent 并行修改同一仓库时，如果每个 Agent 都能自行创建分支、合并、变基或清理工作树，容易出现修改相互覆盖、提交来源不清、未经审查的结果进入目标分支，以及冲突处理中静默丢失内容。主 Agent 还需要持续响应用户，不适合承担逐提交的集成工作。

## 决策

涉及 Git 写入的多 Agent 任务由一个具体且不可复用的次级 Agent 个体担任 Git 集成者：

1. 次级 Agent 固定任务基线提交，创建 mission 集成分支。
2. 次级 Agent 为每个三级 Agent 创建绑定 mission、任务、Agent 身份和允许路径的隔离分支及 worktree。
3. 三级 Agent 只能在自己的 worktree 修改并提交；不得自行 merge、rebase、push、force-update、删除分支或清理 worktree。
4. 三级 Agent 通过独立反馈进程上报提交 ID、差异摘要和测试证据，来源必须是其具体 `agentInstanceId`。
5. 次级 Agent 验证身份/分支绑定、祖先关系、任务范围、文件边界、敏感信息、命名规范、自动备份合规和测试结果。审查通过后，才将提交以保留来源的方式合入集成分支。
6. 审查失败或出现冲突时，次级 Agent 不得静默选择一侧内容；应向原三级 Agent 下发修正，或创建独立冲突修复任务后再次审查。
7. 全部 worker 结果集成后，次级 Agent 运行目标测试和完整质量门禁，生成合并报告，并在当前模式和用户授权允许时执行到目标分支的技术合并。

Devolve 可以让主 Agent 自由决定任务调度，但不能省略多写入 Worker 场景下的次级 Git 集成者。Ponder 不执行 Git 写操作。

## 权限与恢复

- 分支创建和新增提交不等于获得远端权限。`git push`、PR、发布、强制推送和受保护分支修改继续要求用户明确授权。
- Git 历史不是破坏性变更自动备份的替代品。
- checkout 覆盖、reset、clean、rebase、引用强制移动、分支/worktree 删除等操作必须由 Git 工具在执行前自动创建受保护恢复引用、未提交内容 pre-image 和审计记录；备份过程不经过模型。
- 次级 Agent 不得使用模型可控的“跳过审查”“跳过备份”或“强制合并”参数。

## 可追溯记录

任务链和次级 Agent 工作存档至少记录：

- mission、任务、次级与三级 `agentInstanceId`。
- 目标分支、集成分支、worker 分支、`baseCommit` 和 `headCommit`。
- 允许修改路径、实际修改路径和越界检查结果。
- 审查决定、拒绝原因、测试命令/退出码、合并提交和遗留风险。

## 结果

- 三级 Agent 可以并行编码，但不能绕过集中审查。
- 次级 Agent 成为单一 Git 集成责任人，主 Agent 保持用户沟通和最终裁决职责。
- 每项合并可追溯到具体三级 Agent、提交、审查证据和次级集成 Agent。
- 需要实现分支/worktree 身份绑定、受控 Git 工具、结构化审查报告和破坏性 Git 操作恢复点。
