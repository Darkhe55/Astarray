# ADR-0013：Agent 待办任务采用带优先级的偏序集

## 状态

Accepted — 2026-08-13

## 背景

项目 DAG 适合描述项目节点、依赖和产出，但不能完整表达某个 Agent 在多个项目或临时指令之间的个人待办顺序。把 Agent 待办事项继续写入项目任务文档，会把调度记忆、项目交付和产出追踪耦合在一起，也无法让不同任务发布者精确指定新任务插入位置。

## 决策

每个承担调度职责的 Agent 在自己的记忆存档域维护独立、版本化的待办任务偏序集：

```text
.astarray/agent-memory/<agentInstanceId>/task-sequences/<taskSequenceId>.json
```

序列所有者是具体不可复用的 `agentInstanceId`，不是 Agent 角色或同级调度组。两个次级 Agent 即使服务同一项目，也必须拥有不同序列目录；互相只能通过认证插入请求或只读状态授权协作，不能直接读写对方序列文件。

任务序列以 DAG 表示有限偏序。发布者添加任务时可以指定直接前驱和直接后继；执行层添加相应边并拒绝环、未知锚点和越权改写。没有指定位置的新任务保持与现有节点不可比，而不是自动追加到队尾。

任务节点只保存调度信息、来源、优先级、状态、阻塞原因和可选外部引用。项目任务文档、项目状态、产出内容和产物追踪继续由项目自己的存储负责。

## 优先级规则

- `priorityTier` 从 0 开始，数值越小越优先。
- 用户任务默认是层级 0；用户可以主动选择更低层级。
- Agent 或工具发布的任务只能使用层级 1 或以下，执行层拒绝其进入层级 0。
- 次级 Agent 分割用户任务时保留层级 0 的用户根任务；派生子任务仍为层级 1 或以下，并作为根任务的必要前驱。必要前驱可以因用户根任务而先行，但不会继承或伪造用户来源。
- 调度只比较当前可执行节点：先满足偏序前驱，再按优先级层级选择；同层使用发布者顺序提示与创建序号稳定排序。
- 新用户任务不打断已经开始的原子调用，但会优先占用后续执行槽。
- 高优先任务若被低层必要前驱阻塞，允许先完成该前驱并记录原因；除此之外，存在可执行层级 0 节点时不得新派发低层任务。

## 任务包

次级 Agent 可以把偏序集中的一条真实有序链打包给一个具体三级 Agent。任务包是派发单位，不抹平包内节点：

- 节点必须形成链、工具和任务范围兼容，默认同一优先级层级。
- 任务包绑定具体三级 `agentInstanceId` 和创建时的序列 revision。
- 三级 Agent 按链依次完成，逐节点报告状态；失败或阻塞节点的后继不得执行。
- 包外新用户任务不会强行打断当前原子节点；是否在节点边界暂停任务包由次级 Agent 调度器按优先级重新裁决。

## 查询能力

提供控制面只读 `taskSequenceStatus` 工具，使任务发布者可随时查看序列、任务、可执行集合、顺序解释和任务包状态。调用者身份由 harness 注入和校验，不允许模型通过填写发布者 ID 获得他人视图。用户可在任意模式从 TUI/CLI 使用；Ponder 模型仅可在 ADR-0014 的本地只读白名单和可见范围内调用该查询，不能管理或改写任务序列。

用户可查看自己发布任务及其派生链；Agent 可查看自己发布或获授权观察的任务；工具发布者通过内部能力接口查询。返回一致 revision 的调度快照，不包含项目产出内容，也不改变 Agent 的 busy 状态或序列顺序。

## 持久化与安全

- 任务序列使用 schema 版本、单调 revision、原子提交和损坏恢复。
- 发布、插入、状态迁移、打包和取消均记录认证来源。
- 删除、覆盖、重新排序和压缩历史属于破坏性变更，底层存储工具必须在修改前自动备份；备份过程不经过模型。
- 已完成节点可从活动视图隐藏，但历史和来源保留到记忆保留策略明确清理。

## 结果

- Agent 可以跨项目维护独立待办，不污染项目任务文档和产出追踪。
- 用户任务默认获得最高调度层级，自动生成任务不能冒充用户任务提权。
- 任务发布者能指定插入位置并随时获得可解释的状态视图。
- 次级 Agent 可把完整依赖链作为任务包派给三级 Agent，同时保持逐节点可追溯性。
