# ADR-0014：思索模式采用本地只读工具边界

## 状态

Accepted — 2026-08-13

## 背景

思索模式需要读取项目现状才能进行可靠分析，但不能因为模型认为某次调用“只是查看”就获得写入或敏感能力。工具名称、模型描述和云端安全分类都不能替代实际执行边界。

## 决策

Ponder（思索模式）允许一组显式注册的本地只读能力：

- 读取工作区内允许的项目文件和元数据；
- 列出允许目录；
- 在允许文件中检索文本；
- 查询只读任务状态；
- 通过专用适配器读取 Git `status`、`diff`、`log` 等不改变仓库的视图。

Ponder 不获得通用 shell、任意进程、通用网络、外部连接器、包安装、文件创建/编辑、Git 写入、凭据读取、`backupVault` 或 `deleteBackup`。ADR-0016 的事实验证可以提供专用只读资料搜索代理，但不能转换为任意网络访问。普通文件只读工具不能直接访问受保护的 Astarray 状态、ADR-0018 的敏感内容、备份物理存储、密钥文件或策略明确排除的敏感路径；`taskSequenceStatus` 只能返回经认证与字段裁剪的状态投影，不能暴露底层状态文件。

## 本地强制执行

`LocalToolPolicyEngine` 在工具暴露和实际执行两个时点校验：

1. 工具注册时声明稳定工具 ID、`operationEffect`、资源范围和本地适配器；Ponder 只收到只读白名单的 schema。
2. 调用时根据当前模式、认证主体、实际参数、规范化真实路径、符号链接和文件打开方式重新判定。
3. 只读文件适配器由本地进程使用只读句柄；Git 查询使用固定子命令和参数语法，不允许拼接 shell。
4. 操作系统沙箱移除工作区写权限、进程执行和网络能力，作为策略包装层之外的第二边界。
5. 工具未知、声明不完整、路径不可解析、可能写入、同时读写或副作用无法证明时一律 fail-closed。

`LocalSensitiveOperationClassifier` 在 Ponder、Assist、Devolve 三种模式的策略判断之前，统一使用版本化静态元数据和确定性参数规则识别文件变更、Git 变更、进程执行、网络、外部发布、凭据/备份访问和系统级操作。规则在本地加载并执行；Ponder 据此硬拒绝非只读调用，Assist 据此决定 ask/deny，Devolve 据此执行不可绕过的系统边界与审计。Provider 的分类、模型自述或 AI 风险评分只能作为非授权性诊断信息，不能允许、降级或绕过一次调用。

Ponder 的读取不会创建或修改项目、任务、记忆、缓存或遥测文件。安全组件可产生不持久化且不包含文件内容的本地拒绝事件，但模型不能利用该事件获得额外能力。

## 必测行为

- 允许工作区内普通文件读取、目录列出、文本检索、任务状态查询和固定 Git 只读查询。
- 拒绝写入标志、创建、删除、替换、截断、重命名、Git 写命令、shell、网络、安装和外部发布。
- 拒绝路径穿越、绝对路径逃逸、符号链接/联接点逃逸、TOCTOU 替换、备份库和凭据路径。
- 工具别名、大小写变化、包装命令、伪造 `readonly` 字段和未知工具均不能绕过。
- 降级到 Ponder 后，后续调用立即按新策略复检；已授权的 Assist 调用不得沿用。
- 断网和无 Provider 安全服务时，本地结果与联网时一致。

## 结果

思索模式可以基于真实项目内容分析，同时编辑能力和敏感能力在模型之外被确定性禁用。该模式是“本地只读”，不是“模型自律的只读”。
