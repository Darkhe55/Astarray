# ADR-0022：默认 Agent 控制流与三级 Agent 生命周期

- 状态：Accepted（设计冻结，尚待 T08A 实现与动态验收）
- 日期：2026-08-13

## 背景

主 Agent 必须持续与用户交流，不能因为后台任务、完成汇报或长消息历史进入执行循环。次级 Agent 已拥有任务偏序集和 Git 集成职责，但尚未统一规定如何持续分发任务、何时复用或新建三级 Agent、如何关闭后台 Agent，以及上下文过长时怎样保存并移交工作记忆。

## 决策

### 主 Agent：交流、评估与任务插入提案

主 Agent 只负责与用户交流、评估需求、形成设计方案和新指导。它输出版本化 `TaskInsertionProposal`，包含目标次级 Agent、目标任务序列、插入前驱/后继、任务摘要、约束和验收条件。认证本地 `ConversationTaskInsertionController` 验证用户来源、序列 revision 和插入位置后，代表控制面提交偏序集变更；该控制器不是主 Agent 可调用的写工具。

来源与优先级保持不变：用户原始任务或指导仍为 `priorityTier: 0`；主 Agent 自行推导的设计、拆解或补充节点是 Agent 来源，只能进入 `priorityTier >= 1`。主 Agent 不得通过转述把 Agent 生成内容伪装成用户来源。

主 Agent 提交提案后立即继续用户对话，不等待次级 Agent 接收、分解、三级执行、Git 集成或远端传输。

### 汇报只入档，不抢占主 Agent 对话

次级 Agent 每完成、终止或阻塞一个任务包，都通过独立反馈进程发送带具体 `agentInstanceId` 的结构化汇报。`MainAgentReportArchiveIngestor` 在本地验证、确认并写入主 Agent 的报告索引；汇报到达不会自动恢复主 Agent 模型、插入当前模型上下文或打断用户输入。

主 Agent 只在后续用户对话轮次根据问题、任务引用和 token 预算，通过只读 `MainAgentReportReader` 选择相关摘要或报告读取。需要用户操作的事件可由 TUI/CLI 控制面显示状态徽标或专用授权界面，但同样不能把完整汇报主动注入主 Agent 当前轮次。报告索引与原始次级/三级工作存档分离，保留来源、revision、任务引用和内容哈希。

### 次级 Agent：持续调度和完整项目集成

次级 Agent 独占自己的任务偏序集调度循环。每次任务状态、反馈、权限、资源或 Git 基线变化后，重新计算 ready set，并按前驱、优先级和稳定同级顺序持续形成任务链包并向三级 Agent 分发，直到没有可执行节点、需要用户裁决、达到并发上限、被暂停或会话关闭。

次级 Agent 负责：

- 判断每条任务链应复用现有三级 Agent 还是创建新个体；
- 创建和回收三级 Agent，选择性附加工作存档；
- Git 分支/worktree 分流、贡献审查、测试、冲突修复和受控合并；
- 在有效权限允许时执行 Git 远端、GitHub 类项目控制、PR、CI、发布和产物传输适配器；
- 在每个任务包终态后向主 Agent 报告结果，而不等待主 Agent读取。

“完整项目控制”表示职责归属次级 Agent，不构成权限放行。远端写入、发布、传输和破坏性 Git 操作仍在实际执行前按次级 Agent 的当前有效权限、本地策略、自动备份和用户裁决重新检查。

### 三级 Agent：一次激活只执行一条任务链

三级 Agent 的一次激活绑定一个不可变 `taskBundleId` 和一条真实有序任务链。它只按链完成分配工作，逐节点保存检查点，并及时向任务发布源（通常为所属次级 Agent）汇报成功、失败、阻塞、中断原因、提交和测试证据。它不得领取链外任务、修改偏序集、调度其他 Agent、操作集成/目标分支或执行远端项目控制。

任务链达到终态后，三级 Agent 进入 `idle-awaiting-lifecycle-decision`，不能自行领取新任务。次级 Agent 决定复用、暂停、关闭或创建替代个体。

### 复用、新建、关闭与记忆接手

`TertiaryAgentAssignmentPlanner` 只能在以下条件全部满足时复用已有三级 Agent：该个体仍存活且空闲；同一所属次级 Agent；任务/mission、worktree、权限与工具范围兼容；没有未确认副作用或未处理控制消息；上下文和消息预算未超阈值；历史内容不会与新任务冲突。否则创建具有新 `agentInstanceId` 的三级 Agent。

次级 Agent 可在任务成功、确认无法继续、明确终止、消息/上下文列表达到本地阈值、权限撤销、健康检查失败或会话收敛时调用受控生命周期工具关闭三级 Agent。关闭流程为：停止新派发、收敛或标记未确认调用、持久化检查点与 handoff、确认反馈入档、撤销权限租约、注销 mailbox 身份、处理 Git 分支/worktree，再终止后台运行。不得仅以杀进程代替状态收口。

需要后续接手时，次级 Agent 可以创建新的三级 Agent，并向本地跨 Agent 附件控制器请求从旧个体工作存档中显式选择 `handoff`、未完成节点、关键决策和产物引用形成不可变附件；次级 Agent 模型不能直接读取旧个体记忆文件。必要时可先创建一个只负责“记忆整理/交接包生成”任务链的新三级 Agent；它仍只处理这一条任务链，不能自动继承旧身份、权限、消息历史或完整上下文。旧 `agentInstanceId` 永不复用。

## 后果

- 主 Agent 不因后台汇报或项目执行失去用户响应能力。
- 次级 Agent 成为持续调度、三级生命周期和本地/远端项目集成的唯一责任层。
- 三级 Agent 行为保持单链、可界定和可回收；上下文过长时通过结构化 handoff 换新个体，而不是无限追加消息。
- 报告、工作存档、Agent 待办偏序集和项目任务链仍是不同事实域，通过不可变引用关联。

## 验收重点

- 后台汇报到达时主 Agent 模型不被唤醒，用户输入仍能立即处理；后续对话可按需只读加载相关报告。
- 用户来源任务与主 Agent 派生任务的优先级不可混淆；插入保持偏序集无环并使用 expected revision。
- 次级 Agent 在 ready set 变化后持续派发，稳定遵守优先级、并发限制和必要前驱。
- 复用/新建决定可解释且确定；三级 Agent 一次激活不能越出任务链。
- 关闭、上下文轮换、交接和重启恢复不丢失终态汇报，不复用身份，不重复未确认副作用。
- GitHub/远端控制只由次级 Agent 发起，并在工具执行前重新鉴权；三级 Agent 无相关工具。
