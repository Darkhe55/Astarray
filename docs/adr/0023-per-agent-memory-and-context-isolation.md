# ADR-0023：每个 Agent 的记忆与上下文严格隔离

- 状态：Accepted（设计冻结，尚待 T08A 实现与动态验收）
- 日期：2026-08-13

## 背景

独立工作存档若只限制写入，而仍允许上级直接读取下级文件、后台汇报自动进入主 Agent 上下文或替代 Agent 挂载旧记忆，就仍会发生上下文污染、错误归因、历史指令复活和权限信息扩散。每个 Agent 必须拥有真正独立的记忆域，而不只是不同文件名。

## 决策

### 独立记忆域

主、次级、三级每个具体 Agent 都绑定唯一且不可复用的 `agentInstanceId`，存档以个体为最小且唯一的所有权单位，不以 `main/secondary/tertiary` 角色、同级组、任务类型或逻辑名称作为共享所有者。每个个体拥有独立的：

- 模型会话上下文和上下文预算；
- `memory-archive.json`；
- mission 内 `work-archive.json`；
- 读取回执、循环预算、缓存命名空间和未决消息视图；
- 对调度 Agent 而言，自己的任务偏序集。

Agent 运行单元只能挂载自己的记忆域。任何 Agent 都不能直接读取、搜索、写入、合并或删除另一个 Agent 的记忆文件；角色层级不是绕过依据。

规范路径必须包含经过无碰撞编码的完整 `agentInstanceId`，文件内 owner 字段、目录身份、运行时身份和写入 capability 四者一致。禁止角色级共享文件、同级汇总存档、可复用计数器 ID、截断 ID 路径或“所有次级 Agent 共用”的缓存/收件箱。即使两个同级 Agent 处理相同任务、使用相同模型或拥有相同显示名称，也必须使用互不重叠的记忆目录和命名空间。

### 跨 Agent 信息传递

跨 Agent 只能使用两种带来源的通道：结构化反馈消息（包括 ADR-0024 受权通信 grant 建立的限定路由），或由本地 `CrossAgentContextAttachmentController` 生成的不可变上下文附件。通信 grant 不提供记忆访问。附件控制器执行身份校验、可见性检查、明确条目选择、revision 固定、脱敏、内容哈希、token 预算和来源封装。

附件进入接收 Agent 的 `externalHistoricalContext` 分区，优先级低于系统约束、权限、当前用户任务和当前发布指令。附件只在当前任务激活中有效，不自动并入接收 Agent 的长期记忆。接收 Agent 若需保留结论，只能在自己的存档中写入带原始来源和附件哈希的观察记录；不得去除来源后冒充自身记忆。

### 报告与交接

次级 Agent 发给主 Agent 的终态报告先进入独立报告索引。报告到达不唤醒主 Agent、不改变主 Agent 当前上下文，也不自动写入主 Agent 记忆。后续用户交流需要时，主 Agent通过只读报告读取器选择相关项作为当前轮次外部资料。

三级 Agent 被关闭后，新建接手 Agent 使用新的身份和空白个人记忆。旧个体的 `handoff`、未完成节点、决策和产物引用只能经附件控制器选择性传递；不得挂载旧目录、复制完整消息列表、复用缓存命名空间或继承权限租约。

### 共享事实域不是共享记忆

项目任务链、Agent 待办偏序集、Git 提交、审查报告和产物存储各自拥有明确所有者和事实域。Agent 可以在权限允许时读取其不可变引用或公共状态视图，但这些内容不会自动成为任何 Agent 的个人记忆，也不能触发跨 Agent 上下文合并。

## 验收重点

- 两个 Agent 使用相同任务文本时，存档、缓存、读取回执、消息和上下文仍完全隔离。
- 两个同级 Agent 使用相同显示名、任务 ID 或模型时仍生成不同且无碰撞的个体存档；任何角色级共享路径都由契约测试拒绝。
- 任意 Agent 直接访问其他 `agentInstanceId` 记忆路径都在本地执行前被拒绝。
- 未选择的存档条目永不出现在接收方 prompt、日志、缓存键或后续记忆中。
- 附件无法覆盖当前任务或权限；接收方持久化引用时保留原始来源和内容哈希。
- 主 Agent 忙于用户对话时大量后台报告只增加报告索引，不改变当前模型上下文。
- 新接手 Agent 使用新身份和空白个人记忆，仅收到明确选择的 handoff 附件。
