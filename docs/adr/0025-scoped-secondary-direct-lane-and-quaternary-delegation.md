# ADR-0025：次级 Agent 任务直达、职责分离与四级委派

- 状态：已接受，待实现
- 日期：2026-08-16
- 决策范围：用户路由、项目上下文获取、任务规划、测试验收、Git 集成、四级 Agent
- 对应任务：T08C

## 背景

既有控制流把主 Agent 设为唯一用户对话入口，并由次级 Agent 调度三级 Agent。该结构适合需要讨论方向、跨模块权衡或持续战略沟通的任务，但对目标明确的小型工作会增加一次没有实际价值的主 Agent 转发。同时，如果次级 Agent 为掌握项目细节而直接吞入大量源码和文档，会迅速消耗上下文，降低后续规划、审查和合并质量。

现有三级 Agent 只执行一条任务链，次级 Agent 负责最终 Git 集成。面对紧急或工作量较大的任务，还需要允许三级 Agent 在自己的任务链内继续拆分，但不能因此把三级 Agent 提升为项目集成者，或让四级 Agent 获得更宽权限和完整上级上下文。

## 决策

### 1. 保留主 Agent 独占用户对话，增加任务级次级直投通道

- 单会话仍只有一个负责大体方向、全面布局、跨任务权衡和用户表达的战略主 Agent；主 Agent是唯一与用户进行连续对话的 Agent。
- 用户默认把消息发送给主 Agent。遇到目标明确、无需方案讨论的小型任务时，界面推荐“直接交由次级执行”；认证用户确认后，本地控制面把用户原始指令投递给一个具体次级 `agentInstanceId`，不调用主 Agent模型进行重复规划。
- “次级直投”描述的是任务信封的投递路径，不建立用户与次级 Agent之间的独立对话。用户仍停留在主 Agent会话中，次级结果按汇报链返回主 Agent。
- “适合直达”的自动建议只能来自本地版本化资格策略。默认要求：目标和验收标准明确、无需方案讨论、影响范围有界、不修改总体架构或公共契约、不含未决高风险裁决、没有跨项目协调。无法确定时回到主 Agent。
- 用户的显式路由决定具有最高优先级，但不能绕过安装、权限、备份删除、发布和其他操作授权门禁。
- 直达消息仍是认证用户来源，进入次级 Agent 自己的任务偏序集时保持 `priorityTier: 0`；次级拆出的任务节点是 Agent 来源，只能使用层级 1 或以下。
- 本地控制面投递时保留原始用户来源、具体目标次级 Agent、任务范围和 revision；次级只收到该任务消息与显式附件，不自动复制主 Agent完整会话。
- 次级 Agent的过程与终态汇报经独立反馈进程进入主 Agent只读报告索引。默认不把大量三级/四级明细注入主 Agent当前上下文；主 Agent在向用户反馈或继续规划时按需读取次级摘要。

### 2. 主 Agent 不掌握项目实现细节

- 主 Agent 负责目标、优先级、路线、跨项目取舍和用户长期决策，不承担源码级持续上下文。
- 用户向主 Agent询问具体实现细节时，主 Agent向负责该范围的具体次级 Agent 发起结构化细节查询；次级 Agent把可追溯结果反馈给主 Agent，再由主 Agent按用户的知识水平、问题目的和当前对话语境解释给用户。
- 主 Agent不能把“不了解细节”作为猜测依据。没有次级证据时必须明确说明并发起查询。

### 3. 次级 Agent 通过侦察型三级 Agent 获取项目上下文

- 次级 Agent 需要了解项目时，优先创建或复用一个具体的 `project-reconnaissance` 三级 Agent，为其分配只读任务链和最小读取工具子集。
- 侦察 Agent 读取允许范围内的源码、架构文档、任务文档、测试和 Git 只读信息，生成版本化 `PROJECT_CONTEXT_DIGEST_V1`。
- 摘要必须包含：扫描范围、关键入口、稳定契约、相关文件引用、内容指纹、依赖关系、测试入口、未确定事项、冲突和来源。不得把大量原文、完整工具输出或无关文件塞入次级上下文。
- 原始读取回执和详细观察保存在侦察 Agent 的个体存档；次级 Agent只接收受 token 预算约束、带来源/revision/hash 的不可变摘要附件。
- 项目指纹变化后旧摘要标记为 stale；次级 Agent可要求增量复查，不默认重新注入全部历史。
- 敏感内容禁读、反自指和读取活锁保护对侦察 Agent 同样生效。

### 4. 次级 Agent 负责详细规划、分发和合并裁决

- 次级 Agent 是项目执行细节的主要所有者，负责把用户目标转化为任务偏序集、任务包、允许路径、完成条件、上下文附件和模型用途。
- 次级 Agent 任命实现、测试和验收用途的具体三级 Agent。实现者不能验收自己的产出。
- 默认使用三个不同的 `agentInstanceId`：实现 Agent、测试 Agent、验收 Agent。低风险任务可由用户策略允许测试和验收由同一个非实现 Agent承担；高风险任务三者必须独立。
- 测试 Agent只验证确定性测试、属性/并发/安全反例、构建与打包证据；验收 Agent对照任务目标、架构约束、差异、测试证据和人工验收要求给出 `rework | merge-ready | blocked-human-review` 建议。
- 次级 Agent依据不可变提交哈希、测试证据和验收报告作出返修或合并决定。缺少人工体验、操作授权或高风险用户裁决时只能进入 `blocked-human-review`。
- 次级 Agent仍是向 mission 集成分支、用户目标分支和远端仓库执行最终技术合并的唯一层级；模型建议不能绕过本地合并门禁。

### 5. 三级 Agent 可以委派四级 Agent

- 当任务紧急、任务量大、存在可并行子链或达到用户配置的资源条件时，三级 Agent可以经本地控制面创建四级 Agent。
- 四级 Agent必须绑定具体上级三级 `agentInstanceId`，一次激活只执行其上级任务链中的一个严格子链；任务、工具、权限、资源范围、期限和上下文均不得宽于三级 Agent。
- 四级 Agent使用新的不可复用 `agentInstanceId` 和独立记忆、缓存、读取回执、mailbox、工作存档及 worktree。只接收显式选择的上下文附件。
- 四级 Agent不能创建第五级 Agent、修改上级偏序集、访问兄弟记忆、操作远端项目、写入 mission 集成/目标分支或直接向用户请求权限。
- 四级 Agent向所属三级 Agent报告；三级 Agent负责其子链规划、测试、审查和收口。
- 四级 Agent首次接收工具组时获得完整公开用法，同一 revision 后续只接收 `ASTARRAY_TOOL_HELP_REQUEST_V1` 提醒；其默认工具帮助上级是所属三级 Agent，未分配或不可用能力再由三级逐级上报。帮助回执不授予工具或权限。
- 若四级 Agent产生 Git 写入，次级 Agent为其预先分配四级隔离分支/worktree。三级 Agent可以在本地门禁验证后把直属四级贡献合入自己获分配的三级任务分支，但不得向上合入 mission 集成分支、目标分支或远端；最终向上集成仍由次级 Agent完成。
- 三级 Agent整合四级贡献时必须保留各具体四级来源、提交、允许路径和测试证据，且不得用 Git 分支替代破坏性变更自动备份。

### 6. 主 Agent 独占用户通信与次级摘要

- 用户界面的连续对话对象始终是主 Agent。次级直投入口必须明确显示具体目标次级 `agentInstanceId`、任务范围以及“结果将由主 Agent解释反馈”，避免被误认为切换聊天对象。
- 次级直投不授予读取主 Agent记忆、其他次级记忆或全局用户历史的能力。
- 次级 Agent会接收大量三级和四级汇报，因此默认生成版本化 `SECONDARY_USER_FACING_SUMMARY_V1`，只包含目标、当前进度、主要结果、风险、需要用户决定的事项和证据引用。详细日志与个体报告留在次级自己的存档和报告索引中。
- 主 Agent读取次级摘要后，可以压缩术语、补充背景、分层解释或询问用户是否需要展开，但不得改变事实、删除关键风险或把次级来源冒充为主 Agent自己的发现。
- 用户要求细节时，主 Agent发起绑定具体任务/revision的问题；次级返回针对性明细或新的摘要。用户主动查看原始报告属于只读审计行为，不建立与次级/三级/四级的直接对话。
- 三级、四级不直接与用户对话；需要人工裁决时沿直属上级逐级上报。
- 所有跨层消息经独立反馈进程传递；转发保留原始来源和路由链。

## 权限与 Git 不变量

- 主 Agent仍只有读取类模型工具。
- 次级 Agent的当前有效权限是三级 Agent的上限；三级 Agent的当前有效权限是四级 Agent的上限。
- 每次实际工具执行仍重新鉴权。委派、紧急程度、模型切换和用户直达都不能扩大权限。
- 次级 Agent是唯一项目级 Git 集成者；三级 Agent只可在自己任务分支内整合直属四级贡献；四级 Agent只写自己的隔离分支。
- 实现、测试、验收和合并使用具体 Agent身份、提交哈希和任务 revision 绑定，任一变化使旧验收结果失效。

## 完成条件

- 用户可在主 Agent会话中把符合资格的小任务直投具体次级 Agent；结果由次级生成摘要并由主 Agent解释回复。不符合资格或存在方案歧义时无损交回主 Agent规划。
- 主 Agent询问细节时通过具体次级 Agent获得针对性回答，不加载整个项目源码或全部下级上下文，也不向用户伪装自己掌握了未查询的细节。
- 项目侦察摘要证明大规模原文未进入次级 prompt、日志、缓存或长期记忆；摘要失效和增量刷新可追溯。
- 实现、测试、验收个体隔离，作者不能自验；次级 Agent只有在全部门禁满足时才能合并。
- 三级 Agent可以分派多个四级子链，但四级权限、工具和任务始终是严格子集；不存在第五级委派。
- 四级 Git 提交只进入三级任务分支，三级不能向上合并，次级最终集成保留完整贡献来源。
- TUI、Headless CLI 和 GUI 均明确显示主 Agent是当前对话对象，并提供“小任务直投次级”入口、四层 Agent树、次级用户摘要、侦察摘要、测试/验收状态和合并裁决。
- 单元、属性、并发、真实反馈进程、Git worktree、崩溃恢复和 tarball 隔离测试通过，关键分支覆盖率不低于 95%。
