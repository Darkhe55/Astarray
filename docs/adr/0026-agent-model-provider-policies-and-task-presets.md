# ADR-0026：Agent 独立模型/提供商策略与任务类型预设

- 状态：已接受，待实现
- 日期：2026-08-16
- 决策范围：模型目录、Provider、Agent 独立选择、故障切换、任务类型预设、设置界面
- 对应任务：T07C

## 背景

不同 Agent 用途对模型能力、上下文、速度、成本、工具调用和多模态支持的需求不同。战略主 Agent、项目次级 Agent、项目侦察、编码、调试、测试、验收、办公文档、前端和绘图不应被迫使用同一个模型或 Provider。同时，允许 Agent 任意填写模型名称会绕过用户成本、数据出境和能力边界，也可能在 Provider 切换时复制不应外发的上下文。

## 决策

### 1. 版本化模型与 Provider 目录

- 本地控制面维护版本化 `ModelProviderCatalog`。公开条目使用稳定 `providerProfileId` 与 `modelProfileId`，记录显示名、模型标识、能力、上下文上限、工具/视觉支持、成本标签、区域和健康状态。
- Provider 凭据、API key、endpoint secret 和本地能力令牌仅以受保护引用存在，不进入模型目录公开 DTO、Agent prompt、日志、导出或反馈。
- 用户可登记任意数量的 Provider 和模型条目；产品不设置模型列表数量上限。通用磁盘、文档大小和界面分页限制不能转化为模型数量配额。

### 2. 每个 Agent 独立选择和切换

- 主、次级、三级、四级每个具体 Agent都拥有独立 `AgentModelAssignment`，模型选择不按角色共享可变状态。
- Agent可以在用户允许列表内请求或自动选择模型，并在检查点边界切换 Provider/模型。用户可将策略设为固定模型，此时 Agent不能自行切换。
- 切换只能发生在没有未决工具调用、未确认副作用或并行 Provider请求时。切换前保存任务检查点，切换后从该 Agent自己的记忆摘要和当前任务附件重建上下文。
- 模型切换不改变 `agentInstanceId`、任务所有权、记忆域、工具子集、权限、Git职责或优先级。
- Provider 切换前执行本地数据出境和内容策略；不允许发送的内容不能因为故障切换而转移到另一个 Provider。

### 3. 用户强制用途模型列表

- 设置控制面允许用户按用途配置不设数量上限的允许模型列表，例如：
  - `strategic-main`
  - `project-secondary`
  - `project-reconnaissance`
  - `implementation`
  - `testing`
  - `acceptance`
  - `craftsman-workflow-customization`
  - `quaternary-subtask`
- 每个用途策略支持 `fixed`、`ordered-fallback`、`automatic-within-list` 和 `manual-each-run`。
- 用户强制的允许列表是硬上限。列表中没有健康且满足能力要求的模型时任务进入 blocked 并反馈，不得静默使用列表外模型。
- 列表顺序、选择策略、预算、Provider区域和能力过滤均绑定 revision；修改后未开始的运行重新解析，运行中的切换在下一个安全检查点生效。

### 4. 高级任务类型 Agent 预设

- 用户可以创建、命名和配置不设产品数量上限的 `TaskAgentPreset`，把任务类型映射到 Agent用途和模型列表。
- 内置建议类型包括办公文档、前端、通用编码、debug、测试、验收、资料侦察、工匠工作流定制、绘图/视觉；用户可以增加自定义任务类型。“工匠”的阶段披露与执行边界由 ADR-0027 控制，模型预设不能使其提前显现或扩大权限。
- 每个预设至少包含：稳定 ID、显示名、匹配任务类型、目标 Agent层级/用途、允许模型列表引用、选择策略、所需能力、工具子集上限、权限 profile 上限、并发/成本预算和 fallback 行为。
- 自动任务类型匹配只能建议预设；涉及更宽权限、数据出境、额外安装或成本提升时仍需要现有控制面裁决。用户显式指定预设时优先。
- 绘图/视觉预设只有在允许列表中存在视觉能力模型且当前工具权限允许时才能派发；模型能力说明不授予绘图、文件或网络工具。

### 5. 配置优先级

有效模型策略按以下顺序解析，越具体的用户设置覆盖越宽泛设置，但不能突破全局 Provider/模型禁用和数据策略：

1. 当前任务的认证用户显式固定模型或预设。
2. 具体 `agentInstanceId` 的会话级覆盖。
3. `TaskAgentPreset` 的任务类型映射。
4. Agent用途允许列表。
5. Agent层级默认列表。
6. 会话全局默认列表。

解析结果、catalog revision、策略 revision、选择原因和 fallback 次序写入审计。模型或 Provider不能修改自己的允许列表。

### 6. 故障切换与可观测性

- 超时、限流、能力不匹配或 Provider故障时，只能按有效列表和策略进行有界 fallback。
- 每次切换生成 `AGENT_MODEL_SWITCH_V1`，包含具体 Agent、任务、旧/新模型公开 ID、原因、策略 revision、上下文指纹和时间；不包含凭据或完整 prompt。
- 同一任务的失败切换使用有界预算和退避，不能在多个 Provider间活锁。
- 测试和验收 Agent可由用户设置为不同 Provider/模型以降低相关性，但产品不强制使用不同供应商，也不能把模型多样性当成验收通过依据。

### 7. 设置与导出

- TUI、Headless CLI 和 GUI 共用认证设置控制器，提供 Provider/模型公开目录、用途列表、排序、固定/自动策略、任务类型预设、具体 Agent会话覆盖和当前有效解析结果。
- 设置页面对大列表使用搜索、分页或虚拟列表，不设置数量配额。
- 导出只包含公开配置、稳定 ID、显示名和策略，不包含凭据、endpoint secret、会话令牌、内部健康探针或一次性授权。
- 模型设置控制器不是 Agent工具；Agent只能提交切换请求或能力不足报告。

## 完成条件

- 四个层级的具体 Agent可以同时使用不同模型/Provider，彼此切换不污染身份、记忆、缓存或工具权限。
- 用户可为每种用途设置任意长度的模型列表，并创建任意数量的任务类型预设；不存在硬编码数量拒绝。
- 固定、顺序 fallback、自动列表内选择和逐次手选均有确定行为；列表耗尽时 fail-closed。
- 中途切换只在安全检查点发生，不重复未确认调用，不跨 Provider泄露受限上下文。
- 办公文档、前端、编码、debug、测试、验收、侦察、工匠工作流定制和绘图预设可动态验收；预设不能扩大权限、使工匠提前披露或绕过安装门禁。
- 设置修改、目录升级、模型禁用、Provider故障、能力不匹配、成本/并发预算和活锁保护均有单元、属性、并发与 fake-provider 测试。
- TUI、Headless CLI、GUI 和 tarball 隔离环境行为一致；关键分支覆盖率不低于 95%。
