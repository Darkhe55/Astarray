# ADR-0027：阶段性显现的“工匠”三级 Agent 预设

- 状态：已接受，待实现
- 日期：2026-08-17
- 决策范围：三级 Agent 预设、阶段触发、渐进式能力披露、工作流定制、次级自动安排提示词
- 对应任务：T08D

## 背景

项目推进到中后期后，经常会重复出现相似的检查、转换、构建、测试、资料整理或交付流程。每次临时重新组合基础工具会浪费次级 Agent 的规划上下文和三级 Agent 的执行时间。为此增加“工匠”三级 Agent：它利用当前已经存在且已授权的基础工具，深入定制可复用工作流、方法、模板和安全执行配方。

“工匠”不应在会话开始时就占用次级 Agent 的工具/角色说明上下文。它作为本地控制面中的休眠预设存在，只有会话时间、项目阶段、项目记忆规模或重复工作模式达到配置阈值后，才向具体次级 Agent披露为可选下级。渐进披露用于减少早期上下文噪声，不是隐藏安全规则；用户可在设置中随时查看、配置、立即披露或禁用该预设。

## 决策

### 1. “工匠”是休眠的三级 Agent 预设

- 内置稳定标识为 `tertiary-preset:craftsman-v1`，用途标识为 `craftsman-workflow-customization`，中文显示名固定为“工匠”。
- 会话开始时，本地控制面只加载预设元数据和阶段策略，不创建工匠 Agent，也不把它的提示词、工具说明或完整能力描述注入次级 Agent上下文。
- 阶段规则命中后，本地控制面经独立反馈进程向具体次级 `agentInstanceId` 发送 `CRAFTSMAN_PRESET_AVAILABLE_V1`。该消息仅表示“现在可选择该下级”，不代表已创建 Agent、已领取任务或已获得新权限。
- 用户可从设置或主会话显式要求立即披露。用户也可完全关闭自动阶段披露；关闭不删除预设配置或既有工匠产物。
- 每次真正执行都创建或复用一个符合生命周期规则的具体三级 Agent，使用不可复用 `agentInstanceId`、独立记忆域、mailbox、读取回执、工具说明回执、任务链和隔离 worktree。

### 2. 工匠的职责与边界

- 工匠只使用所属次级当前可分发且已经存在的基础工具子集，分析重复工作，产出深度定制的工作流、方法、模板、配置、脚本或组合配方，以减少后续重复规划和工具调用。
- 工匠不得因为“定制工作流”自行安装依赖、克隆代码库、注册新工具、扩大工具 schema、修改权限 profile、读取其他 Agent记忆或绕过 Assist 安装双重门禁。
- 若定制需要新增依赖或能力，工匠只能按 `ASTARRAY_TOOL_HELP_REQUEST_V1`/能力上报链说明缺口；次级再按既有安装和授权流程处理。未获授权时必须提供仅使用现有工具的降级方案或报告阻塞。
- 工匠一次激活只处理一条“工作流定制”任务链。其代码/配置产物只能写入自己的隔离分支；测试、验收和项目级合并仍遵循次级 Agent的现有门禁。
- 工匠不能担任自己产物的最终验收 Agent。可复用产物进入项目前，至少由一个不同的测试/验收三级 Agent验证；高风险自动化仍使用独立测试和验收个体。

### 3. 阶段信号由本地确定性控制器计算

阶段控制器只读取本地公开元数据、计数器、任务终态和显式里程碑事件，不让模型判断“是否已到阶段”。支持以下信号：

- `activeSessionDurationMinutes`：排除暂停、离线和纯等待后的累计活跃会话时长。
- `acceptedTaskChainCount`：已经通过次级验收门禁的任务链数量。
- `acceptedMilestoneIdentifiers`：如架构冻结、基线验收、首次功能集成、稳定化阶段等版本化里程碑事件。
- `projectMemoryIndexEntryCount` 与 `projectMemoryIndexedBytes`：只统计允许公开的项目记忆索引元数据，不读取记忆正文或敏感文件。
- `repeatedWorkflowFingerprintCount`：由本地规范化工具序列/任务类型指纹识别的重复次数，不使用云端语义判断。

所有信号值、阈值、策略 revision 和命中原因写入可审计阶段记录。文件大小、时间和计数变量必须在名称中明确单位；符号链接、别名路径和敏感存储不纳入记忆规模统计。

### 4. 内置阶段策略与用户自定义

系统提供三个可编辑建议模板；数值是默认值，不是不可变安全边界：

| 策略 | 任一条件命中后披露 |
|---|---|
| 较早 | 活跃 30 分钟；首个集成里程碑；记忆索引 64 条或 512 KiB；同一工作流指纹重复 2 次 |
| 均衡（默认） | 活跃 90 分钟；3 条任务链验收通过；记忆索引 256 条或 2 MiB；同一工作流指纹重复 3 次 |
| 保守 | 活跃 180 分钟；8 条任务链验收通过或进入稳定化阶段；记忆索引 1,024 条或 8 MiB；同一工作流指纹重复 5 次 |

- 用户可创建、命名和配置不设产品数量上限的 `CraftsmanStageTriggerProfile`，选择 `any`/`all` 组合规则、信号、阈值、里程碑集合、冷却时间、每阶段提醒次数、目标次级范围和披露动作。
- 用户可只启用某类信号，例如完全不使用时间条件，或只在指定项目里程碑后披露。
- 预设、阈值或项目 revision 变化后重新计算，但必须使用幂等披露键，防止恢复、并发和重复事件造成通知风暴。
- `pn` 仍只用于反馈等待退避且单次上限 3 小时；阶段时长阈值不是 `pn`、任务 TTL 或自动授权有效期。

### 5. 披露动作和次级自动安排提示词

每个阶段策略可选择：

1. `suggest-only`（默认）：只把工匠作为可选下级通知次级 Agent，由次级决定是否提出或安排工作流定制任务。
2. `suggest-with-prompt`：同时附加用户预先编写的 `secondaryArrangementPromptTemplate`，要求次级结合当前 ready set、重复工作指纹和权限边界形成安排建议。
3. `auto-enqueue-proposal`：本地控制面把该提示词生成的“评估并安排工匠”节点放入次级偏序集；自动节点来源仍是本地策略，只能使用优先级层级 1 或以下，不能抢占用户层级 0 任务。

自动安排提示词是给次级 Agent的计划输入，不是工具授权、安装同意、Git 合并许可或用户验收。次级可以选择新建或复用具体工匠 Agent，但必须说明目标、输入、现有工具子集、预期复用收益、产物位置、测试和停止条件。用户在触发时显式确认形成的新任务才可作为用户来源层级 0。

`CRAFTSMAN_PRESET_AVAILABLE_V1` 至少包含：具体接收次级 Agent、项目/会话、阶段策略 ID 与 revision、命中信号摘要、披露动作、提示词模板引用、幂等键和结构化原始来源。转发不得覆盖来源。

### 6. 工匠产物契约

工匠完成时生成 `CRAFTSMAN_WORKFLOW_BUNDLE_V1`，至少包含：

- 目标问题、适用/不适用范围和重复工作指纹；
- 使用的现有工具公开 ID/revision、组合步骤、输入/输出和前置条件；
- 权限、敏感数据、自动备份、幂等性、失败恢复和活锁边界；
- 产物文件/提交引用、来源 Agent、任务 revision 和内容哈希；
- dry-run 或最小实验、确定性测试、性能/调用量对比及已知限制；
- 兼容性条件、失效条件、版本和推荐复查里程碑。

长工具输出和工作记录保存在具体工匠 Agent的个体存档；次级只接收有界 bundle 摘要。跨 Agent复用必须由本地控制器选择具体 bundle revision 形成不可变附件，不能自动污染其他 Agent长期记忆。

## 完成条件

- 新会话开始时次级 Agent prompt、工具说明和可选下级列表中不出现工匠完整说明；阶段命中前不存在工匠实例或隐式工具授权。
- 每种内置信号、`any/all` 组合、用户自定义阈值、手动披露、禁用、冷却、恢复和并发去重行为确定且可追溯。
- 阶段命中后只向目标具体次级 Agent披露；其他同级次级 Agent不继承通知或上下文。
- 三种披露动作均可动态验证；自动节点只能位于层级 1 或以下，不能绕过用户任务、权限、安装、备份、验收或 Git 门禁。
- 工匠只用已有已授权工具完成至少一种真实重复工作流定制，并证明后续调用/规划成本下降；需要新依赖时正确阻塞或降级。
- 工匠产物经不同 Agent测试/验收后才可由次级合并，来源、revision、哈希和失效条件完整。
- TUI、Headless CLI 和 GUI提供阶段模板、自定义信号、提示词、披露动作、当前阶段状态、手动披露和通知记录；大列表使用搜索/分页且不设数量硬上限。
- 单元、属性、持久化恢复、并发、真实反馈进程、权限反例、Git worktree 和 tarball 隔离测试通过；关键分支覆盖率不低于 95%。
