# ADR-0033：细节微淘原型的能力边界与来源契约

- 状态：Proposed（WB-00-01 冻结草案；实现检查点 WB-00-02 通过后转 Accepted）
- 日期：2026-09-13
- 来源：WB-00 任务卡（Agent 派生实施方案）；能力矩阵见 `docs/reports/WB00_01_SCOPE_FREEZE.md`

## 背景

设计大纲 §12 的"细节微淘"要求用户不必离开 Astarray 就能对产物做小幅修订，并把修订安全地回交模型。
风险点是：编辑器很容易滑向"万能格式编辑"，而任意格式的解析-重写会引入往返损失；
人类编辑与 Agent 并发修改还牵涉备份、revision、来源与模式权限边界。

本 ADR 只冻结**首期原型的边界**，不实现代码（实现属 WB-00-02/03/04）。

## 决策

1. **首期场景**：只做**单文件、字节级区间的文本/代码内嵌编辑**与模型回交。
   - S1 文档/说明文字的小幅修订（错别字、措辞、补充段落）；
   - S2 源码小补丁（少数字符/行）；
   - S3 配置/数据文本的定点取值修改。
   图片/UI、视频/音频**不在本期**，另立任务卡（ADR 明确不声明支持）。

2. **能力矩阵（原生编辑 / 局部替换 / 只读）**

   | 对象 | 原生编辑 | 局部替换 | 只读 | 说明 |
   | --- | --- | --- | --- | --- |
   | UTF-8 无 BOM 文本（txt/md/ts/tsx/js/json/yaml/toml/css/html/sql/sh…） | ✅ | ✅ | — | 字节级区间替换；未触碰区间字节不变 |
   | 非 UTF-8 编码、含 NUL 的二进制 | — | — | ✅ | 不提供编辑入口，只提示 |
   | `.env`/`.env.*`、私钥、凭据库、本地敏感路径 | — | — | ✅（且禁读） | 由本地路径/内容策略在打开或返回前执行，模式升级不可绕过 |
   | 工作区边界之外 | — | — | ✅（拒绝） | 由 WorkspaceBoundary 判定 |
   | `node_modules`/`dist`/`.git`/vendor 等生成物与依赖目录 | — | — | ✅ | 编辑它们不构成有效交付 |
   | 超过大小预算（首期默认 256 KiB 或 200k 字符，取先到者） | — | — | ✅ | 提示改用专门任务 |
   | 结构性格式的"语义级重排"（JSON 键排序、YAML 归一、XML 美化等） | — | — | ✅（不做） | 会引入往返损失，转交任务处理 |

3. **往返损失声明**：原型**不做格式解析与重写**，只在区间内替换字节，并且：
   - 未编辑区间**字节级零损失**（含 CRLF/LF、tab/空格、行尾空格、缩进风格、注释顺序）；
   - 不规范化 BOM、不重排 JSON 键、不改引号风格、不自动格式化；
   - **不宣称全部格式可无损编辑**：需要结构化重排或格式化的场景一律判为只读并转交任务，
     在 UI 上显式说明"此格式不支持内嵌编辑"。

4. **草稿 / 发布 / 撤销**
   - **草稿**：本地自动保存（输入防抖 500 ms），服务端草稿文件
     `agent-memory/<agentInstanceId>/micro-edit-drafts/<artifactKey>.json`（含 `artifactRevision`、
     `baseContentHash`、草稿正文与来源）。**逐按键不触发任何模型调用**。
   - **发布**：只有显式"发布"才形成**不可变差异**（unified diff + `baseContentHash` + `resultHash` +
     新 `artifactRevision` + 来源），写入该 Agent 工作存档条目；模型只在下一次请求获得**有界差异**，
     不获得整份文件（受 ADR-0029 读取预算与全局上下文预算约束）。
   - **撤销**：以"再发布一次上一版内容"实现（revision 前进），**不删除备份**；
     撤销**不替代**变更前自动备份（ADR-0009）。

5. **来源契约**：人类编辑必须携带 `{ sourceType: "user", userId }`（具体到不可复用的人类个体）；
   Agent 发起的变更必须为 `{ sourceType: "agent", agentInstanceId }`；转发时保留原始来源；
   来源不进入可配置权限目录，也不能由模型声明或字符串推断（与 ADR-0007/0028 一致）。

6. **变更前自动备份**：任何删除、文本删减、替换、截断或覆盖都由执行层在写入前自动备份
   （`BackupVault.createPreMutationBackup`，由工具策略包装器在工具执行前调用，不经过模型）；
   备份只能经受控备份工具读取或恢复（ADR-0010），草稿与撤销都不是备份的替代品。

7. **并发修改与陈旧覆盖**：产物以 `artifactRevision` + 内容哈希标识；发布采用 CAS，
   期望 revision 不符时**拒绝陈旧覆盖**（保留人类修改），由用户显式重放或合并（ADR-0028）。

8. **模式与预算边界**：思索模式**完全只读**（无编辑器入口）；协同/放权模式允许**本地人类**编辑
   （这是用户动作，不是模型工具调用）；模型回交差异受上下文预算与读预算约束，超限只回摘要与引用。

9. **依赖策略**：不捆绑大型媒体或编辑器依赖。首期内嵌编辑为零依赖实现（`contenteditable`/`textarea` +
   自研最小高亮），**懒加载**（首次进入编辑态才加载该模块）；若后续确需 Monaco/CodeMirror 等外部组件，
   按 ADR-0019 安装门禁先询问用户是否已有可用资源，再逐次授权，不在本卡内隐式下载。

10. **资源测量定义（WB-00-04）**：冷启动到页面可用、首次可编辑耗时、空闲/活动内存、CPU 占用、
    磁盘增量、关闭回收、单次修订总耗时；必须同时提交设备规格与输入规模，只在证据支持后提出
    图片/UI/视频新任务卡。

## 非目标

- 不做格式感知的结构化编辑、批量重构、跨文件改动。
- 不做多人实时协同编辑；并行修改按 ADR-0028 的"保留+拒绝陈旧覆盖"处理。
- 不在本期声明图片/UI/视频/音频编辑能力。

## 后果与风险

- 只做字节级区间编辑牺牲了"智能格式化"，换来可验证的零往返损失与最小权限面；对需要的场景给出转交路径。
- 人类编辑与 Agent 并发下的差异语义需在 WB-00-03 用真实场景验证（人类修改保留、陈旧覆盖拒绝、草稿恢复）。
- 懒加载模块仍需人工体验结论（首帧、内存）支撑，未测量前不宣称性能收益。
