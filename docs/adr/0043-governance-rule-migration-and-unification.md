# ADR-0043 治理规则迁移与文档统一（安装/外部软件与范围裁决）

- 状态：已采纳（GOV-01 冻结；文档改写与测试期望修订属 GOV-02）
- 日期：2026-09-17
- 来源：docs/tasks/2026-09-16_INCREMENTAL_DESIGN_TASK_CARDS.md §2/§7（用户指导，未跟踪文件）
- 相关：ADR-0019（安装两阶段门禁）、ADR-0020（可配置权限组）、ADR-0039（范围分类与裁决矩阵）、ADR-0042（读取依赖规则）

## 1. 背景

旧规则（AGENTS.md 安装条款、ADR-0019）把协同模式下的安装统一视为「任意安装均逐次人工授权」。
用户确认的新方向是「**先识别实际作用范围，再确定上级或人工裁决者**」（ADR-0039 的 S1–S7 与三模式矩阵）：
项目内、作用范围已验证且受控的操作可由有权上级按设置批准；跨项目根、项目外副作用、未知范围与外部软件控制需人工；
安装类（S5）仍需独立安装开关。

迁移不得丢失既有安全要素，也不得保留同时生效的矛盾描述。本 ADR 冻结迁移范围、必须保留的要素与冲突清单。

## 2. 统一契约（冻结）

1. **单一权威表述**：范围与裁决以 ADR-0039 为准，迁移与统一以本 ADR 为准；任何旧表述必须改写为引用（或标注已被替代），
   不得保留「协同模式任意安装均逐次人工授权」这类与新矩阵同时生效的矛盾描述。
2. **必须保留（不得因迁移丢失）**：
   - 独立安装功能开关（默认关闭；**关闭即拒绝**，开关不得代替授权）；
   - 已有资源询问/选择流程与「确认没有」的有效回执；
   - 绑定精确内容与参数的逐次授权、一次性 nonce、revision 检查与**执行前复检**；
   - 不得使用会话记忆、Agent 推断或批量许可放行；
   - `deny` 优先；S4（范围未知）不得把「用户离线」当同意（ADR-0039）。
3. **变更点**：安装与外部软件不再一律人工；先判定实际作用范围（S1–S7），再按矩阵选择上级自动批准或人工裁决；
   项目内受控安装可上级批准，全局安装、项目外缓存/环境写入与未知安装脚本不得借项目内 cwd 放行。
4. **历史记录保留**：被替代的旧表述不删除，改为「历史/已替代」并注明替代 ADR 与 revision；历史验收记录保留其当时语义。
5. **顺序**：先改文档（治理文件、ADR 标注），再改测试期望与实现；测试期望修订必须与新规则匹配且**不得放宽**，
   实现改动须先写行为反例（安装类 S5 仍拒绝开关关闭；项目内受控安装按矩阵）。
