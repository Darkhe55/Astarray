# Astarray 架构文档

> 对应实施批次：T00（架构定稿与契约）。
> 设计来源：`agent-main-architecture.md`、`designtodo.txt`、`IMPLEMENTATION_PLAN.md` §2（冻结决策）。

## 1. 总体结构

单一主 Agent + 三种内置模式（Ponder / Assist / Devolve）+ 用户命名自定义权限模式。内置模式的默认信任梯度为：

```
Ponder（思索模式，本地只读、零副作用） → Assist（协同模式，次级 Agent 受限执行 + 门禁询问） → Devolve（放权模式，次级 Agent 权限默认允许 + 自由调度）
```

- 模式是主 Agent 的一个运行状态，不是独立进程。
- 主 Agent 将任务转交本地会话控制器后立即回到待机，持续接收用户输入，不陷入任务流程。
- 每个主、次级、三级 Agent 个体都以不可复用的 `agentInstanceId` 使用独立记忆域和模型上下文；不存在角色级或同级共享记忆。跨 Agent 只能传递带来源的反馈或明确选择的不可变附件。

## 2. 三层 Agent 分工

| 层级 | 职责 | 工具信息 |
|---|---|---|
| 主 Agent | 持续与用户交流和评估，形成任务插入提案；后台结果只入报告索引，后续对话按需读取 | 读取类工具预览与只读报告读取 |
| 次级调度/集成 Agent（Assist） | 独占待办偏序集持续调度；决定复用/新建/关闭三级 Agent；负责 Git 分支与 worktree、审查、测试、合并及获授权的 GitHub/远端项目控制与传输 | harness 内置提示词：其有效权限内的工具与用法 |
| 三级执行 Agent（Worker） | 一次激活只执行一条任务链；代码只提交自己的隔离分支；向任务发放源报告终态或中断原因，等待次级生命周期决策 | 当前任务链所需工具子集 |

Devolve 模式下本地会话控制器仍创建具体次级 Agent，由次级 Agent 决定调度策略；只要任务使用多个 Git 写入 Worker，该次级 Agent 同时负责分流、审查和技术合并，复用同一 task store、反馈进程、Worker 与工具策略边界。主 Agent 始终只接收、读取和转交。

主 Agent 生成的 `TaskInsertionProposal` 由本地控制面写入次级 Agent 偏序集。原始用户指导保持用户来源和层级 0；主 Agent 自行派生的设计/拆解保持 Agent 来源并只能层级 1 或以下。提交后主 Agent 不等待后台确认。次级 Agent 在 ready set、反馈、权限或 Git 基线变化时持续重新调度；每个任务链终态汇报异步写入主 Agent 报告索引，不唤醒或污染当前用户对话（ADR-0022）。

次级/三级 Agent 第一次接收某工具组时获得完整公开说明；相同 revision 的后续激活只收到 `ASTARRAY_TOOL_HELP_REQUEST_V1` 固定提醒。已分配工具的用法由本地控制器直接按单工具回复，未分配或不存在的能力逐级上报，三级默认上报所属次级。工具说明回执按个体隔离且不扩大权限。Agent 实例无累计或同级产品数量配额；并发资源不足时排队。直属上级经授权可把直属低一级 Agent 的不透明沟通句柄交给具体同级 Agent，但不转移任务、记忆、工具或权限（ADR-0024）。

## 3. 模块与依赖方向

```
TUI/CLI → Application Controller → Domain Core
                            ├────→ Orchestration
                            ├────→ Runtime/Tool Ports → Adapters
                            └────→ Stores/Feedback Process Client
```

强制约束：

- UI 不得直接访问 Provider、工具或文件系统。
- 独立反馈进程不得依赖 React/Ink。
- Agent 只能通过 feedback client 与独立反馈进程交互。
- 领域层不能依赖进程通信协议的具体实现（通过 `FeedbackTransportPort` 接口隔离）。

## 4. 独立反馈进程

- 形态：**独立进程**（`child_process.fork` 或同等跨平台机制），不得退化为进程内定时器或协程（ADR-0001）。
- 主进程负责启动、健康检查、优雅关闭与异常重启；反馈进程崩溃后重放未确认消息。
- 每个具体接收者以完整不可复用 `agentInstanceId` 拥有独立持久化 mailbox journal；同级 Agent 也不共享 mailbox 或投递视图。
- 每条消息必须携带结构化原始来源：用户、具体 Agent 个体或系统组件。Agent 来源必须包含不可复用的 `agentInstanceId` 和主/次级/三级角色，仅有角色名无效（ADR-0007）。
- 来源在消息进入反馈系统时确定并保持不可变；转发者不得覆盖原始来源。缺失或非法来源的消息在入池前拒绝并审计。
- 投递语义：普通消息仅在接收 Agent 为 `idle` 时投递；投递成功且收到 ack 后才从未投递集合消费（投递后 ack 前崩溃可幂等重投）。
- 退避：首次忙碌后等待 2 秒，依次 3、5、7、11… 秒（第 n 个质数），单次封顶 10,800 秒（ADR-0002）；新消息入池、接收者变空闲、重连成功时重置到 2 秒。
- 顺序：跨类型按优先级，同优先级严格 FIFO（ADR-0003）：`instruction > backup-deletion-warning > failure > permission-ask > ambiguous > success`。
- 控制通道：显式 cancel 属于控制信号，可通过 `AbortSignal` 中止；普通反馈不得中断 Agent。
- 展示与审计：TUI、headless JSON、诊断日志和审计事件均保留来源，使用户能区分用户裁决、Agent 汇报与系统事件。

## 5. Agent 个体记忆隔离、工作存档与选择性附加

- 每个主、次级、三级 Agent 个体拥有独立记忆目录；mission 工作文件为 `.astarray/missions/<missionId>/agents/<agentInstanceId>/work-archive.json`，长期个体文件为 `.astarray/agent-memory/<agentInstanceId>/memory-archive.json`（ADR-0008、ADR-0023）。
- 工作存档保存结构化摘要：任务分配、进度、关键决策、结果、失败、交接信息和产物引用；不默认保存完整模型上下文、原始超长输出或敏感值。
- Agent 只能挂载和读写自己的个体记忆域；任何上级、下级或同级 Agent 都不能直接访问另一个 `agentInstanceId` 的记忆路径。禁止按角色或同级组共享存档、缓存、收件箱或上下文。
- 上级 Agent 发布新任务或重新调用下级 Agent 前，只能由本地附件控制器选择具体存档条目形成附件；模型本身不直接读取源存档。
- 选择结果记录存档所有者、存档 revision、所选条目的完整结构化快照、选择原因与内容哈希；任务创建后使用不可变快照，避免并发更新改变已派发任务含义。
- 重新唤醒尚未回收的同一 Agent 个体可沿用其 `agentInstanceId`；回收后创建的替代 Agent 必须使用新 ID，并由上级显式附加旧个体的存档。
- 默认不自动注入完整存档，以控制 token、避免过期上下文污染。附加内容必须标记为历史上下文，不能覆盖当前用户指令、任务约束和权限策略。
- 附件位于接收方独立的外部历史上下文分区，仅对当前任务激活有效，不自动写入接收方长期记忆；需要保留时只能写带原始来源和附件哈希的本个体观察记录。
- 默认仅在同一 mission 内复用；跨 mission 复用需按长期记忆权限规则处理。

### 5.1 Agent 待办任务偏序集

- 每个承担调度职责的 Agent 在自己的记忆存档域保存独立待办序列：`.astarray/agent-memory/<agentInstanceId>/task-sequences/<taskSequenceId>.json`（ADR-0013）。
- 序列是有向无环图表示的偏序集。任务发布者添加任务时可指定直接前驱和后继；未指定位置时，新任务与现有节点不可比，不默认追加到队尾。
- 用户发布任务默认 `priorityTier: 0`；Agent、system 或工具生成任务只能使用层级 1 或以下。优先级身份由认证来源决定，不接受模型自由填写。
- 次级 Agent 分割用户任务时保留层级 0 的用户根任务；派生子任务仍处于层级 1 或以下，并作为该根任务的必要前驱，不通过继承用户层级提权。
- 调度器先选择前驱已完成的 ready set，再按优先级和稳定同级顺序执行。用户高优先任务不打断当前原子调用，但优先获得后续执行槽。
- 高优先任务若被必要的低层前驱阻塞，可以先执行该前驱，并在状态视图解释原因。
- 次级 Agent 可将同一优先层、适合同一执行者的一条依赖链冻结成任务包，一次派给具体三级 Agent；包内仍按节点记录完成、失败和阻塞。
- 控制面 `taskSequenceStatus` 提供只读序列、任务、ready set、顺序解释和任务包查询。用户在任意模式都可从 TUI/CLI 查看，不会打断 busy Agent；Ponder 模型可在认证可见范围内调用，但不能管理任务。
- Agent 待办序列不保存项目任务文档或产出内容，只保存外部引用；项目状态与 Agent 记忆调度状态不得隐式互相覆盖。

## 6. 权限模型

### 6.1 Git 分流与集成权限

- 次级 Agent 从固定 `baseCommit` 创建 mission 集成分支，并为每个三级 Agent 创建独立分支和 worktree；三级 Agent 只能写入自己的隔离工作树。
- 三级 Agent 完成后上报具体 `agentInstanceId`、基线/头提交、差异摘要和测试证据。次级 Agent 校验身份绑定、祖先关系、允许路径、敏感信息、命名和测试后，才可合入集成分支。
- 审查失败或冲突时不自动取舍，必须重新派发修正/冲突任务。所有 worker 结果集成后，由次级 Agent 运行完整门禁并生成结构化合并报告。
- 合入用户目标分支的技术操作由次级 Agent 完成，但仍受当前模式和用户裁决约束。`git push`、PR、发布、强制推送及受保护分支修改不自动授权。
- 分支不能替代工具内自动备份。reset、clean、checkout 覆盖、rebase、强制移动引用、删除分支/worktree 等破坏性 Git 操作必须由工具预先创建受保护恢复点并写审计。

- 工具类别：`readonly`（直接 allow）、`restricted`（ask 用户）、`forbidden`（deny）。
- Ponder 只获得显式本地只读白名单：工作区普通项目文件读取/列举/检索、只读任务状态和固定 Git 只读查询。通用 shell、进程、通用网络、写入、凭据和全部备份工具不暴露；即使构造调用也由本地 wrapper 硬拒绝。高严谨性资料搜索只能通过隔离的结构化事实代理完成。
- `LocalSensitiveOperationClassifier` 根据版本化工具元数据、实际参数、规范化真实路径、链接状态和打开方式确定副作用；未知或无法证明只读时 fail-closed。Provider/AI 风险评分不是授权依据（ADR-0014）。
- `SensitiveContentAccessPolicy` 是三种模式共同的不可放宽前置门禁：`.env`/`.env.*`、私钥、凭据库、能力令牌及本地 DLP 命中的内容均不得进入模型。它覆盖文件、搜索、Git、压缩包、插件、事实验证上传、缓存、反馈和存档，Devolve 与用户会话授权也不能绕过（ADR-0018）。
- Assist 会话授权默认 10 分钟或会话结束（先到者为准，ADR-0006）；参数变更后必须二次鉴权。
- Assist 安装使用独立的两阶段门禁（ADR-0019）：在任何代码库、依赖、运行时、插件、工具链或系统包安装前，先由认证用户回答是否已有可用资源；已有时只做只读兼容性验证，没有时才检查默认关闭的 `isAssistInstallationEnabled`。开关开启只允许提出申请，每次安装仍须绑定精确来源、版本/commit、目标、作用域、参数和安装脚本摘要取得 `allow-once`，不得继承十分钟会话授权。
- 安装开关只能经认证用户设置界面修改，Agent 与模型不能修改。等待已有资源答复或安装授权期间不持锁；工具执行前由本地策略复检模式、开关 revision、授权 nonce 和参数哈希。
- 权限在工具**实际执行前**检查（策略包装层），不只派发时检查。
- Devolve 免应用层逐次询问，但仍受工具注册表、工作区边界与操作系统权限约束。
- 模式降级：已开始的原子调用可正常结束；所有后续调用按新模式重新鉴权。
- 权限决策由版本化 `PermissionCapabilityCatalog` 与 `PermissionProfileStore` 驱动（ADR-0020）。每项可配置权限取 `deny/ask/allow`；Devolve 出厂配置全部 `allow`，Assist 使用独立默认矩阵，Ponder 配置签名冻结且只读。
- 用户可创建无产品数量上限的命名自定义权限组。运行态引用不可变 `permissionProfileId` 和 revision，名称只用于显示；工具、任务、反馈、缓存和审计不得只记录可变名称。新工具注册前必须映射权限目录，未分类工具 fail-closed。
- 权限组只配置应用层授权。内部强制执行层与权限目录完全分离，不生成设置项、按钮或用户可见说明，也不进入权限组导出和模型可见工具描述；命中时仅返回不揭示内部规则的最小不可用结果。详细规则只保留在受保护实现与内部验收材料中。
- 主 Agent 在所有内置、自定义和临时提升状态下始终只能使用读取类模型工具（ADR-0021）。本地会话控制器创建具体次级 Agent，并把当前 profile 及会话覆盖作为其次级权限上限；次级 Agent 只能向三级 Agent 分发相等或更窄的三态权限、资源范围和工具子集。
- 公开权限 `agent.communication-delegate` 控制直属上级是否可把直属低一级 Agent 的限定通信句柄授权给具体同级 Agent。该 grant 不可转授权，并在投递前复检身份关系、任务范围、profile revision、到期与撤销状态。
- 认证用户可在当前会话临时提升公开权限，默认作用于全部现有及后续次级 Agent，也可限定具体次级 Agent。提升不改基础 profile，会话关闭、到期、撤销或 profile revision 变化时失效；Agent 回收额外撤销个体覆盖。关闭会话默认导出基础 profile 加会话级覆盖，也可分别导出个体有效配置；导出不包含会话、Agent、nonce、一次性许可或内部字段。

## 7. 任务链持久化

- 位置：`.astarray/missions/<missionId>/task-chain.json`（ADR-0004）。
- 格式：版本化 JSON，含 `schema_version` 与单调递增 `revision`；临时文件 + flush + 同目录原子替换 + 备份恢复。
- 损坏文件进入 recovery 流程，不得静默覆盖。
- 任务链文件是任务状态的唯一事实源（可恢复、可审计、主 Agent 问答进度时读取）。
- 这里的“唯一事实源”仅限项目任务状态。Agent 跨项目待办和发布者优先级的事实源是 §5.1 的 Agent 待办任务偏序集。

## 8. 记忆、缓存与指标

- 主 Agent 只在自己的记忆域保存会话与任务概要；次级终态结果进入独立报告索引，后续用户对话按需读取，不自动并入主 Agent 记忆。三级工作态在本个体存档完成 handoff 后释放；Ponder 不落盘。
- 缓存、读取回执、循环预算、消息视图和上下文预算均以完整 `agentInstanceId` 分区；同级 Agent 使用相同任务、模型或显示名时也不能共用命名空间。
- 长期记忆写入遵循 Assist 权限门禁。
- 缓存：仅缓存确定性且无副作用的调用（ADR-0005）；v0.1 不实现语义缓存；缓存键包含 Provider、模型、模式、输入、系统提示词哈希、工具子集哈希、上下文摘要哈希和相关文件指纹。
- 指标：调用数、token、缓存状态（hit/miss/bypass/stale_reject）、峰值并发、消息延迟；估算 token 标记 `estimated`。

## 9. 恢复与安全

- 崩溃恢复覆盖：task chain 更新中断、投递后 ack 前崩溃、反馈进程崩溃/孤儿、journal 损坏。
- 非幂等副作用无法确认成功时进入 `blocked`，不得盲目重试。
- 安全边界：路径穿越、符号链接逃逸、ANSI/OSC 注入清洗、secret 脱敏、无限 tool loop 防护。

### 9.1 明确完成与早停恢复

- 模型完成任务时必须返回结构化 `ASTARRAY_TASK_COMPLETION_V1` 控制事件；文本兼容格式只在最终独立末行有效。
- 本地 `LocalCompletionVerifier` 核对事件身份/revision、任务节点、产物、验收证据、未决调用和阻塞状态。完成标识不能替代本地验收。
- 本地 `AgentRunWatchdog` 定期观察请求活性、流式进展、工具状态、任务 revision、完成事件和结束原因。输出结束但本地状态未完成时，从原子检查点有界续跑。
- 默认 5 秒检查、90 秒无进展、5 秒完成事件宽限、最多 3 次自动续跑；均使用带单位的配置名。活跃请求/长工具不会并发续跑，取消、用户输入、明确拒绝和非幂等不确定结果不会机械重试（ADR-0015）。

### 9.2 事实验证与用户裁决

- 本地 `LocalRigorPolicyEngine` 标记高严谨性任务；法律、医疗、财务、安全、破坏性操作、权限、发布和时效性事实默认属于高严谨性，模型只能上调不能下调。
- 高严谨性任务强制调用受控 `factVerification`，证据权重为“资料搜索依据 > 本地实验验证 > 纯推理验证”。Ponder 的搜索仅经专用只读代理，不能获得通用网络能力。
- 工具生成按主张组织的 `EvidenceBundle`，包含来源、取得时间、实验环境、冲突、覆盖和局限。本地完成验收器检查是否完成验证流程。
- 所有证据都只是辅助资料。工具不得返回最终 `qualified/safe/pass` 判定，UI 必须把证据关系与用户最终判断分开（ADR-0016）。

### 9.3 反自指与活锁

- 文件读取按具体 `agentInstanceId + taskExecutionId + 规范资源身份 + 操作/范围/参数` 建立读取回执；同一来源在默认 30 秒内重复读取未变化且已覆盖的内容时，本地拒绝正文重读并返回回执和剩余等待时间。
- 文件、网页、工具输出和存档中的调用文字默认是不受信数据，不能仅因其中写着“再次读取/调用工具”而触发能力。
- 本地循环守卫检测工具/资源 A→B→A、自环、Agent 回派乒乓、搜索换词和无进展重试；相同在途调用单飞合并，默认连续 3 次无进展后暂停路径。
- include/redirect 设置深度、节点与扇出上限；等待期间不持锁。真实文件变化、用户新信息或新证据属于进展，但不清除任务级总预算（ADR-0017）。

### 9.4 工具内破坏性变更备份

- 删除资源、删除部分文字/字段、替换、截断和任何覆盖属于破坏性变更（ADR-0009）。
- 自动创建备份由具体执行工具内部完成，不作为一次模型规划步骤，也不自动把备份内容注入模型提示词、工具输出或反馈消息。
- 工具先把目标完整 pre-image 写入内容寻址、追加写的受保护备份库并持久化清单；成功后才能修改目标。
- 备份后、变更前必须重新校验目标指纹，防止 TOCTOU。指纹变化时中止并重新开始，不得用已过期备份继续覆盖。
- 备份库位于工作区状态目录的受保护分区，例如 `.astarray/backups/objects/` 与 `.astarray/backups/manifests/`；普通文件工具无直接权限。
- 恢复当前版本前也先备份当前目标，使恢复操作本身可撤销。
- `backupVault` 受控工具提供列出、读取和恢复；底层对象路径与恢复密钥不暴露。恢复属于覆盖，恢复前先备份当前目标。
- `deleteBackup` 是独立特权工具与自动 pre-image 规则的唯一递归例外。协同模式逐次警告用户并暂停发起 Agent，用户精确授权后继续；放权模式不提示但写入不可删除的高查阅优先级审计日志；思索模式禁止。
- 删除采用短锁两阶段隔离：锁内验证 revision 与引用关系并移入 quarantine，释放锁后清理。授权等待期间不持有锁；处于 `awaiting-user-authorization` 的 Agent 通过专用控制通道接收匹配请求 ID 的决定，避免死锁。

## 12. 主对话独占、次级直投与四级 Agent（ADR-0025）

- 单会话仍只有一个用户连续对话主 Agent。用户默认把消息交给主 Agent；小型、明确且无需方案讨论的任务可由界面推荐直投具体次级 Agent，直投只绕过主 Agent模型的重复规划，不建立用户—次级独立对话。
- 次级 Agent默认用 `SECONDARY_USER_FACING_SUMMARY_V1` 汇总三级/四级结果、风险、进度和用户裁决事项。主 Agent读取摘要后面向用户解释，不能更改事实或丢失来源。
- 次级 Agent通过只读侦察型三级 Agent获取项目细节，接收 `PROJECT_CONTEXT_DIGEST_V1` 而不是项目全文；侦察原始资料保存在具体 Agent个体域。
- 次级 Agent任命不同的实现、测试和验收三级 Agent，作者不得自验；次级根据提交哈希、测试、验收和人工门禁判定返修、等待或合并。
- 三级 Agent可为严格子链创建四级 Agent。四级不能创建第五级，权限/工具/上下文/范围均为三级子集。三级只可在自己的任务分支内整合直属四级贡献；项目级最终集成仍由次级 Agent完成。
- 主、次级、三级、四级都按不可复用 `agentInstanceId` 隔离记忆、缓存、读取回执、mailbox、工作存档和模型上下文。

## 13. 模型/Provider 策略与任务类型预设（ADR-0026）

- `ModelProviderCatalog` 使用稳定 Provider/模型公开 ID 和 revision；凭据只保存在受保护控制面。
- 每个 Agent独立解析模型策略。用户可为战略主 Agent、项目次级、项目侦察、实现、测试、验收和四级子任务配置任意长度允许列表，并选择固定、顺序 fallback、列表内自动选择或逐次手选。
- `TaskAgentPreset` 支持办公文档、前端、编码、debug、测试、验收、侦察、绘图和用户自定义任务类型，不设置预设数量上限。
- 策略优先级为任务显式指定、具体 Agent会话覆盖、任务类型预设、用途列表、层级默认、会话默认；任何层级都不能突破全局禁用、数据出境和权限边界。
- 模型切换只在安全检查点发生，生成 `AGENT_MODEL_SWITCH_V1`；身份、记忆、任务、工具、权限和 Git责任保持不变。允许列表耗尽时阻塞，不得静默扩展。
- TUI、Headless CLI 和 GUI共用认证设置控制器，使用搜索、分页或虚拟列表承载大规模模型和预设配置。

## 14. 阶段性“工匠”三级 Agent（ADR-0027）

- 工匠是休眠的三级预设，只用已有已授权基础工具定制重复工作流；会话开始时不实例化、不发送完整说明，避免占用次级 Agent上下文。
- 本地阶段控制器按活跃时长、已验收任务链、版本化里程碑、项目记忆公开索引规模和重复工作流指纹决定何时发送 `CRAFTSMAN_PRESET_AVAILABLE_V1`；不让模型判断阶段。
- 提供较早、均衡、保守模板，并允许用户配置不限数量的 `CraftsmanStageTriggerProfile`、`any/all` 阈值、冷却、目标次级、提示词和披露动作。
- 自动安排提示只能生成优先级层级 1 或以下的提案；不能扩大工具/权限、批准安装、替代人工验收或越过次级 Git 合并门禁。
- 工匠产物使用 `CRAFTSMAN_WORKFLOW_BUNDLE_V1`，由不同测试/验收 Agent验证；跨 Agent复用只传递显式选择的不可变 revision 附件。
