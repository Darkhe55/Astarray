## 2. 逐项核对结论

| 测试断言的安全要素 | 与新规则关系 | 结论 |
| --- | --- | --- |
| 安装分类（包管理器/系统包/克隆/生命周期脚本/fail-closed） | 不受范围细分影响 | **保留** |
| 已有资源询问、验证失败回退、无资源才进入开关 | ADR-0019 保留要素 | **保留** |
| 独立开关默认关闭、开启才可创建请求、关闭立即失效 | 保留要素（GOV-02b 亦要求） | **保留** |
| 精确计划绑定、一次性 nonce、revision/模式/过期复检、消费 | 保留要素 | **保留** |
| deny 不产生授权、回执无效拒绝、双 Agent/双任务隔离 | 安全要素 | **保留** |
| 非安装调用直接放行 | 不影响 | **保留** |
| `installation-gate-guard` 非 Assist 模式拒绝安装 | 与 ADR-0039 S5 放权行「开关开启后按配置 allow」存在**表述差异** | **记录为待接线项**（见 §3） |

**结论**：旧安装门禁测试断言的是 ADR-0019 的**保留安全要素**与当前不可达路径的既有语义，
与 GOV-02b 的范围细分不冲突；**无需修订测试预期**（GOV-01 冲突清单中"待修订"一项据此关闭）。

## 3. 待接线项（冻结，随安装类工具引入时处理）

- 旧 `InstallationGateGuard` 对非 Assist 模式一律拒绝安装（`安装尝试需经 Assist 门禁`），
  而 ADR-0039 S5 行规定放权模式在开关开启后按已配置决策 allow/ask。**当前无安装类工具，路径不可达**。
- 冻结要求：引入安装/外部软件/进程执行工具时，执行链必须（a）显式映射操作类型并提供本地范围证据（GOV-02c §31）；
  （b）S1 受控安装消费受信范围授权（上级批准）而不是一律用户 allow-once；（c）放权模式不得被旧守卫无条件拒绝，
  必须以范围矩阵决策为准（可 deny/ask）；（d）独立开关与参数绑定在任何模式都保持。
- 不得通过简单删除"非 Assist 拒绝"分支来放宽；必须与范围门禁决策合并后再执行。
