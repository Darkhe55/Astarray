3. 安装验收脚本 `scripts/verify-entry-runtime-selection.mjs` 已改为**只用公共写入面**造引用
   （`credential-set` → `register` → `list` → `doctor --provider`），不再手工写凭据文件；随后用同一引用驱动

## 17. 状态更新（2026-10-01 第九次加更：完成门禁离线反例 + 单次真实验收脚本就绪）

### 17.1 卡死原因（已修，`fe9684c`）

`InteractivePermissionAskDecisionPort.readLine()` 读 stdin **无上限**：`echo allow-once |` 只有一行，
第二次询问时管道已 EOF，Promise 永不结算 → CLI 永久挂起（实测 16 分钟，浪费 1 次真实额度）。
现为有界等待（默认 120s，可注入），超时 fail-closed 返回 null 且**不授权、不 unblock**。
反例：`tests/tui/integration/permission-ask-timeout.test.ts` 5/5（含"管道 EOF / 第二次裁决"）。

### 17.2 三类离线反例（全绿）

`tests/core/integration/completion-gate-counterexamples.test.ts` 7/7：
工具选错后声称完成 → 非 done 且无产物；未解决的写失败后声称完成 → 非 done；
验收门禁未通过/组合缺失 → `LocalCompletionVerifier` 拒绝；**全部条件满足（含失败已解决）→ 必须接受**。

**语义（按用户 2026-10-01 措辞）**：拦「未解决的必需操作失败或验收缺失」，**不拦**失败已解决后的正常完成。

**顺带查清**：写工具失败后 worker **不再给模型第二轮机会**（实测该 mission 仅 1 次模型调用），
直接以"完成声明与本地工具结果不一致"结案；模型选错工具即本轮终止（候选：是否有界重试，本检查点不改）。
