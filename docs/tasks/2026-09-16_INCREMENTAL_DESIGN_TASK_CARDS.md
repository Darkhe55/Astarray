## 2. AUTH-SCOPE：按模式、实际作用范围及上级裁决授权

### 设计契约

- 中文名仍为思索模式、协同模式、放权模式。主 Agent 的只读角色不变；实际授权由本地控制面和有权裁决的次级执行层处理，不给主 Agent 添加写工具。
- 放权模式：没有用户的显式干预时，按上级 Agent 及当前有效权限设置处理；可配置项默认 allow，可自动形成允许回执，不要求额外模型往返。用户设置的 deny 不得被上级覆盖；ask 使用已配置的裁决路由，不因用户离线当作其同意。
- 三级/四级请求沿直属上级处理，需要扩大委派范围时升至有权处理的次级；权限不得超出该次级当前有效上限。上报应有界、去重且不可循环回派。
- 协同模式：作用范围已验证且局限于已登记项目根的操作，默认由有权上级批准后执行；可按设置形成自动批准回执。跨项目根、项目外副作用、外部软件控制以及作用范围不明确的操作，要求认证用户对精确操作授权。
- 项目路径不以 cwd、路径字符串前缀或命令自述判断。执行前解析真实路径、链接/junction、目标文件、子进程、安装脚本、缓存/配置/环境写入等副作用；未知范围归人工裁决。
- 调用已登记的项目构建/测试工具不因运行时二进制位于项目外就一概归为外部软件控制；必须有可验证的执行能力和副作用范围。启动、自动化控制第三方应用另列外部软件权限，协同模式默认人工批准。
- 项目内 clone、依赖或环境操作只有在真实影响范围受控且当前权限允许时，才可由上级批准；全局安装、项目外缓存写入、全局环境变更或未知安装脚本不能借项目内 cwd 放行。
- 不因本设计放宽远端发布、备份删除等未被本次明确替代的专用授权流程。准确性检查开关也不授予操作权限。

### 与旧安装规则的迁移

旧规则是“协同模式任意安装均逐次取得人工授权”。新规则拟调整为“先识别实际作用范围，再确定上级或人工裁决者”。保留安装功能独立开关、已有资源询问/选择流程、精确安装参数绑定及执行前复检；安装开关关闭仍拒绝，不能以自动批准代替开关。

若任务所需资源尚不明确，先询问用户是否已有资源，不自动开始安装。用户已提供明确资源选择或安装指导时，本次绑定该选择，不反复询问同一问题；这不是无限期或批量安装许可。所有安装脚本和额外项目外副作用必须纳入当前请求，不能藏在测试或初始化中。

规则迁移须更新旧矩阵、测试和文档，不保留相互矛盾的同时生效描述。权限等待释放锁，仅暂停依赖该授权的节点。规则变更不追认旧请求；在途操作在安全检查点对账后使用新 revision。

## 4. READ-FORMAT：内置多格式读取视图

readFile 增加 shouldIncludeComments 和 shouldIncludeImports，可选且默认 true。返回视图不更改源文件，不执行其代码或加载导入目标；统一保留源 revision/hash、原行定位、省略类型及策略版本。

| 内置格式族 | 必交付范围与规则 |
|---|---|
| C 系 | C/C++、Objective-C、C#、Java；注释、头文件/导入；普通 using、宏与预处理控制不得误删 |
| Python | py/pyi；注释、import/from；文档字符串视为语言内容而非普通注释，默认保留 |
| Rust | rs；嵌套注释、文档注释、use/extern crate；保留属性、宏和字符串 |
| 前端 | JS/TS/JSX/TSX、HTML、Vue、Svelte、CSS/SCSS/Less；混合文件按区段分派策略 |
| LaTeX | tex/sty/cls；百分号注释和静态包/文件引入；正确处理转义及逐字环境；不执行宏 |
| 配置/文档 | JSON/JSONC、YAML、TOML、Markdown、纯文本；各自合法注释，无导入概念返回不适用 |
| 其他常用语言 | Go、Shell、SQL；明确方言/能力范围，动态加载和执行语句不冒充静态导入 |

1. 使用轻量策略注册表，按后缀、特定文件名和明确格式覆盖选择；后缀不足以确定方言时如实处理。动态导入/包含及无法可靠判定的构造保留并标记局限。
2. 采用语言感知扫描/解析，不用通用正则跨语言删除内容。首检查点冻结每类格式的导入范围和失败语义。
3. 不支持、解析失败或能力不足时返回明确不可过滤状态，不静默声称成功。允许用户显式选择原文；不修改文件以“修复解析”。
4. Python 文档字符串、Rust 属性、C 宏等有语义内容不得当注释丢弃；重要注释省略时提示视图不完整，准备修改时按需补读原文。
5. 过滤结果不是可直接覆盖写回的完整源码。敏感检查先于返回视图，过滤不能隐藏违规内容以绕过检查。
6. 缓存键纳入文件版本、视图参数、范围和策略版本；允许合法补读被省略部分，反复切换参数不能重置总调用预算。不同视图仍算同一个文件。
7. npm 包内包含声明支持的策略，按需加载；不运行到某语言才自动联网安装。评估包体积、解析耗时、峰值内存和模型返回量；不承诺必然减少磁盘 I/O。

| 检查点 | 实施范围 | 必需验收 |
|---|---|---|
| READ-FORMAT-01 | 核对已有解析依赖；策略接口、格式能力矩阵和公共回执 | 冻结四种参数组合、unsupported/parse-error 语义；新增依赖先遵守当时有效安装规则 |
| READ-FORMAT-02 | C 系、Python、Rust 策略 | 每种承诺语言有真实夹具：字符串伪注释、多行导入、嵌套/逐字字符串、不完整源码、同行代码 |
| READ-FORMAT-03 | 前端及混合格式策略 | 模板/脚本/样式区段、JSX、URL、嵌入代码及副作用导入不误删 |
| READ-FORMAT-04 | LaTeX、配置文档和其他语言 | 转义百分号、verbatim、Markdown 围栏、Shell heredoc、方言不支持等边界 |
| READ-FORMAT-05 | 读取缓存、防重复读取、产品入口和 tarball | 过滤后按需补读可用；跨 Agent 隔离；未支持格式不虚报；安装包离线可用并有资源测量 |

单个语言族工作过大可在其内部继续拆检查点，不缩减本卡完成范围。

## 5. GIT-PRESERVE：远端同步失败后的本地保全

这是本地快照的正式定义。它不是远端同步成功、不是单纯目录清单、不是仅建立原仓库内的备份引用，也不替代变更前自动备份。

- 推送出现网络失败时立即生成本地保全点，不等待五次重试耗尽。无远端或其他同步失败也记录原因并保全；认证失败、冲突拒绝与网络失败分别展示，不强推、不自动解决远端分歧。
- 每阶段上传最多重试五次，无远端依赖任务可继续；下一阶段再尝试累计提交。同一提交和工作树指纹复用已验证快照，不因重试重复全量复制。
- 保存目标分支/引用和恢复需要的 Git 对象、暂存与未暂存状态、范围内未跟踪文件、版本化清单、哈希和完整性结果。在工作树之外的受保护目录存放独立可恢复数据，排除备份自身，避免递归。
- 不改动用户 HEAD、index 或工作树，不为快照自动 git add/commit。Git 历史归档与工作树快照分别验证；只有 bundle/提交不足以覆盖脏工作树。
- 默认不收集无关依赖缓存及构建产物，明确排除清单；已跟踪内容不能因忽略规则被静默遗漏。LFS、子模块、浅克隆、尚无提交的仓库分别识别，缺对象或仅有指针不得宣称完整可恢复。
- 由工具本地执行，敏感备份不暴露给模型、日志或普通导出；复用受控备份访问/恢复。权限不足或磁盘不足记录失败，不伪造成功。
- 并发修改按快照代次进行一致性检查；必要时短时协调或有界重试，始终不能把缺失文件和读取失败静默当成空数据。临时产物原子发布，不完整快照不标 ready。
- 默认恢复到新目录/隔离 worktree，校验文件及暂存状态，不覆盖当前人工工作区。备份删除继续走专用流程，不自动淘汰旧快照。
- 本机保全不能抵御整个磁盘损坏；跨设备灾备不纳入本卡。快照失败暂停依赖该保全点的危险操作，不必冻结整个项目。

| 检查点 | 实施范围 | 必需验收 |
|---|---|---|
| GIT-PRESERVE-01 | 审计并复用恢复点服务；冻结保全清单、范围和状态 | 分离 remote-sync 与 local-preservation 状态；列出 LFS/子模块等支持或受限策略 |
| GIT-PRESERVE-02 | 同步失败接线、独立对象归档、脏工作树/index 快照、原子清单 | 网络故障/缺远端触发；二进制、未跟踪、已暂存与未暂存并存、删除/重命名、无提交仓库 |
| GIT-PRESERVE-03 | 崩溃恢复与独立恢复演练、产品状态入口 | 原仓库不可用仍可恢复已声明范围；并发改写、缺对象、磁盘不足不能虚报；重试不重复快照 |

现有 git-recovery-point-service 可以复用但须先审计，不以“已有恢复点”代替本卡验收。

- 验收：长任务中途追加、撤销旧要求、新建无关任务、重复指导及旧完成声明均有产品入口反例。

## 7. 实施顺序、测试与交付

推荐：当前检查点收口 → AUTH-SCOPE-01 → ACCURACY-01 → 完成 AUTH-SCOPE → 完成 ACCURACY → GIT-PRESERVE → READ-FORMAT。GUIDE 增量在其所属模块空闲且相关权限/版本契约确定后接入；不要求无关读取策略等待 Git 功能，但共享文件不得双写。

每次只领取一个检查点；预计超过三小时则再拆分。开始编码前完整读取仓库四份治理文档及相关当前 ADR，登记旧/新规则冲突。生产变量完整可读，布尔使用 is/has/can/should，时间变量带单位。

检查点先写反例，再实现并跑定向测试与 npm run check；安全/状态机改动补专项覆盖率。交付需 npm pack 及 tarball 隔离消费者验证，不用内部类单测代替实际入口。不要安装缺失依赖或执行隐式下载来绕过当前有效授权。

每项证据记录真实命令、退出码、平台、输入规模、commit/dirty 基线、产物版本与未满足条件。未经运行的场景标未验证；本文件不授予编码 Agent 自验收权限。
