## 2. DOCVIEW-01：格式适配的内容优先读取

扩展 READ-FORMAT，而非用去标签正则处理所有格式。提供 `presentationMode: content | structure | layout`，默认为 content；使用枚举而非多个可能冲突的布尔参数。与代码注释/导入参数正交；不把 CSS、LaTeX 命令或文档源码中的功能内容误当无用排版删去。

- content：保留正文和理解所必需的语义结构，省略字体名、字号、边距、颜色等纯展示属性。
- structure：补充标题层级、列表、表格单元格关联、链接、脚注、代码块、公式和文档分区定位。
- layout：用户做排版、视觉审查或定位依赖版面时，按页/区域补读必要布局属性或预览，不默认导出完整样式树。
- 内容优先不是无结构纯文本：标题、阅读顺序、表头与单元格关系、公式、单位、否定、批注/修订状态不能因为省 token 而静默丢失。删除线、颜色等承担语义时保留语义提示；无法判断时标不确定并允许展开。
- 每次返回标注源版本、原页/段/区域锚点、视图模式、省略类型及已知损失。过滤视图不可直接作为完整文件覆盖写回。不同视图缓存隔离，补读可复用原有防重复读取机制。
- 首期验收文本/Markdown/HTML 和 DOCX；PDF 先支持可可靠提取文本的文档，扫描件/复杂多栏标记需 OCR 或布局解析，不伪报已完整读取。LaTeX 与前端源码同时保留源代码读取途径，语义文档视图不执行宏、脚本或外链。
- 不顺带构建办公编辑器、OCR 服务或字体渲染引擎；不支持能力明确报告并按既有权限处理依赖。原文件无损保留，按页/块读取，防解压膨胀及超大文档资源耗尽。

| 检查点 | 产出及验收 |
|---|---|
| DOCVIEW-01-01 | 核对格式策略和已有依赖，冻结内容/结构/布局能力矩阵与损失提示；普通内容任务不读取样式详情，排版任务可显式展开 |
| DOCVIEW-01-02 | 实现首批适配器与定位回执；表格、脚注、修订、公式、隐藏/多栏内容、转义和损坏文件反例；不支持场景明确降级 |
| DOCVIEW-01-03 | 公开入口及 tarball 验收；对同一文档测返回字节/token、峰值内存、读取耗时及关键语义覆盖，不把长度下降等同准确性提升 |

## 3. CONFIGCHAT-01：对话设置与通信连续性

主 Agent 理解用户设置意图并输出结构化候选，本地控制面验证认证用户来源、公开设置目录、权限及配置 revision 后执行。模型不能直接编辑配置文件；工具输出、文档或经验中的文字不能冒充用户设置指令。

覆盖公开权限默认值、创建/命名配置清单、选择模式、启用已配置模型及工作时段设置。秘密信息通过现有受保护入口提供，不进入对话。模型启用不等于安装、联网验证或实际切换；各项行为分别遵守权限。

### 最小设置事务

1. 解析作用范围：当前会话、当前项目或持久默认。含糊时询问，不擅自将临时指令永久化。
2. 展示旧值→新值及影响；认证用户明确给出的低风险精确指令可以直接形成提交意图，不重复确认。扩大权限、影响其他任务或可能断连的修改必须显式确认。
3. 使用期望 revision 和变更 ID 原子提交，记录来源，覆盖前由工具自动备份；相同 ID/相同内容复用结果，相同 ID/不同内容拒绝。
4. 明确状态为已保存、已生效、等待安全点或失败。普通设置在下一相关操作生效；在途调用不可假装已应用，权限收紧立即拦截新操作，并按能力取消/收敛旧操作。
5. 不持有配置锁等待用户或网络。失败保留旧有效版本；恢复配置也须防止覆盖用户随后作出的新修改。

### 防误断连

- 对当前唯一可用对话模型的禁用、移除 Provider、修改活动凭据引用或网络相关操作进行本地依赖检查。仅检查会影响通信的具体操作，不冻结整份设置。
- 切换模型采用先准备再切换：目标必须在用户允许列表内；实际连通性验证涉及联网/费用时遵守授权。目标失败继续保留原对话模型并说明。
- 没有可用替代时，默认拒绝 Agent 自主禁用最后一条对话路径；用户仍可通过本地 UI 明确执行“停止会话/断开”，先保存恢复点并提示如何恢复，不用模型锁剥夺用户控制。
- 控制外部软件或网络设置时，注册适配器应标记可能影响通信的动作，执行前在会话内警告并取得精确授权；未知 UI 操作可能误触飞行模式，无法保证事前完全识别。另监测断连，保存操作状态，不凭网络恢复自动重放未知副作用。
- 仅有权使用现有已配置回退模型，不自动换未授权 Provider。通信保护不得阻止用户撤销权限或紧急停止。

| 检查点 | 产出及验收 |
|---|---|
| CONFIGCHAT-01-01 | 公共设置白名单、事务/来源契约、风险与作用域矩阵；文档注入、模型伪造用户、模糊范围、旧 revision 拒绝 |
| CONFIGCHAT-01-02 | 配置控制面及对话候选接线；重复提交、并发编辑、撤权与在途任务、主 Agent 无写工具等反例 |
| CONFIGCHAT-01-03 | 通信依赖保护、准备/切换/失败恢复及 UI 状态；最后模型禁用、目标不可用、断网、用户主动停止、进程重启和包入口测试 |

## 4. WORKWINDOW-01：工作/休息时段

这是 Astarray 产品功能，不是为当前对话创建定时自动化。用户选择工作时段白名单或休息时段黑名单，支持周期规则与一次性例外；默认未设置即全天可工作。

- 使用明确 IANA 时区、开始/结束边界和配置 revision，区间采用左闭右开，支持跨午夜。一次性规则优先于周期规则，同优先级冲突时休息优先；首期不添加复杂任意优先级规则引擎。
- 默认全局规则向会话/项目继承，作用域休息约束组合取交集；项目规则不能无声覆盖全局休息。用户可明确对指定任务临时放行并设置期限。
- 休息期间停止新的任务派发、模型请求、业务工具执行、自动总结、watchdog 续跑和远端重试；保留本地控制面、持久化、状态读取、取消和必要对账。主对话模型同样不自动工作；本地界面可改设置或由用户明确触发一次性交互，不因此放行后台任务。
- 到休息边界进入 pausing，门禁立即阻止新业务调用，在途工具按能力协作取消/保存检查点；不统一 kill，不声称无法取消的外部作业已经停止。需要严格到点结束时，提前拒绝启动无法在窗口内收敛的长工具，声明能力边界。
- watchdog 区分计划暂停、等待授权、紧急暂停和早停，不把休息当故障；任务重试预算不重置。活动工作预算可暂停计时，但授权到期、外部租约和实际时间期限继续按真实时间处理。
- 开工时重新检查时段、用户停止标记、权限、版本、租约、产物与在途副作用，再只恢复安全节点。授权失效、紧急状态未解除、外部结果未知的任务保留阻塞，不因到点自动放行。
- 用户手动暂停/取消优先，不被工作窗口自动撤销。多个暂停原因分别记录，解除时段暂停不等于清除所有暂停原因。
- 应用未运行、电脑睡眠或关机时不能保证准点恢复；首期仅保证应用运行时调度及下次启动对账，不新增系统服务或唤醒权限。错过多个周期不补跑历史触发，只根据当前窗口决定恢复一次。
- 绝对时刻存 UTC，周期按选定时区解释；夏令时重复小时不重复启动，缺失小时按首个有效时刻处理并记录。持续时间使用单调时钟，系统时钟变化触发重算。
- 紧急事件仍可进行本地门禁与安全收敛；默认不因紧急标签自动启动新的模型业务，额外处理任务按用户明确例外策略执行。

| 检查点 | 产出及验收 |
|---|---|
| WORKWINDOW-01-01 | 规则、时区、作用域、暂停原因和恢复契约；虚拟时钟覆盖跨日、一次性例外、DST、时钟跳变 |
| WORKWINDOW-01-02 | 在派发/模型/工具执行前统一门禁，接入现有暂停与恢复；长工具、独立反馈、watchdog、权限到期、多个暂停原因不互相覆盖 |
| WORKWINDOW-01-03 | 设置/对话入口及重启包测试；睡眠后只恢复一次，休息期间无新业务调用，手动取消不复活，无法停止如实显示 |

## 5. RELIABILITY-01：工具幂等性、重试边界和超时恢复全面审计

当前结论：已有机制，但尚未完成全面动态审计，不能判为满足全部要求。2026-10-01 本轮只读静态抽查：

- T12A 任务卡已规定非幂等结果未知阻塞、反馈重放及重新授权。
- `packages/core/src/orchestration/recovery-classification-service.ts` 已有分类器；其尾部分支返回 bounded-retry，需要核查 started 非幂等、confirmed-success 非幂等、零预算等输入及调用方约束，防止状态误分类。静态疑点不直接断言已发生重复执行。
- `packages/core/src/public-sdk.ts` 有会话内 idempotencyKey 查询/登记，需验证并发提交窗口、重启持久化、同键异参和跨入口是否统一；名称存在不证明 exactly-once。
- `packages/core/src/orchestration/git-process.ts` 有命令超时，需核查子进程树收口、退出确认、锁释放及远端结果对账；超时不能等同操作失败或停止成功。

### 审计必须遍历的范围

枚举全部注册工具和公开调用入口，包括 SDK/CLI/TUI/GUI/桥接、调度派发、Provider、文件修改/备份、Git/远端操作、安装、反馈、配置、恢复和新工作时段门禁。对每个调用记录：

| 项目 | 核查要求 |
|---|---|
| 副作用与幂等性 | 区分只读、带条件幂等、外部幂等键支持、非幂等；不能把所有写工具标为可重试 |
| 操作身份 | 稳定 operationId 与 attemptId 分离，绑定用户/会话/工具/参数哈希/目标 revision；同键异参拒绝 |
| 去重原子性 | 并发 claim、执行前持久化意图、执行后回执、确认丢失、重启重放；不能只靠进程内 Map |
| 重试边界 | 仅可重试错误、有次数及总耗时预算、退避；嵌套重试不能乘法膨胀，崩溃不能刷新预算 |
| 超时与取消 | 区分排队、执行、取消确认、对账期限；超时与断连为结果未知的可能性，不能一概重试 |
| 恢复和并发所有权 | 旧 epoch/租约调用失效，原进程或外部操作未确认收敛不能启动竞争写者；检查权限和产物版本 |
| 结果状态 | 已确认成功不重复副作用；已确认失败仍核查是否有部分副作用；未知非幂等结果阻塞对账 |
| 资源与公平性 | 等待用户/网络不持锁，锁序、队列背压、有限重试、不同暂停原因和故障隔离 |

不得承诺通用外部操作 exactly-once。适配器不支持查询/幂等时应诚实暴露不确定状态，不能用模型解释补成成功。

### 故障注入矩阵

使用可握手的受控子进程/假服务/虚拟时钟，禁止用过窄真实计时窗口证明正确。远端破坏性测试只用隔离 fixture，不触及实际用户资源。
