日期：2026-10-02。状态pending，设计布置，未实现/验收。用户要求三个功能；具体默认值与检查点为派生方案。首轮读取AGENTS.md指定治理文档及相关ADR，核对当前实现；当前检查点收口后由次级协调公共文件所有者，不能覆盖在途改动。

本卡关联PROJECT-01、CONFIGCHAT-01、HISTORY-01、CURATE-01、SMART-01与OBS。复用真实接线，不按历史done推断满足前驱；每轮一个检查点，超过三小时再拆分。

## 1. FOLDER-01：通过对话扩展项目文件夹

模型可根据用户任务提出“将额外文件夹纳入当前项目”的候选，不能自行赋权。认证用户通过独立授权卡明确批准后，本地控制面更新登记根集合/revision，再按有效权限执行。明确项目归属、读取/写入权限、子目录范围、有效期及撤销方式；不等于授权整个磁盘。

### 短而准确的授权交互

每个重要授权单独呈现，首期一张卡只处理一个文件夹及一项明确权限方案；不把多个路径、安装、执行命令和删除操作堆成“全部同意”。普通业务描述不能夹带授权。用户可以逐项批准/拒绝/稍后处理，不默认勾选，不因拒绝重复催促。

卡片固定展示：

- 请求：将哪个规范化绝对路径加入哪个项目；准确路径可复制/展开，不能只显示容易混淆的尾部名称。
- 原因：一两句说明当前任务为什么需要、拒绝会阻塞什么；无夸张警告或诱导措辞。
- 权限：只读或明确读写、是否含子目录、期限；不是“访问全部资源”等含糊措辞。
- 操作：批准这项、拒绝、查看详情。详细影响折叠，但关键范围和写入能力不得隐藏。

示例：“为读取本任务的公共素材，申请将 D:/Assets/ProjectA 加入项目A，只读，含子目录，仅本次会话有效。此操作不授予修改权限。”示例路径不代表默认授权位置。

权限含糊时先澄清，不默认读写或永久化；推荐只读、当前会话作为初始选择。明确用户请求仍需本地精确授权确认，模型转述不是签字。批量目录请求保留队列，逐项裁决，不连续弹窗抢占用户。

### 与项目隔离衔接

- 检查真实路径、链接/junction、重叠根、父目录包含其他项目、网络路径及登记revision；原始路径与解析目标不一致时清楚提示。
- 已属于其他项目的目录不得通过“纳入本项目”绕过PROJECT借阅：提供只读/副本导入流程；不自动改归属或授予来源写权限。项目迁移另立显式流程，不在本卡实现。
- 授权绑定用户、项目、路径/范围、权限、有效期和revision，控制面原子更新；执行前复检，变更时失效相关旧许可/缓存。正在执行的工具按安全点对账，不能假装已即时撤销已发生副作用。
- 模型仍受当前模式/角色权限上限；主Agent只读，不能通过新增目录获得写工具。目录许可也不代替安装、外部软件或具体操作授权。
- 文件系统无法提供所需隔离时如实降级/拒绝，不能仅靠提示词限制shell。根集合更新前自动备份配置，重放同请求不重复登记，同ID异参拒绝。

| 检查点 | 产出及验收 |
|---|---|
| FOLDER-01-01 | 对话候选、短授权卡、作用域/归属契约；含糊路径、其他项目目录、父目录扩大范围反例 |
| FOLDER-01-02 | 根登记事务、执行前复检、撤销/重启及缓存失效；未批准零新增权限、并发revision冲突正确处理 |
| FOLDER-01-03 | SDK/CLI/TUI/GUI共用入口与包验收；人工能分辨路径/读写/期限，批量请求逐项决策且不打断正常对话 |

## 2. SECRETARY-01：实验性同级秘书Agent

默认关闭，仅认证用户显式开启。秘书与主Agent同级，不是所有主Agent的上级；使用独立不可复用agentInstanceId、记忆、模型配置和预算。本身不编码、不验收、不执行项目工具或替项目调度者合并Git。

工作区严格限定为客户端专用数据目录中的秘书域，不是整个用户目录或客户端安装程序目录。运行时解析并登记，不让模型自行指定；不通过扩展根获取项目文件权限。其持久记忆由本地控制面处理，模型工具保持只读报告查询/状态查询，不因秘书角色获得任意文件写入。

### 两种用户工作方式

- 项目模式：分别打开项目对话，项目主Agent持续负责该项目。
- 汇总模式：秘书窗口展示获准项目的安排、完成情况、未完成项和待决策事项；可从每项跳转项目/证据。模式切换不复制历史、不启动重复任务、不改变项目归属。
- 项目报告由控制面生成/选择带来源、项目、revision、时间和哈希的最小附件/状态快照；秘书不能直接读项目目录或其他Agent私人存档。用户先选择纳入汇总的项目和可见类别。
- 默认普通后台报告只入档，不唤醒秘书或项目主Agent模型；用户查询、明确授权的简报或正常引导才触发解释。
- 用户通过秘书下达项目任务时，秘书只生成带目标项目的转交提案，控制面保留原始用户来源并路由给项目主Agent/任务入口。目标不明确时询问，不一条指令广播所有项目。秘书派生建议仍是Agent来源，不能冒充用户层级0。
- 路由带原消息ID/幂等ID/关联回执，显示待转交、已接收、已派发及实际完成，不把秘书回复视为项目已执行。防同级互转循环，必要时升级用户，不互相重复转派。
- 待裁决事项显示具体项目、操作和有效版本；秘书可帮助解释，实际批准走原授权卡，不能用一句“全部处理”覆盖各项目的重要授权。
- 项目离线/报告过期时显示最后更新时间和未知状态，不推测完成。汇总不改变项目权限，也不暗中请求跨项目导出。

### 次日首次启动与历史收拢

- 用户设置时区和 `minimumClientClosedDurationMinutes`；推荐初值360分钟，可调整。判定同时满足跨本地日历日、离线超过阈值和该日未处理；单纯跨午夜短重启不触发。
- 客户端记录关闭/最后心跳/启动及日期处理回执。崩溃导致关闭时刻不确定时标记估计，保守避免重复模型整理；多窗口同时启动须原子领取同日任务。
- 首期只在真实启动时判定，不额外启动系统唤醒服务；长开客户端跨日不自动假装发生首次启动。时钟回拨、DST、旅行改时区用明确日历策略和去重记录，不反复触发。
- 触发后客户端可立即把默认消息视图收拢到“今天”；昨天及以前仍在本地历史中，提供“查看全部历史”、日期跳转和搜索，显示旧消息已收拢而非删除。待决策和未完成事项即使来自昨天也保持可见。
- 实际历史整理分类复用CURATE：首次启用前说明范围、模型/外发、预算、产物和频率并授权；重大变更再确认。秘书开关不替代梳理方案授权。未授权时仅本地调整显示并提供授权入口，不调用模型整理。
- 先基于权威状态显示可读概览，再按授权后台整理，不能阻塞启动/主对话。休息时段或预算不足时延期模型总结，展示已有状态，缺失不补写成事实。
- 整理只处理已提交游标并保存分类/索引，不删原文；秘书只整理自己的获准汇总历史，项目原始记忆仍由各项目/个体负责。
- 提供快捷入口：“今日安排”“已完成”“未完成”“待我决定”。摘要带时间和项目来源，完成/待验收/待人工追认分开，用户可展开证据。
- 默认显示今天是可配置视图偏好，用户可选择总是显示全部或恢复上次位置；切换不影响保存，避免强迫用户改变阅读习惯。

## 3. ONBOARD-01：从工作习惯开始的使用引导

首次使用提示：“可以先聊聊你的工作习惯或常见流程，例如每天重复处理什么、哪些步骤最费时间，我可以帮你设计适合的自动化方案。”清楚说明先讨论方案，不因交谈自动执行、安装或开启实验功能。

- 首次提示可跳过，之后保留“聊聊我的工作流程”入口；不强制填写问卷，不要求提供私密工作内容。
- 适时提示采用本地可解释信号，例如用户完成阶段任务、主动咨询效率，或允许采集范围内发现重复工作；不为推荐而读取新项目/完整历史或额外调用模型。
- 默认同类提示至少间隔7天，可关闭；首次提示之后用户选择“不再提示”必须持久化生效。具体频率可在人工体验后调整，不能通过换文案绕过拒绝。
- 正在输入、授权裁决、错误恢复、紧急事件或任务高负载时不弹出；使用不抢焦点的轻提示，不和重要授权卡混排。
- 推荐方案说明输入、预期收益、所需权限/成本和停止方式，用户选择后才另走任务和授权流程。不保证自动化收益，不把话术当作启用实验功能的同意。
- 首期不建设行为画像平台，不默认遥测上传；提示触发/忽略状态仅存客户端必要元数据。

| 检查点 | 产出及验收 |
|---|---|
| ONBOARD-01-01 | 首次/适时提示触发、冷却和拒绝状态；跳过、不再提示、重启及迁移不反复弹出 |
| ONBOARD-01-02 | 项目/秘书界面入口、流程讨论→方案→显式执行的衔接；不抢焦点、不隐式授权，人工确认短且易懂 |

## 4. 实施顺序与验收规则

推荐FOLDER契约→FOLDER实现，再SECRETARY契约/报告→模式路由→次日整理，ONBOARD可在界面文件所有权明确后独立推进。SECRETARY次日模型整理等待CURATE/HISTORY相关真实接线，未满足时保持禁用并说明；不凭本文启用尚未实现能力。

每个检查点先写反例，运行定向测试、npm run check、适用安全/状态机覆盖率；交付npm pack及verify-package/smoke-install公开入口验证。无新增授权不安装工具、不连接真实邮箱、不开放公网、不启用秘书。主Agent继续遵循响应与只读边界。

必测：授权文案与实际参数一致、路径链接/重叠根、伪造用户、跨项目报告泄漏、同级上下文污染、秘书项目越权、多窗口去重、关闭期间长短/日期变化、整理方案变更未授权、旧历史可查、未决项不消失、关闭实验功能后停止新派发。

记录commit/dirty基线、平台、命令退出码、包哈希、真实状态/来源证据及人工体验结论。未跑场景标未验证；独立测试/验收及阶段提交推送遵循现有规则，不夹带别人修改。共享索引/状态由集成者安全更新，本轮不修改。
