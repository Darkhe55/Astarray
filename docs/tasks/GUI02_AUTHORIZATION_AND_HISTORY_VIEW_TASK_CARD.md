## 2. 授权详情卡的内容要求（用户原文，逐条落为验收项）

每张授权卡**简短、独立**展示：

| 项 | 内容 |
| --- | --- |
| 归属 | 哪个**项目**、哪个**具体 Agent**、哪个**任务**发起 |
| 操作 | 要执行的**工具/action**、**目标路径或资源**、**关键参数** |
| 理由与影响 | **为什么需要**、**会产生什么影响**、**批准范围及有效期** |
| 动作 | 「**批准本次**」「**拒绝**」；**不默认选中批准**、**不提供一键批准全部** |

**不得绕过专用流程**：安装等操作继续遵守"**先询问已有资源**"等专用流程，
**不能被普通授权卡绕过**。

## 3. 安全要求（用户原文，逐条落为反例）

| # | 要求 | 反例（必须红） |
| --- | --- | --- |
| S1 | 事件只传必要且**脱敏**信息，不含秘密或**可复用执行令牌** | 事件载荷中不得出现凭据/密钥/令牌；断言具体字段白名单 |
| S2 | 裁决入口校验 **CSRF、认证主体、项目/会话可见性、裁决权限** | 缺 CSRF ⇒ 403；跨项目/跨主体 ⇒ 拒绝；无裁决权 ⇒ 拒绝 |
| S3 | 请求绑定**具体操作、完整参数指纹、权限 revision**；过期/撤销/参数变化**均不能复用批准** | 改一个参数后复用旧批准 ⇒ 必须失败 |
| S4 | **重复点击不重复执行**；多页面并发裁决**只能有一个有效结果** | 同请求并发 2 次 ⇒ 仅一次生效，另一次幂等失败 |
| S5 | 执行前**仍重新鉴权** | 批准后权限被撤销 ⇒ 执行前必须重新拒绝 |
| S6 | **关闭页面或重启不等于批准**；旧一次性批准**不自动恢复** | 批准前关页面/重启 ⇒ 不得视为已批准 |

## 4. 历史视图要求（用户原文）

- **三视图**：当前会话／历史任务／待恢复；**保留当前会话视图的独立性**
  （即 `/state` 重启后为空是**合法接口语义**，但界面必须明确区分，不让用户误以为数据丢失）。
- **分页、按需加载**：不得一次读取全部 97 个 mission。
- 展示：任务目标、项目、时间、**最后记录状态**、可查看的结果。
- **"历史最后状态"与"当前正在运行"分开**；重启前的 `running` **不得直接显示为仍在运行**。
- 查看历史**不自动恢复、不触发模型调用、不把全部历史注入上下文**。
- **恢复须显式操作**，先**对账**并**重新检查所需授权**。
- 损坏或无权访问的记录**明确处理**，**不静默消失、不跨主体泄露**。

### 5.2 公共事件字段白名单（用户 2026-10-11 指定，**禁止原始 `argumentsJson`**）

**复用既有信封字段、不重复**。`explanation` 与参数摘要**必须本地脱敏 + 长度限制**
（不得因名为"摘要"就信任模型文本）：

| 字段 | 说明 |
| --- | --- |
| `projectIdentifier`、`sessionIdentifier` | 复用信封 |
| **发起方具体 `agentInstanceId`** | 不可复用身份，作为地址 |
| `action` | 工具含多种操作时**必须明确**（取值见基线 §6.2，含 `unknown` 保守语义） |
| `operationFingerprint` | 绑定**本地保存的完整规范化参数** |
| 请求**状态** + 请求自身 **revision** | 供多页面同步、拒绝陈旧裁决 |
| `askIdentifier`、`toolName`、有效期 | —— |

**关键参数呈现**：必须是**本地生成的结构化安全预览**（项目内相对路径、创建/覆盖动作、
内容长度、变更摘要、影响范围；文件写入可按权限过滤差异预览；**敏感值遮蔽**），
**不是模糊的一句话**。**脱敏后不足以让用户准确判断 ⇒ 不得要求盲批**，
改走**独立受控详情**或**专用授权流程**。**指纹是绑定依据，不是理解操作的替代品。**

**裁决入口**：接收**请求 ID、决定、预期 revision／指纹**；服务器**从本地权威记录取原始参数**，
重新校验**主体、权限、期限、当前状态**。
**禁止**：接受前端新参数替换原请求；把"知道请求 ID 或指纹"当作有权批准。
