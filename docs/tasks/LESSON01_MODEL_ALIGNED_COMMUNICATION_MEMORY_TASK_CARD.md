# LESSON-01：模型配置对齐的沟通经验与跨任务复用

> 日期：2026-09-20。
> 状态：pending，仅完成任务布置；未实施、未验收、未插入运行态任务序列。
> 来源：用户要求每个长时存在或经常调用的 Agent 保存沟通教训，并确认同模型审阅 Agent 跨任务复用通用教训、排除任务专属内容的方向；具体字段和检查点为 Agent 派生方案。

## 1. 目标与实施边界

扩展现有个体存档、受控读取和跨 Agent 附件工具，增加沟通经验记录类型。支持分派前、接收任务时、审查汇报时读取相关经验，减少定位歧义和无依据的完成汇报。不得建设共享对话记忆、模型能力排行榜或第二套验收系统。

经验归具体 Agent 所有；通用性、适用模型和接收者是独立维度。相同角色、模型名称不意味着可以共享全部记忆。一次失败不能证明模型能力不足或故意欺骗。

不设置 Agent 存活时间或调用次数准入硬门槛；所有个体可以记录，长时/复用个体是主要受益对象。首期不新增专门总结 Agent 或常驻总结服务。

开始编码前完整读取 AGENTS.md 指定的四份治理文档及相关当前 ADR，遵守 [产品接线共同规则](./PRODUCT_INTEGRATION_ROLLOUT.md)。权限以接入时最新有效规则为准，不能从历史任务卡恢复已被替代的安装规则。

### 避免并行编辑冲突

- 本轮仅新增本文件，不修改已有设计、索引、任务卡或代码；共享任务索引当前有未提交修改。
- 现有编码 Agent 先收口当前检查点。次级集成者在安全检查点核对当前实现、commit/dirty 差异和文件所有者，再安排本卡。
- 个体存档、附件、模型配置和运行循环公共文件不得双写；若实施并行，使用分配的隔离 worktree，由次级审查集成。
- 首检查点核对存档写入、个体隔离、配置快照、附件、公共应用入口的动态证据。已有能力复用，缺失能力显式列为前驱；不凭旧卡 done 推断产品接线可用。
- 本卡与 ACCURACY、SUM、GUIDE 重叠时先协调公共契约，不要求无关功能全部完成；优先复用其开关、摘要、版本回执与安全点机制。

## 2. 记录契约

字段名在 LESSON-01-01 结合现有 schema 冻结，不预先另起一套身份或模型目录。

| 内容 | 要求 |
|---|---|
| 所有者及来源 | 不可复用的 ownerAgentInstanceId、记录 ID/revision、原任务及消息/工具证据引用 |
| 沟通关系 | 发布者/接收者实际 agentInstanceId、层级、职责角色、沟通方向及阶段 |
| 双方模型快照 | Provider、准确模型标识、可获知版本、实际生效的相关配置；快照取事件发生时而非写总结时 |
| 任务情境 | 任务类型、必要工具能力、触发条件、上下文截断/预算不足等已知状态 |
| 内容 | 可观察事实、原因假设、下次行动建议分别保存，不能混为确定事实 |
| 范围 | task、project、role-model-config；另外保留经审查的模型无关规范类别 |
| 状态 | 未验证观察、已核验、被反证、被替代或撤销；推广状态与有效性状态分离 |
| 有效性 | 创建/核验时间、策略版本、适用模型配置、后续成功/失败或不适用反馈 |

模型参数按 Provider 实际能力记录，如推理强度、温度、输出及上下文预算、影响工具行为的配置。不要求所有模型具有相同字段；缺失值显式 unknown，未知不得当成精确匹配。配置指纹使用本地生成的规范化非敏感快照，不含凭据、令牌或私密端点。

Agent 可提交心得，但模型/身份/回执等权威字段由本地补齐或验证。无证据内容保留为未验证观察，默认不自动注入，不自动推广。引用存在不等于其支持原因推断。

记录修订采用追加事件；合并相似经验保留各来源，不覆盖原记录。真实删除及恢复继续走受控备份流程。

主 Agent 只读角色不改变：其沟通经验由本地控制面根据允许的输出候选和事实回执存档，不向主 Agent 模型暴露写入工具；其他 Agent 仅能在有效权限下写入自己的存档。

## 3. 适用层次与通用经验推广

| 范围 | 示例 | 可用范围 |
|---|---|---|
| 任务专属 | 本次必须检查某个订单退款回调 | 仅指定任务及明确版本范围 |
| 项目通用 | 本项目生成文件不得手工修改 | 同一项目且相关任务 |
| 角色＋模型配置通用 | 某审阅配置曾遗漏异步失败分支，应单独核对 | 匹配职责、配置和触发情境的其他任务 |
| 模型无关规范 | 不确定符号指向时先澄清；测试结论应引用实际回执 | 经审查确认的通用规范，不强行绑定某个模型 |

默认新记录是任务专属。职责/模型配置通用不等于所有任务都注入；必须仍与当前问题类型相关，代码审阅经验不能直接用于文案审阅。

推广流程：

1. 所有者或有权上级提出推广候选，说明可泛化部分及证据局限。
2. 负责次级审查，剥离具体文件、变量、业务数据和临时要求，保留不可变原始引用。未经核验的一次观察不直接升级为强制规则。
3. 本地控制面校验来源、权限、范围、revision、内容指纹及敏感信息；语义是否通用属于审查结论，不声称确定性 schema 检查可以证明。
4. 批准后登记派生通用条目的受控索引；原始记忆仍归原个体。接收者只拿经选择的不可变附件，不读取旧 Agent 私人存档。
5. 默认在原项目内复用。跨项目复用须有明确的用户允许策略及内容审查；抽象标题不能自动证明没有泄漏业务信息。原证据跨域不可读时只返回引用及访问状态，不自动扩大权限。
6. 新任务收到附件不等于把该经验写入自己的长期记忆；接收者的新观察独立存档并引用来源。

次级自身的经验需推广时，首期由认证用户或不同于提出者的指定审阅者审查语义，由本地控制面登记；不能为此给主 Agent 增加写权限或允许自提自批。

## 4. 模型匹配与读取

- 默认严格匹配沟通方向、双方职责、双方模型/版本及相关实际配置，再匹配任务类型和触发条件。实例 ID 用于追溯和访问控制，不作为跨任务复用必须相等的条件。
- 推广时可以明确哪些条件与经验无关，但放宽每个匹配维度都应有审查理由；未声明的放宽不生效。不要将全部运行参数都机械纳入匹配而导致永不复用。
- 模型别名背后的版本无法确认时标记身份不确定，不保证同名即同模型；相近或未知配置仅在主动查询时作为参考返回，显示差异，不能伪装精确匹配。
- 用户确认为模型无关规范后才可跨模型自动使用，优先引用已有规范，不重复堆叠同义提醒。
- 模型/关键配置切换、经验撤销或任务 revision 改变时重新选择并使旧缓存失效；在下一安全点停止继续注入失效经验，不重复重启正在执行的调用。
- 默认只返回少量高相关行动建议、适用说明和证据引用；详细原因及原证据按需展开。纳入现有本轮上下文预算，不扩大全局预算，也不因预算裁切否定或适用条件。
- 同一接收者/任务 revision/经验 revision 已投递不重复注入。缓存按具体接收 Agent 隔离，键含项目/作用域、相关模型配置、任务情境和条目版本。

### 扩展现有工具的三个动作

1. 记录：提交观察、假设、建议和证据引用，由本地生成权威元数据。
2. 查询：按当前任务和实际模型配置返回适用条目；支持只读摘要、详情和主动相近条件参考。
3. 修订：追加有效/不适用/反证/替代记录，及经授权的推广提案与审查结果。

检索到的经验是带来源的辅助资料，不是新用户指令；不能提升权限、改写验收要求、绕过执行门禁或要求读入无关敏感内容。

## 5. 效率、开关及纠偏

- 提供独立“沟通经验辅助”开关，支持项目默认和当前任务覆盖，默认开启相关建议；Agent 不能自行更改用户设置。
- 关闭时不自动检索、注入或触发模型生成总结；用户主动请求记录/查询仍依照正常权限执行。已有存档不删除。
- 准确性检查为快速档时，经验只能提示，不能偷偷增加严格验收、人审等待或额外审阅模型调用；需要提升检查等级时由用户决定。
- 仅在明显沟通失误、返修、有效改进或阶段收口时提出记录，不逐工具调用总结；能够随现有终态汇报提交的，不额外调用模型。
- 去重同一问题并追加证据，记录正向有效做法；单次成功不自动抹去历史风险。冲突经验显示冲突，不能同时作为强制要求。
- 审查/记录失败不影响原任务真实性状态；经验系统不可用时降级为无经验辅助，原任务权限和验收规则继续生效。
- 使用有界选择和预算，不增加固定总经验数量上限；冷门记录仍在个人存档中按需读取。首期不实现自动模型评分、自动参数调优、统计学习推荐或复杂衰减算法。

## 6. 场景验收

### 场景 A：同名符号歧义

记录事实为“修改了错误命名空间中的符号”，原因假设为“定位信息不足且未澄清”，不得直接断言模型性能低。

上级建议：匹配配置且存在多义目标时，写清文件、命名空间/完整符号及预期行为。下级建议：候选目标不唯一时先询问。无歧义的小任务不得被强制要求长提示或额外往返。

### 场景 B：汇报通过但实际失败

保存报告与同次执行的非零退出码证据，标注原因未知或假设；不得仅凭结果不一致认定故意欺骗。上级提醒核对当前产物和本地回执，下级提醒将未执行/不确定项目写成未验证。

原完成校验承担基础真实性检查，经验不替代它。可选质量检查关闭时也不能伪造通过证据。

### 场景 C：跨任务复用审阅经验

任务 A 的审阅 Agent 形成两条记录：指定业务文件的任务专属要求，以及经审查推广的异步错误路径审阅经验。任务 B 分配新的同职责、匹配模型配置 Agent 时，只接收相关通用附件；任务 A 的文件名、业务要求和完整历史不能进入任务 B。

相同模型但推理配置不同、任务 B 是文案审阅、项目权限不允许或经验已撤销时，不自动注入。若建议已被审查为模型无关规范，则使用相应独立规则，不借“同模型”逻辑扩大范围。

## 7. 三个实施检查点

| 检查点 | 产出 | 验收条件 |
|---|---|---|
| LESSON-01-01 | 当前链路审计、未占用 ADR、记录/schema、事件时配置快照、个体存档及推广契约 | 双方配置取自运行时；unknown 明确；事实/假设分离；主 Agent 无新增写工具；非法来源/跨个体写入拒绝 |
| LESSON-01-02 | 现有工具扩展、三层范围及模型无关规范、审查推广、精确选择、附件/缓存/开关 | 跨任务同配置命中但不带任务细节；不同模型/参数不误套；原文不可越域读；去重与版本失效正确 |
| LESSON-01-03 | 分派/接收/审查节点的应用接线、恢复、产品设置及包消费验证 | 场景 A/B/C 从公开入口走通；关闭无自动总结/检索；模型切换不串用；崩溃重试无重复推广/投递 |

每轮只执行一个检查点；预计超过三小时则进一步拆分。预先协调公共文件所有者，不同时推进多个涉及同一契约的检查点。

### 必需测试矩阵

- 身份：同级隔离、旧实例接手、新实例附件、伪造所有者、跨项目证据拒绝。
- 匹配：同模型不同 Provider/版本/推理配置、unknown 参数、模型切换、相同接收模型但不同上级配置。
- 内容：无证据观察、错误归因、原文不支持总结、通用化残留业务信息、矛盾经验及恶意指令内容。
- 范围：任务专属不进入其他任务；项目经验不跨项目；角色/任务类型不匹配不注入。
- 生命周期：同事件重放、撤销/替代、缓存失效、索引原子发布失败、附件原文权限变化、重启恢复。
- 效率：开关关闭、简单任务无额外模型轮次、同版本不重复注入、预算不足不截断关键条件。

先写失败反例再实现；运行定向测试和 npm run check，隔离/状态机相关变更补 coverage 及当前仓库安全专项门禁。交付执行 npm pack、verify-package.mjs 与 smoke-install.mjs，并通过公开包入口验证；安装或联网按当前有效权限处理。

测量每次派发新增 token、自动模型调用数、检索/记录延迟、重复注入率、错误适用率及人工标注样本下的同类失误复发情况，保留样本数、配置和分母。没有足够对照证据时只报告观测值，不宣称降低幻觉或提升准确率。
