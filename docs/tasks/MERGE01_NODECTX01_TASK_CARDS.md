## 1. MERGE-01：智能指令合并与工具适配

### 1.1 目标与最小实现

- 减少重复规划、模型调用及兼容操作的重复执行，不以工具数量或指令数量下降作为唯一成功指标。第一版仅做确定性去重/明确补充合并；模型可提出相似候选，本地检查后才采纳，不引入独立长时合并模型。
- 原始用户指令追加保存，保留每条来源、ID、revision、优先级、取消权和验收条件；执行组仅引用原指令，不能覆盖原文、伪装用户指令或自动认定被合并项完成。
- 只合并同项目、同任务权威、相容目标和权限作用域的 ready 指令。保留前驱/后继偏序，不跨依赖障碍；语义冲突、目标不明、独立授权、跨项目、已产生副作用的在途操作不合并。用户明确修订走 supersedes，不按“最新文本”猜测废弃旧任务。
- 多项可共用一次读取/检索，但每个子结果映射回原 ID；部分失败只影响对应节点。取消一项不得取消其他项，执行后不能通过拆组合并重放副作用。
- SMART 窗口按原始未完成意图计数，不按执行组数量计数：窗口 3 条不能通过合并塞入第 4 条。未准入候选只保存关联，轮到它时可复用已验证结果；组完成不自动关闭全部原指令，逐项由本地门禁核验。
- 指令合并提供独立开关，初始关闭；用户启用后运行以上保守规则。关闭后不丢组内原指令，不重放在途操作，安全点拆回未执行项。

### 1.2 多格式适配与工具统一

- 以能力族和 action 枚举复用现有工具，例如统一读取工具的 format/view 参数，复用 READ-FORMAT/SUM；不因语言或相似格式另造一套名称。
- 先适配两个现有相近入口作纵向样本，保留旧名称兼容别名并路由同一实现；不得为了统一变成任意 shell/任意方法调用入口。
- 工具描述符按 action 和参数判定副作用、权限、备份与幂等性；含写动作的工具不能整体伪装成 readonly。不同 action 的必需参数使用可校验 schema 分支，不认识的 action/参数拒绝。
- Ponder/主 Agent 只读工具视图仅暴露允许的读取动作；统一工具名称不能让隐藏的写动作绕过本地执行检查。

### 1.3 授权设置：统一授权与参数细分共存

设置层复用现有 profile/revision 控制器，提供：

1. 参数级授权总开关 `isParameterAuthorizationEnabled`（初始关闭以兼容旧配置）。
2. 每个工具保留“统一授权”三态 `deny/ask/allow` 控件；若既有 UI 为开关加选择器，保留使用方式和导入兼容，不降成只有允许/禁止。
3. 每个工具提供“启用参数细分”开关 `isParameterRulesEnabled`，以及该工具 schema 支持的参数细分列表。
4. 列表首版支持 action 枚举、规范化项目路径范围、枚举/布尔值、明确数值区间与固定参数值；每条规则有可读解释和 deny/ask/allow。禁止可执行脚本、任意正则或让模型解析授权条件。
5. 总开关关闭或该工具细分关闭时使用统一授权；均开启时，已匹配参数规则覆盖工具基线，未匹配回退基线。多个规则冲突 deny 优先于 ask，ask 优先于 allow；工具明确 deny 为总拒绝，不被参数 allow 覆盖。基础 ask 可对明确 action 细化 allow，但仍受更外层权限上限约束。

任何结果仍与上级权限、项目边界、模式及专用授权门禁求交；不能因参数 allow 绕过安装逐次许可、备份删除等独立规则。Devolve 的可配置基线按既有规则 allow，Assist 沿用独立矩阵；Ponder 不提供调整。自定义模式和会话提升复用现有范围，不放宽主模型只读；本地强制约束不出现在设置列表。

设置变更展示简短准确差异，扩大权限需既有认证用户确认；配置保存和生效 revision 分开。关闭细分若会从 deny/ask 回退 allow，必须明确提示放宽范围，不以“关闭功能”静默扩大权限。收紧立即阻止新执行，旧在途按取消/对账收敛；所有旧批准按 revision 失效复检。

每次调用仍绑定 tool/action、完整规范化参数哈希、实例/项目/任务、profile revision 与期限。JSON 对象键序可规范化；数组顺序、正文、末尾换行、路径大小写等不随意合并为等价，未知字段拒绝；参数或目标变化重新判权。展示时隐去秘密但哈希绑定不丢参数语义。

批准一个执行组不是批准任意批处理：每个子操作分别检查精确参数与幂等键，安装等重要授权单独展示，禁止把多个高风险操作塞入一次长授权。原子批操作仅在底层真正提供事务时声明，否则逐项返回成功/失败/未执行。

### MERGE-01-01 进展（2026-10-10）：参数级授权优先规则

本轮先落地卡内**权限优先规则**这一最窄且最可判定的契约（§1.3）。实测缺口：
`isParameterAuthorizationEnabled` / `isParameterRulesEnabled` 在整个 `packages/` 内**零命中**
⇒ 参数级授权完全未实现。

- 新增 `packages/core/src/tools/parameter-authorization.ts`：声明式
  `ParameterAuthorizationRule`（tool + action + 三态 decision + 可读 explanation + 匹配条件）
  与**纯函数** `evaluateParameterAuthorization()`。匹配种类仅四种（卡内允许的形态）：
  `path-prefix` / `allowed-values` / `fixed-value` / `numeric-range` ——
  **无可执行脚本、无正则、模型不参与判定**。
- 固化优先级（与声明顺序无关）：工具基线 `deny` ⇒ **总拒绝**，参数 `allow` 不得覆盖；
  总开关或该工具细分关闭 ⇒ 一律回退基线（`isRuleEvaluationSkipped=true`）；
  均开启且**已匹配** ⇒ 规则覆盖基线；未匹配 / 参数不可解析 / action 不匹配 /
  未知匹配种类 ⇒ 回退基线（**fail-closed，不猜测**）；多规则冲突 ⇒ **deny > ask > allow**。
- 已由 `public-sdk.ts` 公开导出（消费者不依赖内部路径）。
- 反例（先红后绿）：`tests/core/unit/merge01-parameter-authorization.test.ts` 9 条
  （实现前模块不存在即失败）。
- **仍未完成**：设置入口（§1.3 第 4 项）与权限引擎/production 接线、两个工具适配样本、
  执行组到原指令映射与合并开关、NODECTX-01 全部内容 ⇒ **不主张 MERGE-01 或 NODECTX-01 通过**。

测试重点：上限 3 不因分组越窗；A 写 X/B 写 Y 不误合并；重复读减少 I/O 但各回执可追踪；参数 read→write、路径逃逸、批次夹带动作被拒；总开关×单工具细分×基线三态×规则冲突矩阵；同键不同值重新授权，单纯键序变化不重复询问；取消和崩溃不重做已成功写入。指标记录请求/工具次数、token、延迟、误合并/漏合并与返修次数，不预设虚假节省百分比。

## 2. NODECTX-01：禁止有损压缩，以节点关闭与暂存管理上下文

### 2.1 术语与不可混淆的边界

- 本项目“上下文压缩”指把历史强制改写为较短文本、覆盖原文或静默丢弃细节来延长会话的机制；所有 Astarray 可控制的自动/手动语义压缩、滚动摘要替代历史、静默截断兜底均禁用，不提供重新开启该机制的开关。
- **内容总结仍允许**：动态摘要、文件头/sidecar 摘要、关闭胶囊、向用户汇报都是原文之外的派生资料，保留来源 ID/revision/hash 和细节回访；总结不是原文，不可作为删原文或伪称细节仍在上下文的依据。
- 本政策不禁止无损磁盘编码/归档，也不要求所有历史同时进入窗口；筛选只能通过可审计节点状态和分段读取完成。禁止的是强制有损替代，不把现有 SUM 组件仅改名后继续做有损截断。
- 仅保证本项目控制的请求装配与存储；Provider 内部不可观察行为不得宣称已禁用。适配器对可配置自动 compaction/truncation 明确禁用；无法保证的接口记录不支持该保证，不以静默压缩重试。

### 2.2 与现有上下文图兼容

复用 T09A 节点、偏序、验收和回访机制。节点业务执行/验收状态与上下文可见性分开存储，不能把“暂不入提示词”当 done。

| 可见性 | 含义 | 恢复方式 |
|---|---|---|
| active | 当前请求需要的已准入节点/片段 | 按预算和依赖装配 |
| temporarily-closed | 非紧急、非重要且当前不需要的节点原样暂存磁盘，等待执行或回访 | 窗口释放、前驱满足后按优先级稳定顺序自动重新准入 |
| permanently-closed | 满足既有完成/验收关闭条件，永久退出自动上下文装配 | 原文仍存档，可显式回访；新需求建立引用旧节点的新节点，不偷偷重开原节点 |

上述为设计语义，不要求立即改动现有状态枚举；优先为现有节点增设独立可见性/延期索引，并保持旧图、胶囊、deferred-review-closed 和回访格式可读。永久关闭不代表物理删除、永不查阅或免除延迟人工核验；待追认节点仍带不确定标记，核验否决时阻断受影响后继并建立返修节点。

### 2.3 上下文不足：落盘、先前驱、再自动补回

1. 本地装配器按实际 Provider/model 的完整序列化请求计量，预留输出与工具结果余量；全局相关内容默认 4096 token 硬预算，沿用可调整上限。摘要总长度仍无固定硬上限，单次读取/注入预算独立。
2. 确定当前 ready 前置段落/任务节点，保护当前目标、有效用户约束、必要依赖、未决问题和工具调用/结果配对；不因旧、长或“不紧急”而隐藏当前执行所需内容。
3. 仅把当前不需要的非紧急/非重要节点完整落盘；先校验原文可读、hash/revision 与写入成功，再提交 temporarily-closed 及队列索引。磁盘失败不移出上下文、不假报暂存成功；不通过模型重写原文。
4. 处理当前前置节点；在完成、关闭、取消、显式调整预算等安全点触发本地准入器。按偏序 ready set、优先级与稳定顺序补回合适片段，保持用户来源优先；上下文释放不等于自动扩大 SMART 指令窗口。
5. 暂存队列只引用原任务/节点，不新增另一套任务调度器，不把排队节点提前标为执行中。非紧急大节点长期装不下时，以无损分页/段落分块加载，不永久饿死；限制每次补回数量并检查实际预算。
6. 紧急消息沿 EVENT 仲裁，不自动关闭关键依赖；有必要时暂停当前任务并检查点恢复。跨文件/跨 Agent 附件继续服从来源、权限和记忆隔离。
7. 当保护内容本身超窗且无法安全分段时，拆任务、创建显式 handoff 的新执行者或暂停说明所需调整；不得偷偷截尾、调用 summarizer 替代历史、无限重试或选择未授权的大窗口模型。

自动补回按 node/revision/activation ID 幂等，恢复时从磁盘索引对账，防止重复注入与丢节点。设置关闭/恢复阈值滞回及每轮迁移上限，沿用读取时间锁和回访回执，防止临时关闭—补回反复振荡；同 revision 无进展时停止并报告，不周期性唤醒模型。

### 2.4 总结与缓存

- 总结用于导航、报告与显式摘要视图，标明覆盖范围、遗漏细节和原文引用；关键决策按相关性提升到受预算约束的全局区，无关内容留盘。
- 不用“摘要已生成”作为关闭资格；资格仍由本地依赖、未决调用、验收及人工策略判定。暂存待处理内容不要求先让模型总结，以免消耗额外调用。
- 缓存键包含个体/任务、节点与内容 revision、可见性/装配策略版本、模型/计量器版本；稳定前缀复用，补回只增量装配。不共享不同 Agent 的可变上下文。

## 3. 顺序、交付及门禁

建议先 NODECTX-01-01 与 MERGE-01-01 做契约（同一实施者每轮一个）；落实 SMART 生产接线与相关可靠性返修后，再依次 NODECTX-01-02/03、MERGE-01-02/03。共享 assembler/调度/权限入口串行集成，不同时重写。

每个检查点先反例后实现，变量名完整，布尔/时间量遵循命名规范，覆盖/删除前工具备份。运行定向测试、`npm run check`、覆盖率及安全专项，冻结同一提交后 `npm pack`、verify-package 与 smoke-install；包级验收必须真正驱动请求/工具而不是只 import。记录平台、命令退出码、包哈希、请求和产物关联、人工/真实服务未测范围。失败门禁或 skip 不算通过，不放宽原阈值。

每轮至多一个检查点；超过三小时拆分。状态修改是交付内容；本地提交只含自己的改动，通过后依仓库规则尝试推送。完成控制事件、业务验收与文档状态三者必须一致，不凭模型声明结案。
