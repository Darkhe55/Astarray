# OBS-01：性能监测、用量检查、错误汇总与诊断

日期：2026-10-01。状态：pending，仅设计与任务布置；未实施或验收。

## 1. 目标和接入约束

为用户和有权 Agent 提供低开销、可追溯的运行状态、资源用量和故障定位能力。复用当前指标、Provider usage、错误定义及 SDK 诊断，不建立另一套调度器、审计系统或遥测平台。默认本地保存，不上传遥测，不在后台调用模型分析错误。

本轮静态核查确认存在：

- `packages/core/src/infra/metrics.ts`：工具/Provider 调用、估算/非估算 token、缓存、并发和消息平均延迟。
- `packages/core/src/measurement/provider-usage-capture.ts`：带请求标识的 Provider usage 捕获；当前 JSONL 读取为 readAll。
- `packages/core/src/public-sdk.ts`：getMetricsSnapshot 和 getRuntimeDiagnostics；后者包含反馈进程和授权端口等状态。

这些仅证明已有基础，不证明全入口接线、持久化去重、费用正确性或长期资源有界。本卡先审计复用；尤其验证逐条 token 数组、全文读取对长会话的影响。

开始编码前完整读取 AGENTS.md 指定四份治理文档、当前相关 ADR 和产品 rollout。与 RELIABILITY-01、CONFIGCHAT-01、WORKWINDOW-01 协調事件字段及文件归属；先收口在途检查点，再插入本卡派生节点，优先级层级 1 或以下。不能同时修改同一公共 schema、SDK 或运行循环。

## 2. 共用数据与工具边界

- 关联键包含项目/会话/任务/具体 agentInstanceId、operationId、attemptId、事件 ID、时间及 schema revision；Provider 请求有独立请求 ID。聚合视图不是跨 Agent 原始记忆共享。
- 数据来源区分本地测量、Provider 返回、估算、缺失和不支持；unknown 不记作零，样本窗口与覆盖范围必须显示。
- 进程资源按进程及采样时刻归属；共享进程不能将同一内存分摊后当成每个 Agent 的精确实测值。需要估算时显示分配方法与不确定性。
- 日志在写入前最小化、清洗；不保存默认 prompt/回复正文、环境变量、凭据、请求头、敏感文件正文或完整命令参数。路径、堆栈、Provider 错误文本同样检查，不能先写原始日志再只遮盖界面。
- 受控只读工具扩展为查询性能、查询用量、查询错误及诊断四类动作，支持范围、时间窗口、分页和摘要/详情。复用已有查询入口与诊断命令，最终公开名称在契约检查点冻结。
- 每次查询校验可见范围，主 Agent 只读选择相关摘要；子 Agent 不得借诊断接口读取同级原始记录。数据中的指令按不可信内容处理。
- 记录源时间与单调耗时，跨进程时钟偏差不得产生伪精确延迟；导出附版本、平台、时间窗口及脱敏说明，不自动联网发送。
- 高基数 ID 放明细索引，不成为无限增长的内存指标标签；事件批量追加、查询分页/聚合，提供有界队列、背压与丢样计数。
- 可配置采样间隔、详细跟踪开关及存储预算；默认轻量采样，不做持续 profiler、全机扫描或 GPU 采集。具体默认值用原型测量冻结。
- 普通观测故障不得阻塞业务；显示监测降级而非一切正常。可靠性审计/授权必需记录不受普通监测开关影响。
- 存储预算耗尽时先停可选详细采集并报告，不静默删除历史。归档、压缩替换和清理遵循自动备份及专用删除规则，避免“删日志先备份”产生无限增长；首期不实现自动清理备份。

## 3. PERF-01：性能监测

首期展示：

- 应用及所属子进程的 CPU、内存、存活与退出情况；CPU 百分比注明核数归一化口径，平台不支持则明确标记。
- 任务队列长度、可执行/运行/等待授权/计划暂停/失败任务数，以及并发峰值。
- Provider 首响应、总响应、工具执行、反馈投递、取消确认和恢复耗时，区分排队、执行、等待；p50/p95/p99 附样本数和窗口，不以单样本推断趋势。
- 工具/模型调用次数、缓存命中及有效复用、上下文占用、重试、无进展事件。
- 索引/备份/日志磁盘占用按低频增量或受控查询测量，不每轮递归扫描工作区。

提供当前概览和任务时间线即可，首期不建复杂仪表盘。告警通过既有独立反馈机制聚合、去重、冷却并在恢复时标记解除，不逐样本唤醒模型。阈值告警默认只提示；不能自行杀进程、改模型、提权或重启任务。高级自动动作须另有明确用户策略。

| 检查点 | 实施与验收 |
|---|---|
| PERF-01-01 | 核对已有事件接线、冻结测量口径/采样预算；用同一工作负载测开关前后 CPU/内存/延迟，记录设备与样本 |
| PERF-01-02 | 进程/任务测量、持久聚合、分页及告警；高并发、进程退出、队列溢出、时钟变化和监测器失败反例 |
| PERF-01-03 | SDK/CLI及现有TUI/GUI最小概览接线和tarball；长会话内存有界，休息时不产生模型/业务请求，无法测量不报零 |

## 4. USAGE-01：用量、配额与估算费用

- 按项目、会话、任务、个体、Provider 和模型查看输入/输出 token、缓存输入及已知推理 token、请求和工具调用次数。字段子集关系按 Provider 语义登记，避免缓存/推理 token 与总量重复相加。
- Provider 报告与本地估算分列；失败、取消、断连也可能计费。最终 usage 缺失保持 unknown 或带标记估算，不能作为零消耗。
- 同一请求的流式增量与最终 usage 去重/修订，最终值替换对应估算，不叠加。重试属于新 attempt，实际多次请求应分别统计；幂等回执重放不再计费一次。
- usage 来源于 Provider 不等于正式账单。本地观测用量、用户预算、Provider 官方配额/余额分别显示，缺官方接口时标不可查询，不从本地调用量推算账户余额。
- 首期费用仅为可选估算：使用用户配置或明确来源的版本化价目、币种、生效时间，区分输入/输出/缓存费率；无匹配价格返回未估算。不捏造价格、不自动抓价、不默认调用账户付费接口。
- 支持查看预算消耗与阈值提醒。用户显式启用硬预算时在新调用前按保守预留及并发原子占用门禁，结束后对账；不能保证最终账单绝不超预算，在途费用和未知 usage 要保留风险提示。首期硬预算可限 token/请求数，金额仅提醒，避免虚假精确费用控制。
- 官方配额接口作为可选适配能力，遵守现有网络/凭据授权、查询频率和费用规则；测试使用假服务，不要求所有厂商同时接通。

| 检查点 | 实施与验收 |
|---|---|
| USAGE-01-01 | 请求级账目/来源/修订契约及现有捕获审计；同键异参拒绝，明确总量/子量、估算与账单边界 |
| USAGE-01-02 | 持久化去重、分页聚合、预算及估价；重复事件、乱序终值、重启、跨模型切换、取消缺usage、并发预算反例 |
| USAGE-01-03 | 公开查询/界面/导出和包验证；账目可复算，不虚报余额，价格缺失和估算来源清楚，不泄漏其他个体明细 |

## 5. DIAG-01：错误汇总与只读诊断

- 统一错误摘要：错误码、阶段、严重性、首次/最近发生、次数、来源、影响任务和已知恢复状态；正常计划暂停、用户拒绝、取消与程序故障分开，不把等待都记成失败。
- 按错误码/组件/安全指纹合并同类错误，保留每次事件关联；相同文本不保证同因，不能把不同任务和配置条件下的事件完全吞并。链路记录根错误候选、包装错误及后续症状，避免一处故障重复刷屏。
- 诊断结果分“确定事实、疑似原因、缺少证据、建议检查、可选修复”。错误数量下降不是已修复的证明；关闭事件需解除证据，复发可关联旧事件。
- 默认读取现有状态/脱敏回执：配置引用有效性、反馈进程、队列、锁/租约、近期超时重试、恢复分类等。主动进程执行、联网探测、创建文件或复现步骤分别预览和授权，不能藏在只读诊断按钮中；思索模式仅允许其既有只读能力。
- 不自动安装、清理、删除备份、重试未知副作用或修复配置。修复建议转为独立有范围任务，由正常权限/准确性流程处理。
- 可选模型辅助解释必须由用户开启或明确请求，只提供经过筛选的证据包，计入用量；输出是推测，不能作为自动授权或最终验收依据。
- 提供脱敏诊断包预览和受控导出，默认只含必要元数据/摘要及证据引用，不附完整会话、源码或日志。导出同样遵守个体/项目可见性和写入规则。

| 检查点 | 实施与验收 |
|---|---|
| DIAG-01-01 | 错误分类/指纹/关联/诊断 schema，复用 DomainError 和现有 doctor；冻结不支持的探测与信息边界 |
| DIAG-01-02 | 持久汇总、分页、只读规则诊断及证据包；重复风暴、敏感错误文本、故障链、不足证据、诊断自身失败反例 |
| DIAG-01-03 | 公共工具/CLI/SDK及最小界面、tarball；故障可从任务追溯到真实回执，无未授权副作用，不把模型推断写成确定根因 |

## 6. 推荐顺序与最终验收

先协调 RELIABILITY-01-01 的工具/事件清单；执行 PERF-01-01 → USAGE-01-01 → DIAG-01-01，冻结一个最小共享事件契约，再按文件归属分批实现各组 02/03。不是一次领取全部契约检查点，每轮只做一个；超过三小时继续拆分。

生产代码命名完整，时间/字节单位明确，布尔遵循 is/has/can/should。先行为反例，运行定向测试、npm run check、适用覆盖率及安全门禁；最后 npm pack、verify-package.mjs、smoke-install.mjs，从安装包公开入口完成“执行任务→采样/用量→注入错误→诊断→重启后查询”链路。

首期不引入外部时序数据库、独立遥测集群或默认新守护进程；现有进程分工可承载则复用。观察开销预算先测再定，不预填性能提升或费用节省百分比。跨平台未实测明确标未验证。

完成证据需包括提交/dirty 基线、来源及实际命令退出码、测试矩阵、资源测量、账目复算、脱敏样例、未满足项和tarball哈希。验收/提交后按常设节奏推送；不提交其他 Agent 改动。索引和状态表在其所有者允许时由集成者更新，本文件 pending 不代表任何功能已上线。
