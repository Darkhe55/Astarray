先使已有核心能力从CLI/TUI/SDK真正可达，再做真实工作助手验收，随后扩展桥接和GUI。2026-09-10只读核查发现：SDK submit只返回accepted且提前发送task-finished、结果Map未写；run拒绝非mock且bootstrap使用ScriptedRuntime；上下文相关类存在但未发现主要能力在生产入口装配。旧T07D卡已要求这些接线，因此必须返修。INT-00须重新核对当前代码，不能把本说明当成永久事实。

尚未证明缺口的能力先审计；已实现功能复用并回归，不重复造模块。任何旧卡done仅保留历史证据意义，若本批发现原验收未满足，须在INT-00写明范围和返修映射。

## 3. 单轮工作量与来源

- 每次激活只领取一张卡中的一个检查点；预计超过3小时继续拆分，按可构建/可测试边界提交。
- 不把整张大卡作为一次执行任务。默认单执行者按上表推进；只有明确安排并行时才使用隔离工作树，由次级负责集成。
- 任务卡是设计计划，不替代Agent个体存档中的运行态偏序集。用户原始任务信封可层级0；本批Agent派生拆分节点使用层级1或以下，保留来源关联。
- 首先检查dirty worktree，保存基线，保留别人的修改。变更前通过本地工具备份；不得把整个工作树全部暂存提交。
- 命名完整可读，布尔is/has/can/should前缀，时间含单位，核心领域禁止any。
- 不足的依赖/工具先问用户是否已有资源，遵守协同安装开关及精确单次授权；不能让测试命令隐式下载包或浏览器。
- 阶段验收通过并完成本地提交后，尝试推送当前分支至已配置远端，最多5次；缺远端或失败记录原因，下阶段再尝试。累积提交一并推送不表示压平或改写历史。

## 4. 证据与测试

每个实现检查点先写行为反例，必须验证公共入口调用真实控制器以及产物/状态变化；仅import、DTO、字符串成功或手工填充结果不能通过。

实现检查点运行相关测试和 `npm run check`；覆盖率相关或状态机修改运行 `npm run test:coverage`。总体分支至少85%，适用关键安全模块单模块至少95%，列出模块与分母，不能靠全局平均替代。INT-00文档纠偏阶段采用链接/差异检查及必要行为诊断，无须为了文档新增无意义代码测试。

包消费与交付检查点还须：

```powershell
npm pack
node scripts/verify-package.mjs <本次生成的tarball实际路径>
node scripts/smoke-install.mjs
```

开跑前检查脚本参数与安装行为；`verify-package`必须传真实tarball路径。SDK消费者只能使用公开exports，必须完成任务和结果读取，不能只测试import。禁止真实服务测试在默认离线CI偷偷联网或产生费用。

平台证据按Windows/Linux/macOS分别记录；未执行平台保留未验证且限制声明。沿用已有跨平台、安全专项和依赖audit整改清单；INT-00映射到可领取检查点，缺现成卡时拆子卡，不得将其无期限放入“剩余风险”后宣布全平台通过。

验收记录至少包含：基线及最终commit/dirty差异、任务/Agent身份、命令及退出码、测试数量、覆盖率、tarball哈希、请求/状态事件、产物哈希、平台、Provider/模型版本、人工结论和未满足项。日志与证据不得含凭据或敏感项目正文。

完成事件使用当前仓库合法的 `ASTARRAY_TASK_COMPLETION_V1` schema；补充证据写入报告，通过现有引用机制关联，禁止自行在控制事件中添加不支持字段。

## 5. 无人时段与终态

离线fake server验证产品接线，真实服务验证外部兼容性，两者分别记状态。缺凭据、成本授权或人工体验时只暂停依赖节点，释放锁与资源，不机械轮询。

Assist默认人工验收阻塞，Devolve默认延迟核验；用户修改策略后按有效revision执行。延迟核验不取消安装、备份删除和其他专用授权，也不能把待人工追认写成已通过。节点策略满足可以继续，但本卡明列的真实服务/人工体验验证缺失不能标为done。

pn单次退避最大10800秒，不是全任务执行超时、自动授权时限或数据保留期限。长任务退出/后台运行/重新连接语义由应用服务明确，不能用固定60秒轮询上限误报失败并销毁任务。
