# PROJECT-01：项目隔离与跨项目受控借阅

日期：2026-10-01。2026-10-10 对账状态：in_progress。授权、回执与查询组件已有实现；实际资源读取/导入 I/O 尚需接线，不得以 didRead/imported-copy 回执代替真实产物。跨项目始终不得修改来源项目，通信规则补充见 COMM-01。计划状态修改：必须，继承 IMPLEMENTATION_PLAN §8.4 用户授权。

来源：用户确认按“项目内自主执行、跨项目受控借阅”方案立卡。下述检查点是Agent派生任务，运行优先级层级1或以下，保留原始用户指导引用。

## 1. 目标与不做事项

每个次级及更低级Agent固定归属一个项目，默认只能读取和操作该项目内获准内容；跨项目仅提供只读查询和导入副本，来源项目不得被修改。上级角色、放权模式或切换工作目录均不自动取得其他项目权限。

首期不实现项目自动全盘发现、双向同步、无限转授权、跨项目远程写入或新IAM平台。复用项目根登记、具体Agent身份、权限执行门禁、受控附件、备份、独立反馈和恢复；仅新增所需的跨项目授权登记及校验。

开始编码前完整读取AGENTS.md指定四份治理文档、当前权限/作用域ADR和产品rollout。当前检查点先收口，次级确认公共文件所有者、commit/dirty基线后再接入；不得覆盖并行改动。本轮仅新增本卡，不改共享索引、旧卡或生产代码。

## 2. 固定项目归属

- 用稳定projectId标识项目，项目名和路径不是身份。登记允许根集合、真实路径及revision，检测重叠根和别名；歧义登记须裁决，不默认扩大范围。
- 每个次级及以下agentInstanceId绑定projectId、当前任务和有效权限；生命周期内不得悄悄切换归属。换项目创建新个体，显式选择附件交接，不复制全部记忆或授权。
- 同项目不同worktree由次级显式登记，仍执行各任务分配范围；不能将整个父目录加入项目来容纳其他仓库。
- 每次工具执行、搜索/列目录、读取、复制、Git、安装、命令及外部软件访问都按实际资源检查，不只检查cwd或字符串前缀。覆盖绝对路径、分隔符、链接/junction、真实路径变化、进程子调用和恢复入口。
- 进程工作目录不构成文件隔离。任意命令无法证明或限制其访问范围时，不得声称已隔离：使用现有受控能力/OS约束或拒绝该执行方式，不能仅靠提示词和路径参数检查。
- 公共工具链、已授权缓存等由本地控制面管理的资源沿用既有范围规则，不因此授予Agent任意浏览项目外文件的能力；本卡不把正常运行时依赖强行复制到项目内。
- 持久存档、模型上下文、缓存、搜索索引和历史查询仍按具体个体隔离。项目隔离是附加边界，不把同项目Agent合并为共享记忆域。

## 3. 两种跨项目能力

| 能力 | 操作范围 | 禁止事项 |
|---|---|---|
| read | 经受控服务读取指定来源文件/目录清单或固定版本摘要 | 不改来源；不自动获得持久导入、再分发或执行来源代码的权限 |
| import-copy | 经明确批准将指定版本内容复制至目标项目指定位置 | 不回写来源，不自动持续同步，不链接成可写的来源路径 |

导入副本后，其后续修改由目标项目正常权限管理。保留来源项目、资源、源revision/哈希、导入回执和目标版本，界面标记为副本。更新副本须重新核对授权、源版本及目标人工修改，禁止以“同步”静默覆盖；覆盖前自动备份。

read只表示工具不提供持久导入能力，不承诺模型或用户看到内容后绝不复制。模型可见内容不能获得数字版权式不可复制保证；强保密资料只返回允许的受控摘要/查询结果，不能用“只读”虚构信息不可传播。

默认读取固定来源版本。目录授权应绑定允许路径和已批准范围，新增文件不能无条件进入；用户明确设置的动态共享目录规则须单独登记，执行时仍检查内容策略及最新规则。

## 4. 授权来源与有效范围

### 用户直接授权

认证用户针对具体来源/目标、资源范围、read或import-copy、任务及期限授权。本地确认用户有权批准来源导出和目标接收，不将任意目标项目用户身份视为所有项目所有者。

### 用户预委托来源项目审批

用户可预设来源项目允许向哪些目标项目提供哪些资源、期限和用途。来源项目主Agent可在此范围内提出批准意见；本地控制面核验委托、身份、范围和revision后签发。主Agent不写权限文件、不生成可信令牌，不因角色天然拥有导出权。

主Agent未运行时，明确允许自动批准的确定性共享规则可由控制面直接处理；需要判断却没有有权审批者时排队，不启动未经授权的新模型或向其他项目绕路请求。

有效授权是来源可导出范围、目标可接收范围、接收Agent当前有效权限三者交集，deny优先。放权模式在用户预设共享范围内可自动通过，超范围仍询问或拒绝；“可配置权限默认allow”不自动创建项目间共享关系。

思索模式仅可使用其原有允许的只读能力；跨项目grant不授予写入、安装、执行或备份权限。主Agent的只读角色不变，导入执行由获准执行层承担。

## 5. 最小授权记录与生命周期

首检查点基于现有schema冻结字段，不新建重复身份系统。至少包含：

- grantId/revision、授权来源/审批依据、用户委托引用；
- 来源projectId和登记revision、目标projectId、具体接收次级/任务；
- 资源选择器及固定版本或经批准的动态规则、动作类型；
- 目标位置（import-copy）、生效/到期时间、撤销状态；
- 是否允许当前任务链内直属下级使用及父grant引用。

Agent仅接收不透明授权引用和公开范围说明，不接收可外传的凭据。请求ID绑定规范化完整参数；同ID异参拒绝，同ID同内容重试复用回执。访问前及返回/提交前复检有效revision，避免校验后撤销仍放出新内容；已传出的数据无法撤回。

次级可以在明确允许的当前任务链内派生更窄的三级授权，三级同理只能给该子链的四级；主体、资源、动作和期限不能变宽。该派生不是项目间转授权：A允许B借阅不等于B可以转交C。无权限复制、任务外再分发或转给同级Agent均拒绝。

任务结束、到期、用户撤销、关系解除或范围变化触发失效，具体规则在ADR冻结。重启重新校验，不恢复过期/一次性许可。授权等待不持文件、任务或项目锁，无关任务继续运行。

撤销停止后续访问并使缓存/待投递附件授权失效，不能抹掉已读上下文或自动收回已导出副本；向用户明确这一限制。因撤销需要清理副本或终止接收者时，另走受控操作，不能偷偷销毁用户产物。

## 6. 效率与避免交叉混乱

- 按任务批准一组明确资料，避免每个文件重复询问；预设单向共享规则可自动判定，拒绝/等待请求去重且不轮询模型。
- 优先提供有版本的项目接口摘要或不可变附件包，再按需展开细节，不复制来源全部历史。
- 共享规则声明具体来源→目标，不使用无限通配关系；首期不引入复杂组继承。
- 读取缓存按接收个体、来源版本和grant revision隔离，撤销/源更新精确失效；不能用别的Agent已读缓存绕过授权。
- 来源资料中的指令是数据，不成为接收项目的用户指导；来源项目无法通过文档命令目标Agent修改权限。
- A等B、B等A的请求不得持锁，控制面检测等待环并返回可读依赖说明；不能让双方通过重复转派规避拒绝。
- 并发导入同一目标需原子领取/目标revision检查；幂等回执防重复落盘，失败和结果未知按现有恢复对账，不无界重试。

## 7. 用户与Agent可见界面

最小“跨项目访问”列表展示来源→目标、接收Agent/任务、借阅内容摘要、动作、审批来源、有效期和状态。支持项目/任务筛选、查看回执、拒绝/撤销；主Agent可只读取得相关状态摘要。

待批准、已允许、已读取/导入、到期、撤销和失败分开显示。“已授权”不等于“已复制”；副本标记与原件区别清晰，不显示授权令牌或原始私密路径。CLI/TUI/GUI/SDK共用控制器及查询结果，不能各自形成不同授权逻辑。

### PROJECT-01-03 真实资源 I/O 接线（2026-10-10）

**缺口（本轮实测）**：`CrossProjectTransferService` 只做授权/回执判定——
`readResource()` 直接返回 `didRead: true` 却**从未读取资源**，`importCopy()` 只写回执
**从不写出副本** ⇒ "回执成立但目标里没有文件"，属**把回执当借阅/导入完成**。

**本轮接线**（`packages/core/src/orchestration/cross-project-authorization-store.ts`）：

- 新增可注入端口 `CrossProjectResourceIoPort`（`readTextFile` / `writeTextFile` /
  `ensureDirectory` / `fileExists`）。**未注入时不执行任何资源读写**：
  `readResource` 如实返回 `resource-read-failed`、`importCopy` 如实返回 `target-write-failed`
  ——**绝不伪装成功**（避免"有回执无文件"的假完成）。
- `readResource`：授权链全部通过后才触达资源；真实读取并返回 `content` / `contentHash`；
  **读取前后各取一次来源 sha256**（必须相等）作为"来源零写入"的**可核对证据**；
  支持 `expectedContentHash`，声明哈希与实际不符 ⇒ `content-hash-mismatch` 拒绝；
  资源不存在 ⇒ `resource-not-found`（不得谎报已读）。
- `importCopy`：授权校验 → 真实读取来源（含前后哈希）→ 原子认领回执 → **真实写出目标**
  （先建父目录）→ 写出后复核目标存在 → 落定真实回执；声明 `contentHash` 与来源实际不符 ⇒
  `content-hash-mismatch` 拒绝。返回新增 `didWriteTarget` 与来源前后哈希。
- 新增 `CrossProjectAuthorizationStore.releaseCopyReceiptClaim()`：写入失败时**释放未完成的认领**
  （否则占位回执会让重试被"幂等复用"挡住，而目标永远没有文件）。**只允许释放 `pending-` 占位回执**，
  已落定的真实回执一律不删（不放宽重放保护）。

**反例（先红后绿）**：新增 `tests/core/integration/cross-project-resource-io.test.ts` 8 条
（实现前 **7 failed**）；并把既有 `cross-project-authorization.test.ts` 中 4 条
"只看回执就算成功"的用例改为**真实文件** + 注入 I/O 端口（原断言在旧语义下才成立）。
两套件合计 **20/20** 通过。

**仍未完成（不主张 PROJECT-01-03/04 通过）**：SDK/GUI 入口尚未接线（CLI 已可用）；
多项目/多同级个体压力验收与包级验收仍待做。

### PROJECT-01-04 陈旧覆盖拒绝 + 公开入口（2026-10-10 续）

**缺口**：`importCopy` 接入真实 I/O 后只做"建父目录 → 覆盖写目标 → 复核存在"，
因此**会静默覆盖人工刚改过的目标文件**（卡内必测场景 2 明确要求"目标有人工修改时拒绝陈旧覆盖"）；
且 `readResource`/`importCopy` **没有任何公开入口**，产品上无法执行。

**本轮接线**：

- 新增可注入 `CrossProjectTargetHumanEditGuardPort`：目标已存在时先问"是否存在与预期副本不同的人工内容"。
  - 有人工改动 ⇒ `target-stale-rejected`，**不写目标、不落定回执**（避免重试被幂等挡住）；
  - **未注入守卫且目标已存在 ⇒ fail-closed 拒绝覆盖**（不静默覆盖人工字节）；
  - **守卫自身抛错 ⇒ 同样 fail-closed 拒绝**（宁可不导入）；
  - 目标不存在 ⇒ 正常写入，**不调用守卫**（避免无谓 I/O）。
- 公开 CLI 入口（`packages/tui/src/cli.tsx` + `commands.ts`）：
  - `astarray cross-project read`：真实读取；`read-allowed` ⇒ exit 0，其余一律非 0；
    未授权时**不回显来源内容**（只在 truly allowed 时输出 `content`）；
  - `astarray cross-project import-copy`：真实写出目标；`imported-copy`/`reused-existing-copy` ⇒ exit 0；
    声明哈希取自**来源实际内容**（入口不猜哈希）；提供 `--expected-target-content-hash`
    时才可判定人工改动。

**反例（先红后绿）**：

- `tests/core/integration/cross-project-stale-overwrite.test.ts` 4 条（实现前 **2 failed**）：
  人工改动拒绝且保留人工字节、目标一致不误拒、目标不存在不受影响且不调守卫、无守卫时 fail-closed；

  只读成功与参数不匹配拒绝、导入真实落盘且来源不变、目标被占且无基线时拒绝覆盖；

## 9. 必测场景与交付

1. 未授权跨项目读取、列目录、搜索、直接写入、命令间接读取及Git路径访问均不能绕过；覆盖Windows/POSIX路径与真实文件系统差异。
2. 用户精确授权read后可读不可导入/写源；import-copy只能写指定目标且不改来源；目标有人工修改时拒绝陈旧覆盖。
3. 有预委托的来源主Agent批准在范围内有效，无委托或伪造身份无效；放权模式不会凭空开启共享。
4. A→B可用不导致B→C可用；有权下级仅使用缩窄任务范围，回收/换任务后授权失效，同级不能继承。
5. 撤销与读取/导入竞态、缓存命中、并发请求、请求重放、过期、配置变更、重启和未知副作用均有明确结果。
6. 多项目等待环、审批者离线、资源不足和大量重复请求不死锁、不反复唤醒模型；无关项目仍可推进。
7. 原始证据/凭据/个体记忆不因项目资料共享泄漏；用户汇总界面不扩大模型读权限。
