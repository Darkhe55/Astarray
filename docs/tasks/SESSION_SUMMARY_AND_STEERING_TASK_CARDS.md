## 共同规则和实施顺序

开始实现前完整读取AGENTS.md要求的四份治理文档、设计依据、本卡及 [产品接线共同规则](./PRODUCT_INTEGRATION_ROLLOUT.md)。复用现有存档、T09A预算/回访、独立反馈、取消与恢复模块。核对当前动态证据，不凭历史done推断前驱可用。

推荐顺序：SUM-01 → SUM-02 → GUIDE-01 → EVENT-01。SUM-01需要T09A-R1/T07D-R1相关接线可用；GUIDE-01另需T07D-R2-02产品循环及T12A-R1恢复路径可用。离线检查点不要求等待真实Provider凭据。已开始的返修先收口，再领取这些新节点；完成后增量回归E2E-01，不覆盖原验收记录。

每轮只执行一个检查点，各卡内部按编号顺序推进；预计超过3小时继续拆分。时间、字节和计数变量必须带单位，布尔使用is/has/can/should，核心领域禁any。权限执行前校验、敏感禁读、备份、个体隔离和安装两阶段门禁沿用既有规则。

实现检查点先写行为反例，运行相关测试与npm run check；状态机/安全变更运行coverage及关键模块专项。交付检查点使用npm pack、node scripts/verify-package.mjs <实际tarball路径>、node scripts/smoke-install.mjs，并从公开入口验证，不只测内部类。性能和质量指标记录设备/模型/样本/分母，不能预填通过。

每检查点记录基线commit/dirty差异、入口与产物证据、实际命令及退出码、覆盖率、剩余条件、提交和推送结果。验收并本地提交后按常设规则推送，最多5次，失败记录下阶段再试。完成事件使用当前合法schema，补充证据另存引用。未实施节点保持pending；缺外部依赖仅阻塞相关节点。

## SUM-01：动态摘要索引与按需展开

状态pending；前驱为上述存档和应用接线。覆盖会话历史、工作存档、报告和延后文件，源码/媒体使用旁置索引，不改原格式。合并现有读取工具，默认summary，支持outline/section/detail。

摘要总长度无固定硬上限，依据对话长度和信息复杂度动态调整。不允许引入固定maximumSummaryLength或总token裁剪；单次返回与模型注入预算独立。长摘要分概览、主题和证据索引分页，不能为取一页扫描全文。

| 检查点 | 实施产出 | 验收条件 |
|---|---|---|
| SUM-01-01 | 登记未占用ADR编号，定义manifest、sourceRevision/hash、coverage、pending尾部、分块和cursor；动态详细度原型 | 长短、多分支、重复消息样本；摘要可增长且无固定总长裁剪；cursor绑定Agent/版本 |
| SUM-01-02 | 受控保存增量索引与原子发布，本地提取权威事实，后台生成叙述；旧文件迁移/外部变化失效 | 崩溃不出现新摘要指旧正文；pending生成可续跑；读取不触发全文重摘要；single-flight有效 |
| SUM-01-03 | 默认摘要与章节展开、分页、有界读取和来源校验 | 实测不读取原文或现场全文哈希；长摘要只读取索引及必要页；陈旧/跨Agent cursor拒绝；可定位原证据 |
| SUM-01-04 | 应用/CLI/现有TUI接线、安装包消费与资源指标 | 从包读取大历史摘要再展开；记录磁盘I/O和模型返回量；资源不足不丢正文且状态诚实 |

更新以新增内容量和阶段检查点触发，具体阈值由01测量决定。动态摘要不能退化成全文副本；通过信息覆盖、重复率和任务回访质量验证，而非硬性长度限制。

### SUM-01-04 进展（2026-10-10）：补齐另外三类来源适配器

卡内 §SUM-01 首段要求摘要"覆盖**会话历史、工作存档、报告和延后文件**"。
实测：`SummarySourceKind` 类型虽已含 `conversation`/`report`/`deferred-file`，
但 `summary-source-adapters.ts` 里**只有 `buildWorkArchiveSummaryEntries`**——
即**类型写了、能力没实现**（前几轮同一类缺口：公开导出/参数校验被遗漏）。

本轮补上三个纯函数适配器，纪律与工作存档适配器完全一致：

| 适配器 | 来源标识（可回溯） | 关键语义 |
| --- | --- | --- |
| `buildConversationSummaryEntries` | `会话#轮次` | 确定性排序、revision 从 1 单调重排、不改写正文 |
| `buildReportSummaryEntries` | `报告#任务` | 同上；重复报告不得双计 |
| `buildDeferredFileSummaryEntries` | `文件#起始行-结束行` | **同文件不同行区间是不同条目**（不得因文件相同而合并） |

共同保证：**确定性内容哈希**；**重复条目不得双计**（重读/重放不灌水）；
结构非法项**跳过**且不中断整批；空输入 ⇒ 空结果（**不伪造**条目）。
四类适配器已由 `public-sdk` 公开导出（含类型），并从**构建产物**实测可达。

- 反例（先红后绿）：`tests/core/unit/sum01-source-adapters.test.ts` 9 条（实现前 9 红）。
- **仍未完成**：会话历史/报告/延后文件的**真实数据源接线**（目前适配器可对条目化输入工作，
  但尚未从会话事件流、报告存档、延后文件存储真实取数）、旧文件迁移、触发阈值测量、
  多设备/多规模重复测量 ⇒ **不主张 SUM-01 通过**。

## SUM-02：跨模型预算与摘要事实可靠性

状态pending；前驱SUM-01。持久化用完整消息/段落/决策及稳定ID；token仅用于目标模型本轮预算。事实来源与模型推断分开，保留冲突、否定、单位、适用条件和unknown。

| 检查点 | 实施产出 | 验收条件 |
|---|---|---|
| SUM-02-01 | 计量适配端口与来源schema，区分Provider/模型/tokenizer/序列化版本，未知时保守估算 | 中英文、emoji、代码、数学/单位样本；无统一字符/token准确性声明；无隐式联网计量 |
| SUM-02-02 | 完整请求计量与包装/输出预留，选入完整记录，模型切换重新计量 | 只分页/调整本轮选入内容，不裁剪存档摘要；全局4096可调规则保持；必要约束放不下则blocked/拆分 |
| SUM-02-03 | 权威字段本地提取，叙述引用证据，依据原始分块重建摘要 | 引用存在不等于语义正确；对照原文检查事实支持、关键遗漏、错误归因；不能仅摘要再摘要 |
| SUM-02-04 | 内容缓存与计量缓存分离；真实产品请求捕获及tarball联测 | 换模型不重写历史；指标可复算；人工标注样本评估质量，不能用生成模型自评通过 |

保留estimated与实际usage区别。降低token不保证降低幻觉；没有充分样本时如实写明，不能虚报改善百分比。

## GUIDE-01：运行中指导与安全点

状态pending；前驱SUM-02、T07D-R2-02、T12A-R1相关路径。首期来源为认证用户、已注册本地工具及文件/任务状态监测。三档行为：仅记录、安全点指导、立即门禁并请求暂停/取消；本卡落实前两档及第三档协议，EVENT-01通过后开放紧急仲裁。

| 检查点 | 实施产出 | 验收条件 |
|---|---|---|
| GUIDE-01-01 | 事件来源/资源/任务作用域、sequence/有效期、指导revision及工具取消能力契约 | 伪造、过期、乱序、重放、跨作用域反例；紧急等级不篡改task priorityTier |
| GUIDE-01-02 | 独立反馈机制中的控制队列/IPC入口，在模型调用和工具前后安全点应用指导 | busy期间即可应用修正，不等整链结束；普通报告不唤醒主Agent；同指导幂等应用 |
| GUIDE-01-03 | 长工具检查点和协作取消，保存回执、收敛旧请求、新请求承接指导 | 不假定Provider允许在途插入；未知停止结果blocked；旧完成声明失效；watchdog不误续跑旧指令 |
| GUIDE-01-04 | 公共应用/CLI/现有TUI提交指导并查看接收/应用状态 | 安装包长任务中途修改目标后行为实际改变；普通指导可继续，主Agent仍只读；记录延迟 |

默认只影响指定任务/资源；依赖传播须显式关联。人类指导由本地控制面路由，次级负责重排，模型仅接收必要差异。旧请求未收敛不得让新的写者争用同一资源。

## EVENT-01：紧急事件仲裁、中断与恢复

状态pending；前驱GUIDE-01。通用事件由本地执行门禁先阻止新操作，再按工具能力取消/暂停、确认和对账。事件紧急性不授予新权限。

| 检查点 | 实施产出 | 验收条件 |
|---|---|---|
| EVENT-01-01 | incident生命周期、资源仲裁与抢占关系、适配器能力协商；原型测合并窗口/队列/抢占限额/确认超时，决定监督进程隔离 | 同资源单一所有者；域规则留给适配器；响应期限不能满足时明确降级，不凭字段承诺实时 |
| EVENT-01-02 | 绕过idle/pn的控制通道、executionEpoch门禁、工具能力取消及分阶段确认 | 收到事件不等于已停止；旧epoch调用/适用提交拒绝；在途副作用须确认；不统一kill、不绕过授权/备份 |
| EVENT-01-03 | 同故障合并、严重升级抢占、同级排队；限额/背压/锁序/短事务/公平性 | 风暴不乒乓切换；独立危险不丢；限额耗尽保持暂停但继续接收事件；无循环等待；旧租约失效仍须fencing |
| EVENT-01-04 | 解除条件、权限/产物/回执/上下文对账、恢复策略；崩溃重放与安装包状态入口 | 未解除不自动继续；自动/用户确认恢复可配置；不能代替专用授权；无重复副作用；反馈故障明确降级 |

状态区分interrupt-requested、quiescing、suspended、handling-incident、reconciling和恢复终态。由本地控制器仲裁、次级安排处理者。正常指导可自动继续；紧急事件解除且对账通过后按用户策略恢复。取消超时不能当作成功停止。

记录接收→门禁、取消请求→工具确认、收敛→恢复的p50/p95/p99和最坏观测值，附设备、并发与队列规模。锁等待/处理无进展必须有界；公平性不能强制让未解除的紧急状态恢复普通执行。
