# SMART-01：智能指令窗口与主 Agent 响应期限

日期：2026-10-01；2026-10-10 对账状态：in_progress。02/03 队列与分类组件已有证据；04 公开导出、概览入口和独立持续接收实验不等于窗口实际驱动模型的四入口闭环，接线/包场景继续验收。计划状态修改：必须，继承 IMPLEMENTATION_PLAN §8.4 用户授权。

## 1. 目标与关联

用户要求在队列、引导之外增加智能模式，默认同时处理三个指令；完成部分指令后自动补位；缺失完成信号时有兜底，但必须区分早停和需要用户澄清；主 Agent 单条用户指令须在三分钟内处理并派发，不阻塞持续交流。

复用 GUIDE-01 的安全点和指导回执、完成验收/早停看门狗、独立反馈、任务偏序集及 T12A 恢复。不新增第二套任务调度器。指令窗口控制上下文中已准入且未处理结束的用户意图数量，不等于模型并发数、下级数量、token预算或项目任务完成数。

开始编码前完整读取 AGENTS.md 指定文档、相关当前 ADR 和 rollout。当前编码检查点先收口，再由次级核对公共文件归属及最新实现后接入；本轮不改写既有卡或生产代码。实现方案为 Agent 派生节点，保持层级1或以下及用户原始指导引用。

## 2. 三种模式与指令计数

| 模式 | 行为 |
|---|---|
| 队列 | 用户指令持久化等待，按明确的可接收边界领取，不自动插入当前工作上下文 |
| 引导 | 提交既有指导通道，在下一可用安全点应用；不谎称已插入正在生成的 Provider 请求 |
| 智能 | 活动指令少于上限时走引导；达到上限时排队；已有指令有效关闭后自动补位 |

- 设置 `maximumActiveInstructionCount`，默认3，正整数；沿用项目默认与会话覆盖。资源限制单独标明，不暗中改变用户设置。
- 每条已接收用户消息默认一个指令信封，包含 instructionId、会话、来源、稳定序号、revision、目标及接收时间；模型拆出的内部任务不能用来规避窗口计数。界面支持用户明确拆分/批量提交，显示各条指令。
- 一条指令可以对应多个任务节点，但关闭前须解释其处理范围；不依赖自然语言“完成了”判断。修订绑定原指令，新版本使旧完成回执失效；模糊追加还是新任务按 GUIDE 规则澄清。
- 准入预留、实际应用及补位原子化；已预留但未应用同样占位，避免快速连发超限。接收/准入/已应用/等待澄清/关闭分别显示。
- 队列按显式前驱和稳定顺序从可执行项中选择，用户可重排但不能越过依赖；与任务偏序集优先级保持一致，不把智能模式当作紧急抢占权限。
- 上限降低不驱逐在途指令，只停止补位直到降至范围内；提高后按容量补位。切换模式保留所有回执，不重投已应用指令。
- 指令数不替代上下文预算；三条超长指令也须分块/摘要/澄清，不能全部强塞入模型请求。

## 3. 完成与窗口推进

模型提交版本化的指令处理回执：指令 ID/revision、处理结果、关联任务/证据引用、未决问题；具体 schema 在首检查点结合现有完成协议冻结。回执是候选，本地核对当前版本、未决调用和任务关联后才能释放槽位。

对于主 Agent，“已处理”指已解释/回答用户，或设计指导已由本地控制面持久化插入下级任务列表并取得可追溯回执；不要求下级工作已完成。UI 必须区分“已派发”与“工作成果完成”。对于执行 Agent，关闭标准仍是它获得的任务/指令验收条件，不以派发子任务自动冒充完成。

允许乱序关闭独立指令：2号完成可以释放一槽，1号未完成仍保留。原始顺序和依赖可追溯，补位不是丢掉队头历史。取消/被替代由授权用户或合法控制事件记录，不自动当成完成。

## 4. 模型停止与缺失信号兜底

这里的停止指一次模型运行/输出停止，不是用户关闭会话或应用。

| 本地判定 | 后续处理 |
|---|---|
| 正常结束且指令关闭回执有效 | 释放已关闭槽位，按剩余容量提交后续指导 |
| 有独立权威证据表明已处理，但模型漏回执 | 本地依据派发/验收记录补记闭合依据后补位，不能仅凭 stop 原因推断完成 |
| 缺回执且无法确定，或属于早停 | 保留窗口，优先有界追问当前指令状态/续跑旧任务，不注入无关新指令 |
| 明确等待用户细节 | 使用下节的澄清参考机制；未解决时保持等待，不机械续跑 |
| 权限等待、预算耗尽、计划休息、紧急暂停 | 服从原门禁，不用补位绕过；解除后重新对账 |
| 用户停止/关闭、取消或异常断连 | 不自动重开会话；异常按恢复机制处理，未知副作用先对账 |

兜底“自动输入剩余指令”仅指确认有可用槽位且允许继续后，按窗口有界提交尚未应用的指令；不一次灌入整个队列，不重复在途指令，不伪造新用户消息。每次补位记录原始来源和自动投递原因。

缺失信号的状态确认与早停续跑共享任务级预算，重启不重置；达到既有限额后报告阻塞并保留队列，不无限请求模型继续。

## 5. 等待澄清时参考后续指令

- 明确记录待答问题 ID、缺少的字段及所属活动指令；先用本地索引选择相关的后续指令摘要，在用户开启的“允许后续指令辅助澄清”选项下供模型参考，推荐默认开启。
- 参考不等于准入执行，不占用新的活动槽位，也不能作为第四条任务偷偷执行。只提供相关有界片段，并标注“仅用于判断是否回答现有问题”。
- 模型返回“包含答案/部分包含/不包含/有冲突或不确定”，并给出原始指令 ID、revision、引用片段、问题字段映射。模型判断不能当作确定事实；本地验证来源/版本/范围，不能自行补全未出现答案。
- 完整且无冲突时，把解答片段关联到原活动指令，继续原任务；部分回答只补足已知字段，仍询问剩余问题；不包含或含糊则停止推进并等待用户。
- 后续指令同时包含答案和新工作时，仅使用答案，剩余工作继续排队；纯回答信封可标记“已作为澄清答复使用”，不能丢掉混合信封中的任务要求。保存片段使用回执，防后续领取时重复执行。
- 密码、授权、扩大权限或改写目标等不得由语义匹配代替对应明确裁决。多条相互矛盾的回答必须询问，不能自行择一。
- 相同问题/候选 revision 组合只检查一次；无新增信息不轮询模型。新的用户补充或明确修订到来才重评，防止等待态活锁和上下文膨胀。

## 6. 主 Agent 三分钟响应与不阻塞

设置本地 `mainInstructionHandlingDeadlineSeconds = 180` 作为单条用户指令处理期限，自本地接收起计时，包含智能队列等待，不能在取出队列时重新计时掩盖积压。批量指令分别记录期限。该期限约束主 Agent 的理解、必要答复、任务提案及控制面持久派发，不要求下级三分钟交付成果。

- 主 Agent 不等待下级完成、测试、Git 或外部网络长操作，具体研究/实施交给次级；主循环与后台执行、反馈、用户输入接收解耦。
- 可明确派发的任务必须在期限内取得控制面接收回执；发出文字“已交办”不算派发成功。主 Agent 只提出候选，本地控制面处理任务插入，不给主模型新增写工具。
- 有歧义、权限缺失或依赖用户选择时，期限内提出具体问题/阻塞说明，释放主 Agent 处理占用；原指令仍标等待而不是虚报已派发。
- 本地期限监督独立于模型，接近期限优先要求有界收口/派发；超时标违约并向用户展示排队/Provider异常原因，不假造设计、强制不安全派发或启动两个竞争主 Agent。
- 连续输入、慢 Provider 或资源故障下不能承诺所有指令无条件180秒完成：本地入口始终可接受、持久化和显示排队，并以逐条超时状态揭示未达标。队列有容量/磁盘背压时明确拒绝接收并保留用户输入，不假回执。
- 智能窗口满且不能合法释放时，不为了三分钟目标越窗；提示积压，用户可提高窗口、修订、取消或改模式。明确区分“应用已接收”和“主模型已处理”。
- 工作时段规则优先于自动模型执行；休息期间即时本地回执并显示下一可处理时段，不谎称满足180秒模型处理目标。用户可明确临时恢复对话，不自动启动后台工作。
- 用户可随时提交取消/暂停和配置变更，这些控制请求走本地控制通道，不占普通业务指令窗口；普通任务不能自称紧急绕过窗口。

## 7. 实施检查点

| 检查点 | 产出 | 验收 |
|---|---|---|
| SMART-01-01 | 现有 GUIDE/完成/恢复链路审计、ADR、指令状态和窗口契约 | 明确计数/关闭/部分处理/期限语义，与 task done 区别清楚；不新建任务调度器 |
| SMART-01-02 | 持久队列、原子准入/回执/补位、模式及窗口设置 | 上限3时第4条排队；重复/乱序回执、降上限、同键异参、并发连发和重启无重复投递 |
| SMART-01-03 | 早停分类、漏回执兜底及澄清参考 | 早停不注入新工作；无答案保持等待；仅抽取答案；混合信封保留剩余任务；停止/休息/授权不被绕过 |
| SMART-01-04 | 主 Agent 期限监督、持续接收、SDK/CLI/TUI/GUI入口和包验收 | 模拟慢模型/长下级任务仍能接收新指令；180秒内派发或如实超时/待澄清；关闭回收，UI状态不冒充成果完成 |

每次执行一个检查点，超过三小时再拆分。依赖现有指导安全点、权威任务状态和恢复能力的真实接线证据，未满足前驱先登记，不靠历史 done 推断。

## 8. 测试与度量

先反例后实现。使用虚拟时钟和可握手假 Provider/工具，覆盖正常完成、自然 stop 但无回执、工具在途、取消确认未知、澄清、不相干后续内容、矛盾回答、完成与追加竞态、旧revision、用户关闭、离线、磁盘失败和主进程重启。

至少一条公开安装包路径演示：输入1/2/3进入活动窗口→4/5排队→2完成→4准入→1询问细节→5中只有回答片段辅助1→5剩余任务仍排队；另外证明早停不引入4/5。片段引用和指令来源全程可追溯。

测量接收→确认、接收→模型处理、接收→控制面派发的延迟及180秒违约数、窗口超限次数、重复注入次数、澄清匹配错误、额外模型请求/token与未处理指令数。附负载/样本/平台，不以快速本地回执冒充模型响应达标。

运行定向测试、npm run check、状态机/隔离专项覆盖率及当前安全门禁；交付 npm pack、verify-package.mjs 和 smoke-install.mjs。安装、权限、命名、自动备份、独立反馈及个体记忆隔离遵循当前规范。完整完成事件使用合法schema，不任意向已有协议塞字段。

记录commit/dirty基线、命令退出码、包哈希、真实入口证据与剩余限制。次级在共享文件安全可编辑时更新索引/状态；验收及本地提交后按常设规则推送，不夹带其他Agent修改。
