## 1. T08C：主对话独占、次级直投与四级委派

### 冻结行为

- 主 Agent 是唯一连续用户对话者。用户默认发给主 Agent。
- “直接交由次级执行”是主会话内的任务投递动作，不是聊天切换。认证用户确认后，原始用户任务信封直接进入具体次级 Agent 的偏序集；结果默认由次级总结给主 Agent，再由主 Agent解释给用户。
- 用户任务保持优先级层级 0；次级拆出的 Agent 来源任务只能位于层级 1 或以下。
- 次级负责项目细节、详细规划、三级任命、项目级 Git 集成及返修/合并裁决。
- 次级需要项目上下文时，派出只读侦察三级 Agent，只接收有界摘要，不接收项目全文。
- 实现者不得验收自己。高风险任务的实现、测试、验收必须由三个不同具体 Agent 承担。
- 三级可以把自己的严格子链交给四级；四级不能创建第五级。项目级最终合并仍只属于次级。

### 检查点序列

| 检查点 | 内容 | 依赖 | 主要验收 |
|---|---|---|---|
| T08C-01 | 四层角色、关系、任务信封、摘要、侦察和裁决 schema | T08A/T08B/T05B/T05C/T06G/T10/T11 通过 | schema 反例、迁移、冻结决策测试 |
| T08C-02 | 小任务资格策略、用户确认、具体次级直投和歧义回退 | T08C-01 | 主 Agent 未被调用；来源/优先级/授权不丢失 |
| T08C-03 | `SECONDARY_USER_FACING_SUMMARY_V1` 与主 Agent 细节查询 | T08C-02 | 后台不自动唤醒主 Agent；摘要可追溯且不漏风险 |
| T08C-04 | 侦察型三级 Agent 与 `PROJECT_CONTEXT_DIGEST_V1` | T08C-01 | 大仓库摘要、stale、增量复查、敏感禁读 |
| T08C-05 | 实现/测试/验收任命及 rework/merge/human-review 门禁 | T08C-03/04 | 作者自验被拒；提交变化使旧验收失效 |
| T08C-06 | 四级生命周期、权限求交、工具帮助和 Git 子分支集成 | T08C-05 | 无第五级；四级不越权；三级不能向项目级分支合并 |
| T08C-07 | TUI/CLI/GUI 投递与状态视图、真实进程及 tarball 验收 | T08C-06 | 三入口一致；主 Agent 对话目标提示清晰 |

一次只执行一个检查点。若单个检查点预计超过约 1,000 行生产代码，先拆出 schema/领域控制器、持久化/恢复、界面/集成三个可独立验收节点，不得降低验收条件。

### 必测场景

1. 符合资格的小任务直投指定次级，不调用主 Agent模型规划；用户仍停留在主会话。
2. 任务有方案歧义、跨项目影响、公共契约修改或高风险未决裁决时，推荐关闭或无损回到主 Agent。
3. 次级汇总上百条下级报告时，主 Agent只接收有界摘要；来源、风险、失败和用户裁决事项不得因压缩消失。
4. 用户追问细节时，主 Agent按具体任务/revision查询负责次级；次级不知道时明确返回未知，不伪造答案。
5. 侦察 Agent只读普通项目范围，不能读取 `.env`、凭据、备份或越界路径；重复读取保护继续有效。
6. 实现、测试、验收身份隔离；高风险任务复用同一身份会被本地门禁拒绝。
7. 人工交互体验尚未完成时只能 `blocked-human-review`，无人时段可继续执行不依赖该裁决的其他 ready 节点，但不能合并被阻塞产出。
8. 四级权限、工具、附件、任务范围和期限是三级严格子集；四级不能访问兄弟或上级长期记忆。
9. 四级 Git 提交只进入所属三级任务分支；三级不能推送、变基、删除分支或向项目集成分支合并。
10. 四级首次工具说明、后续帮助请求及逐级上报按具体 `agentInstanceId` 隔离。

## 2. T07C：独立模型/Provider 与任务类型预设

### 冻结行为

- 每个主/次级/三级/四级 Agent 单独拥有模型分配，不共享可变选择状态。
- 用户允许列表是硬上限；Agent可在列表内独立选择或在安全检查点切换，用户可固定模型。
- 用户可以建立任意长度的用途模型列表和任意数量的命名任务预设；产品不得设置硬编码数量配额。
- 模型选择不授予工具或权限，模型切换也不改变身份、记忆、任务和 Git 职责。
- Provider凭据、完整 prompt、内部 endpoint、令牌和一次性授权不得进入公开配置、日志、反馈或导出。

### 检查点序列

| 检查点 | 内容 | 依赖 | 主要验收 |
|---|---|---|---|
| T07C-01 | Provider/模型目录、公开 DTO、受保护凭据引用 | T08D 通过 | 凭据泄漏反例、revision 和迁移测试 |
| T07C-02 | 用途列表、层级/个体覆盖和确定性策略解析 | T07C-01 | 六级优先级、任意长度、fail-closed |
| T07C-03 | 每 Agent 独立分配、安全检查点切换与事件 | T07C-02 | 并发隔离、未决调用阻塞、身份/权限不变 |
| T07C-04 | 有界 fallback、Provider 健康、数据出境和活锁保护 | T07C-03 | fake-provider 故障矩阵、列表耗尽阻塞 |
| T07C-05 | `TaskAgentPreset` 内置建议类型和无限自定义类型 | T07C-04 | 办公/前端/编码/debug/测试/验收/侦察/工匠/绘图动态测试 |
| T07C-06 | TUI/CLI/GUI 设置、导入导出、隔离打包验收 | T07C-05 | 大列表分页/搜索、三入口一致、tarball 安装 |

### 必测场景

1. 多个 Agent 并发使用不同 Provider/模型，任一 Agent切换不改变其他 Agent状态。
2. `fixed`、`ordered-fallback`、`automatic-within-list`、`manual-each-run` 行为确定且可审计。
3. 任务显式设置、具体 Agent会话覆盖、任务预设、用途列表、层级默认、会话默认按固定顺序解析。
4. 限流、超时、能力不匹配、模型禁用、目录 revision 变化和 Provider故障只在有效允许列表内有界 fallback。
5. 有未决工具调用、未确认副作用或并行 Provider请求时拒绝切换；恢复后不重复非幂等动作。
6. 绘图预设缺少视觉模型或绘图工具权限时阻塞；工匠用途不能使其在阶段前披露，办公/编码/工匠预设也不能绕过 Assist 安装双重门禁。
7. 导出只含公开稳定 ID、显示名和策略，不含凭据、会话令牌、完整 prompt、健康探针或内部执行细节。

## 3. 人工验收与无人时段

- 自动测试、静态检查、构建、fake-provider、真实独立反馈进程、Git worktree 和 tarball 测试先全部完成；人工只验收自动化无法可靠判断的交互理解、信息层级和操作体验。
- 人工验收节点进入 `blocked-human-review` 后，不占用执行 Agent轮询等待。调度器继续选取与该裁决无依赖的 ready 节点；依赖该裁决的合并和发布保持冻结。
- 人工体验脚本至少验证：主 Agent身份始终清晰、小任务直投不会被误解为切换聊天、次级摘要对非技术用户可理解、展开技术细节时来源仍可追踪、大规模模型列表可搜索和辨认。
- 用户拒绝、要求返修或长时间未处理不会自动转为通过。人工裁决必须绑定任务 revision、构建/提交哈希、界面版本和验收人来源。

## 4. 通用执行和停止条件

- 等待/退避量 `pn` 每次最多 3 小时；这不是任务 TTL，也不是丢弃反馈的理由。
- 同一失败连续三次后停止机械重试，保存最小复现、日志、已尝试方案和未决风险。
- 生产变量/函数名使用完整可读语义；布尔值使用 `is/has/can/should` 前缀，时间量名称明确单位，核心领域代码禁止 `any`。
- 任何删除、文字删减、替换、截断或覆盖必须先由执行工具自动备份；模型不得自行读取备份内容。
- 每个检查点运行针对性测试、`npm run typecheck`、`npm run lint`；任一高风险主任务完成后运行 `npm run check`。T07C 完成后还必须执行 tarball 隔离安装。
- 未获得真实命令、退出码、测试数量、覆盖率和变更审查证据时，不得标记完成。
