# TOOLKIT-01：项目工具孵化、用户级复用与通用工具包

日期：2026-10-10。状态：pending；本卡完成方案布置，不代表工具生成、推广或执行功能已启用。

**计划状态修改：必须，用户已授权。** 实施者开始、阻塞及交付时须更新本卡检查点、PLAN_STATUS 当前有效表及必要索引；依 IMPLEMENTATION_PLAN §8.4 记录证据范围和并行冲突，不能以未单列文档授权为由拒绝同步。不得覆盖其他 Agent 的工作。

## 1. 目标、依赖与非目标

将重复且值得复用的工作沉淀为可验证的项目能力，再把符合用户习惯或足够通用的部分推广。工具实现可复用，权限、项目数据和 Agent 记忆不随工具继承。

先完整读取 AGENTS 指定治理文档、本卡与 PRODUCT_INTEGRATION_ROLLOUT；核查以下实际接线，不凭历史 done 判断前驱：

- T08D 工匠预设与 `CRAFTSMAN_WORKFLOW_BUNDLE_V1`：复用阶段披露、已有授权工具组合、独立验收，不新增 Agent 层级。
- MERGE-01：复用能力族/action/格式适配、统一工具授权与参数级规则，不建立第二套权限编辑器。
- NODECTX-01、SUM、工具说明回访：按需读取工具说明，原文保留，不压缩或覆盖历史。
- PROJECT-01 / COMM-01：跨项目只读、显式借阅/导出与来源追踪；推广不是跨项目写通行证。
- EXP 的等价折叠：可提供候选建议，但实验性自动发现默认关闭。用户明确请求保存工作流不依赖自动发现开启，也不自动启用实验功能。
- RELIABILITY：复用幂等、未知副作用对账、备份及恢复；相关已知严重缺口先返修。

本批不做公共市场、远程自动安装/发布、自动跟随全局最新版、工具自我改写、无限递归或跨设备同步。第一版使用已有已授权工具组成工作流；确定性脚本工具的受控扩展见检查点 05，不允许直接放开任意 shell。

## 2. 三类产物，不把一切都变成工具

| 类型 | 适用情形 | 实现与调用 |
|---|---|---|
| 方法/技能模板 | 审查清单、排错方法、报告习惯，需要模型判断 | 按需加载说明；本身不获得执行权限，不为其新增工具名 |
| 工作流配方 | 已有工具可完成的稳定多步操作 | 有界偏序步骤与输入输出映射，通过现有工具执行网关调用 |
| 确定性程序工具 | 高频检查、格式转换、代码生成，普通工具组合成本过高 | 受控实现＋明确 schema＋独立执行边界，按检查点 05 启用 |

次级发现候选后先检索目录：优先参数预设、已有适配器或工作流；确有缺口才创建新能力。相似名称不证明功能等价，合并前核对副作用、输入输出与失败语义。

收益判断不设机械重复次数门槛：记录预计复用次数、单次节省、构建/验证/维护成本及不确定性。自动发现只提案，不按高频日志自动批量造工具；自动节点保持 Agent 来源和优先层级 1 或以下。

## 3. 项目内生成与启用流程

1. 用户明确要求“保存该流程”或次级提出有证据的候选；用户任务与 Agent 提案来源区分。
2. 次级记录目标、已有工具检索结果、适用范围、预期收益与验收标准。
3. 通过现有工匠披露/生命周期入口生成草案；不因本卡在所有会话启动时暴露休眠工匠。显式用户请求可走已有手动披露，披露不构成安装或执行授权。
4. 工匠只读取允许资料，组合已授权基础能力；生成文件与执行新文件是不同操作。草案不在生产发现列表内，不自动执行。
5. 不同 Agent 测试和验收；高风险实现/测试/验收三个个体分离。测试只用隔离 fixture，不默认触及真实项目或外部系统。
6. 次级核对证据，按有效项目策略登记并启用；若现有策略要求用户裁决则等待。未启用包只能被查看，不能调用。
7. 后续任务按项目、用途、权限与版本发现工具；实际每次执行仍检查权限及完整参数。

状态最小集合：draft → validated → enabled；失败标记 rejected，已启用版本可 disabled/deprecated。推广候选是独立记录，不把原项目版本直接变更为全局可见。注册、启用、调用与验收分别记账。

## 4. 能力包与身份契约

复用/扩展现有 bundle，而不是新建互不兼容的包协议。首轮冻结必要字段：

- `toolPackageId`、`version`、内容哈希、schema 版本、类型、可读名称、用途与适用条件。
- 来源项目、生成者具体 `agentInstanceId`、验收者及证据引用；不得只保存角色/模型名。
- 输入/输出 schema、受支持 action、实现/配方文件清单、入口与依赖锁定信息。
- 能力需求：动作、资源范围、参数规则引用、副作用、超时/取消、幂等与失败恢复契约。
- 所需 Astarray/基础工具版本范围、平台、验收过的运行环境和明确未支持条件。
- 发布范围、来源授权/导出记录、状态与 revision；不包含凭据、授权 nonce 或个体私有记忆。

名称不是路由键。调用固定 ID＋版本＋哈希；同名包显示来源和版本，禁止自动选“最新同名工具”。已启用内容不可原地修改，代码或依赖改变生成新版本；运行前校验实际文件与登记哈希，拒绝校验后偷换内容。

建议目录为项目专属受控工具库和客户端用户工具库，确切路径由本地存储契约决定，不散落到系统全局目录。依赖可沿用 npm lockfile 思路，但工具包不要求发布 npm，也不自动下载依赖。

## 5. 推广：项目专用 → 用户级 → 通用包

| 范围 | 含义 | 必要门禁 |
|---|---|---|
| project | 仅来源项目可发现/使用，允许项目适配 | 项目内测试、独立验收与启用 |
| user | 用户自己的跨项目工具库，不是所有人可用 | 用户确认分享范围、导出内容检查、去项目化、新版本独立验收 |
| portable | 可导出的通用能力包，不自动联网发布 | 多种隔离项目 fixture/适配测试、兼容性声明、依赖与授权需求说明 |

推广步骤：从已验证项目版本提出候选 → 选择最小必要文件/规则 → 检查项目数据和权利范围 → 分离通用逻辑/项目配置/用户偏好 → 新候选包验收 → 用户批准入库 → 目标项目显式启用并固定版本。

- 用户级与通用推广不自动发生，运行频次或模型“认为通用”仅能产生提案。用户批准推广不代表批准在所有项目运行。
- 不带出项目源码片段、绝对路径、私有配置、私有记忆、凭据和一次性授权。需要保留的素材必须有明确导出范围；声明来源不等于取得导出权。
- 跨项目只读取批准的来源包，目标项目运行自己的固定不可变副本/受控内容寻址引用；不得直接执行来源项目可变工作目录文件，也不得修改来源项目。
- 目标项目只取得明确授予的能力，不能通过工具包回读来源目录。推广包若仍依赖来源项目，应留在项目专用状态或把该依赖改成显式授权输入。
- 通用标记只是已验证适用范围，不承诺所有语言、框架、平台都可用。至少用两个结构不同的隔离项目证明去项目化；不要用真实另一个项目作为默认测试资源。

## 6. 通用执行逻辑、项目适配与用户习惯分离

示例“生成测试报告”：通用逻辑负责解析/统计；项目配置指定框架格式和允许的结果文件；用户偏好指定中文、先结论后细节等表现形式。偏好不改变权限、安全行为或验收事实。

配置优先级首版固定为：包默认值 → 用户偏好 → 项目适配 → 本次显式非安全参数；都经 schema 校验。安全范围不参与这种后写覆盖，始终走权限求交。

提供偏好预设的命名、查看、选择及版本引用；修改偏好不自动改写已执行任务，也不必重发工具实现。工具调用记录实际配置 revision。模型沟通教训仍按 LESSON 的具体模型/参数匹配，不混为通用工具默认行为。

## 7. 执行权限与防止工具包提权

有效权限 = 调用者当前权限 ∩ 项目边界 ∩ 工具/action/参数规则 ∩ 专用门禁。工具作者声明不构成授权；工作流每个内部步骤仍通过同一个本地执行网关，批准外层不自动批准所有内层动作。

- 复用 MERGE-01 设置：单工具统一 deny/ask/allow、参数授权总开关、每工具细分开关和规则列表。按 action 与规范化参数判断副作用；含写动作的能力不能整体标为 readonly。
- 安装、备份删除等重要许可逐项独立说明，不能藏在批量工作流里。参数变化、版本/哈希、profile revision、资源范围或权限需求变化均重新判定；旧批准不自动沿用。
- 方法模板或脚本中的自然语言仅为不可信任务资料，不能修改来源身份、授权或系统规则。主 Agent 仍只读，次级及下级不因获得工具包而提权。
- 程序工具不能凭 `readOnly` 自声明成为安全工具。纯转换优先通过显式输入数据和隔离输出运行；涉及文件/进程/网络必须经过可强制执行的沙箱与受控 broker，不能仅靠提示词或静态扫描。
- 若目标平台无法兑现所需隔离，拒绝启用程序工具并报告不支持，保留已有工具配方路径；首版不增加任意脚本后备入口。生成脚本不授权安装其依赖，先询问已有资源并遵循安装门禁。
- 运行时有界依赖深度/执行预算、取消与回执；拒绝工具包调用环和自我更新。无副作用失败可按规则重试，结果未知先对账，不重试未知写入。

## 8. 版本、更新、回滚与故障

- 项目锁定确切版本和哈希，不自动随用户库升级。新版本展示行为、依赖和权限差异；新增副作用须重新授权，旧项目继续使用旧版。
- 启用/停用/锁定变更按 revision 原子提交。停用阻止新运行，在途调用按安全点取消/收敛，不能删掉运行中的文件造成结果未知。
- 回滚只切换后续使用版本，不撤销历史副作用；数据恢复使用现有备份工具并按权限处理。备份删除仍走独立入口。
- 包内容损坏、依赖缺失、旧结果不兼容时明确失败；记录调用 run ID、步骤 ID、版本、参数哈希与来源、实际产物和失败原因，不输出秘密。
- 支持禁用和废弃，不要求本批物理删除/自动 GC。旧版被任务/恢复点引用时保留；清理另走备份与授权规则。

## 9. 按需发现与上下文成本

默认目录只返回权限范围内、与任务相关的名称/用途/输入概览；选择后才加载指定 revision 的完整用法。沿用工具帮助回访协议，同一版本不重复注入完整说明。

详细参考资料只在当前步骤需要时读。工具说明和原始配方原文留存，不做有损上下文压缩；不相关说明按 NODECTX 节点暂存/关闭，需要时显式回访。目录、缓存、使用回执按个体与项目隔离；共享只限明确批准的不可变工具包，不共享可变 Agent 记忆。

先按项目、权限、任务类型过滤，再匹配相关性，避免模型选中无权使用的工具。无匹配时返回缺口供上级处理，不自动安装/生成同名工具。

## 11. 测试与验收矩阵

| 维度 | 关键反例和证据 |
|---|---|
| 生命周期 | draft 不可执行；实现者不能自验；缺证据不启用；注册/启用不伪装调用成功 |
| 地址与版本 | 两个项目同名工具不串用；固定版本不跟随更新；文件被替换/哈希不符拒绝；旧接口兼容适配不绕过门禁 |
| 权限 | 外层 allow 内层 deny；action read→write；路径逃逸/链接；过期/撤销/参数变化；安装夹带；统一/细分开关与规则冲突矩阵 |
| 推广 | 候选含私有路径/源码/凭据引用/记忆条目被拒或要求明确去除；批准入库不自动在目标启用；读取批准包不获得来源目录权限 |
| 程序边界 | 尝试逃逸目录、直接联网、启动未授权子进程、访问他人状态、冒充只读、自我改写均被本地拒绝；没有沙箱则不启用 |
| 幂等与恢复 | 完成后重放不重复副作用；执行后回执丢失先对账；部分步骤失败不重跑已成功步骤；取消/停用竞态与磁盘满 |
| 配置 | 改用户偏好不改变权限；项目覆盖不影响其他项目；完整记录实际版本/revision，来源更新使旧缓存失效 |
| 跨项目 | 两个结构不同 fixture 实际复用；来源目录前后哈希不变，目标目录实际产物与预期一致；不得只检查回执写入 |
| 上下文 | 默认只加载相关目录；同 revision 用法按需回访；源说明及细节 hash 不变；不把推广包并入他人长期记忆 |
| 资源收益 | 相同 fixture 对比原流程/工具化流程，报告工具调用数、模型请求/token、延迟、失败/返修率及构建成本；无真实 usage 标为未测，不杜撰节省 |

先行为反例后实现。常规 CI 使用本地假 Provider、预置依赖与隔离 fixture；不默认联网或消耗费用。真实额度、安装、外部项目数据须另行授权。

发布验证使用同一冻结提交：定向测试 → `npm run check` → coverage 与安全专项 → `npm pack` → `verify-package.mjs` / `smoke-install.mjs`（按现有参数接口）→ 安装包公共入口的项目创建/启用/调用/推广/第二项目复用/升级拒绝闭环。记录退出码、commit/dirty、平台、tarball SHA256、运行 ID、证据文件和未满足项。

GUI/TUI 人工体验：用户能区分草案/已验证/已启用、项目专用/用户级/通用、授权/实际运行；能看懂升级权限差异并拒绝，能禁用和选择旧版。未人工走查保留 pending-manual，不能自动代签。

## 12. 完成条件及参考

全部必选检查点及对应门禁通过才可整卡 done；首版只支持配方时明确声明“不支持任意程序工具”。通用不等于全平台，推广不等于联网发布，调用成功不等于业务验收成功。

遵守可读变量名、布尔/时间单位规范、个体来源、备份、独立反馈和 Git 分流职责。修改前备份，提交只含自己的改动；阶段验收及本地提交后按仓库规则尝试 push，不夹带并行文件。

### TOOLKIT-01-02 进展（2026-10-10）：工作流配方有界偏序执行 + 独立验证

新增 `packages/core/src/toolkit/workflow-recipe-engine.ts`，落实卡内"工作流配方 =
已有工具可完成的稳定多步操作，实现为**有界偏序步骤与输入输出映射**，
通过**现有工具执行网关**调用"，并"完整保留来源与**逐步骤回执**"：

- `validateRecipeDefinition()`（纯函数，fail-closed）：拒绝空步骤、重复步骤 ID、
  **未知依赖**、**依赖环**（Kahn 检测）、**未在 `usedToolReferences` 声明的工具**
  （不得引入新工具）、引用未声明输入；
- `RecipeExecutionEngine`：**不新增执行通道**，所有步骤经注入的现有 `ToolPort` 执行；
  反复选取"依赖全部已完成"的步骤；依赖失败/被跳过的步骤一律
  `skipped-dependency-failed`（**不带着坏输入硬跑**）；顶层步骤失败 ⇒ `isSuccessful=false`
  （**不声称成功**）；每步产出回执（配方 ID/版本、步骤 ID、工具名、**实际参数**、状态、输出/失败原因）；
- `createRecipeLifecycle()`：检查点 02 点名的链路"草案 → **独立验证** → 登记/启用 →
  按需发现 → **实际调用**"，与 01 的 `ToolPackageRegistry` 组合复用其作用域/不可变/启用判定。

**"复用不是只 import"的可执行判定**（本检查点核心验收）：

1. 验证者与作者必须是**不同** `agentInstanceId`（沿用 T08D"作者不能自验"，实测自验被拒）；
2. 验证期必须**真实经工具网关执行过配方声明的全部工具**，否则判为未验证 ——
   仅 import 一个函数**不会产生任何工具执行记录**，因此该断言无法被"假装复用"通过；
3. 执行失败的验证不得登记为 `validated`。

### TOOLKIT-01-04 进展（2026-10-10）：版本、更新、回滚与故障

新增 `packages/core/src/toolkit/tool-package-version-controller.ts`（纯本地确定性判定；
不执行工具、不做 I/O、不联网、不读凭据），落实卡内 §8：

| 卡内 §8 要求 | 实现 |
| --- | --- |
| 项目锁定确切版本和哈希，**不自动随用户库升级** | 注册更高版本后已锁定项目解析结果不变 |
| 新版本展示**行为/依赖/权限差异**，标出**新增副作用** | `describeUpgradeDifferences()` 分别给出三类差异 + `addedSideEffects` |
| **新增副作用须重新授权** | `upgradeProjectVersion()` 在 `requiresReauthorization` 为真且未授权时拒绝 |
| 启用/停用/锁定按 **revision 原子提交** | 每次变更 revision 单调递增 |
| **停用阻止新运行**，但**不删在途调用** | `disableForProject()` 后解析返回 null；`listInFlightCalls()` 仍可见，须经 `convergeInFlightCall()` 按安全点收敛 |
| **回滚只切换后续版本，不撤销历史副作用** | `rollbackProjectVersion()` 只改锁定指向；`listCallHistory()` 记录保留 |
| 包损坏/依赖缺失 ⇒ **明确失败** | 实际哈希不符返回 null 并记 `getLastFailureReason()`；`checkPreconditions()` 报缺失依赖 |
| 调用记录含 run/步骤/版本/参数哈希/来源/产物 | `recordCompletedCall()` 返回完整记录 |
| 记录**不输出秘密** | 命中凭据/nonce 模式即**拒绝记录**（不做部分脱敏） |
| 支持**禁用与废弃**，被引用旧版**保留** | `deprecateVersion()` 标记；`removeVersion()` 对历史引用的版本拒绝移除 |
| **崩溃恢复** | `recoverFromInterruptedSwitch()` 收敛到上一个可信版本，**绝不留下"已启用但哈希不符"** |

**本片修掉两个真实缺陷**（均由反例暴露）：

1. **升级门禁存在旁路**：早期设计允许调用方通过 `enableForProject({isReauthorized:true})`
   完成版本切换 —— 那等于"新增副作用须重新授权"这道门禁可以被**顺手传个标志**绕过。
   已改为：版本切换**只能**走 `upgradeProjectVersion()`（总做差异判定），
   `enableForProject()` 遇到版本不同即拒绝并指路；反例 ③ 现在同时断言**无旁路**。
2. **凭据正则漏检真实密钥形态**：`sk-[A-Za-z0-9]{16,}` 因 `sk-live-…` 中
   `sk-` 与首个连字符之间只有 4 个字母而**整条漏掉**（反例 ⑧ 实测发现）。
   已在**两个**模块（版本控制器与推广模块）统一改成 `sk-[A-Za-z0-9-]{16,}`。
